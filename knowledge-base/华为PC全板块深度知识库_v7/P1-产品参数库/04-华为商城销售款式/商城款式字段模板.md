# 华为商城销售款式字段模板

> 用途：建立“商城当时展示的一个具体销售款式”记录  
> 适用对象：华为商城商品详情页、活动页及其具体 SKU/选项  
> 核心原则：商城款式是带渠道与日期的销售快照，不等于长期产品规格

## 一、为什么需要单独的商城款式模板

官网产品页常以系列介绍能力，商城则以可购买选项、套装、颜色和活动组织页面。同名产品可能存在不同处理器后缀、内存/存储、屏幕形态、键盘、颜色或套装；页面默认选中项也可能随访问入口变化。因此，商城记录必须回答“哪一天、哪个 URL、哪个商品或 SKU、当时选中了什么”，不能只抄一个系列名称。

本模板用于把页面上的产品身份、静态配置、销售选项和动态营销信息分开。长期产品事实仍需回到 P1 对应“产品事实.md”及官方规格页；当前发现范围可通过 [扩展产品索引.csv](../07-扩展产品目录/扩展产品索引.csv) 检索。模板不授权补写页面没有公开的参数，也不把用户评价、媒体文章或相似款信息并入事实字段。

## 二、可复制的记录模板

```markdown

- 商品 ID（如页面公开）：
- SKU/SBOM/商品编码（如页面公开）：
- 商品页 URL：

- 抓取日期与时间：
- 访问渠道/地区：
- 页面状态：可打开 / 下线 / 跳转 / 需登录 / 其他

## 当前选中项
- 处理器/平台：
- 操作系统及版本：
- 内存：
- 存储：
- 屏幕/柔光等款式标识：
- 颜色：
- 键盘/输入形态：
- 套装与标配：

## 页面可见的其他选项
- 选项文本：
- 是否确认可组合：是 / 否 / 待逐项选择核验
- 对应 SKU：
- 证据位置：

## 证据与边界
- 产品页/规格页 URL：
- 商城截图或存档位置：
- 与产品事实档案一致项：
- 与产品事实档案差异项：
```

空字段保留为空或写“页面未公开/待核验”，不要删除字段，也不要用其他 SKU 补齐。

## 三、字段如何解读

### 1. 产品身份字段

“商城展示名称”保留页面原文；“官方系列名称”用于和 P1 产品事实档案关联；“款式/后缀”保存 Pro、S、企业版、柔光版、处理器后缀等区别。商品 ID、SKU、SBOM 或商品编码若在 URL/页面公开，应原样记录，但不能把一个编码对应的事实套给其他选项。

URL 不是唯一身份。活动页可能只跳转到专区，商品页可能根据默认选项改变内容，链接参数也可能对应某个 SBOM。必须同时保存页面标题、当前选中项、抓取日期和必要截图。

### 2. 配置字段

处理器、系统、内存、存储、屏幕形态、颜色和键盘必须按“当前选中项”记录。页面把多个选项并列展示，不代表任意组合都存在；只有逐项选择后能绑定同一 SKU，才可写成一个完整销售配置。

“柔光版”“圆键盘”“方键盘”等文字可能是款式身份的一部分，也可能只出现在标题或选项中。未逐项核验时写“当前默认选中项可见”或“组合关系待核验”，不扩展成全系列事实。

### 3. 套装与标配

套装、赠品、加购和包装标配必须分开。包装清单以官方规格或商品详情为证据；活动赠品属于动态信息；第三方店铺组合不能写成官方标配。若页面仅显示图片而没有文字说明，只能记录画面内容，不能推断数量、材质或适配关系。

### 4. 动态销售字段

价格、划线价、券、分期、国补、赠品、库存提示、预计到货和活动倒计时均为快照字段。需要保存时另建带日期记录，并注明地区、登录状态和选中 SKU；本模板只提醒其存在，不把数值写入长期事实。

### 5. 证据状态

每个关键字段标记“商城当前项 / 官方规格 / 官方支持 / 待核验”。商城能证明销售页面当时如何展示；产品规格页用于长期规格；支持页用于兼容与操作；用户评价只能作为问题线索，不能单独成为事实。

## 四、取证流程

1. **固定时间点**：记录年月日、必要时记录时间、访问地区和是否登录。
2. **确认页面层级**：区分专区活动页、系列商品页和具体商品/SKU 页。
3. **保存身份**：复制展示名称、页面标题、URL 参数中的公开编码以及当前选中项。
4. **逐项选择**：一次只改变处理器、内存/存储、颜色、屏幕或套装中的一个选项；记录页面是否生成新编码或改变其他字段。
5. **建立组合矩阵**：每一行只写已实际出现的完整组合；不可选择的组合不靠排列组合生成。
6. **对照产品事实**：回到官方产品页、规格页和 P1 档案，区分商城款式事实与系列规格。
7. **保存脚注**：重量、续航、亮度、性能等数字的测试条件和限定词必须一起记录。
8. **记录动态项但隔离**：如项目需要价格或库存，另存带时间的快照，不回填长期参数表。
9. **形成待核验清单**：页面冲突、选项无法切换、编码不明或信息缺失时停止推断。
10. **复核**：第二人使用同一 URL 和选项路径重开页面，确认记录能复现。

## 五、动态信息边界

“页面可见”“商城展示”“专区列出”都必须带抓取日期。它们不能改写成“当前在售”“长期有货”“全国同价”或“固定赠送”。再次输出购买建议前，应重新打开页面并确认 SKU、地区、登录状态和活动规则。

页面下线不等于产品停产，页面仍在也不等于有库存。商城规格与官网规格页出现差异时，先核对是否为不同 SKU、页面更新时间或字段口径；无法解释则保留双方证据并标记“待审核”，不得选择对宣传更有利的一项。

## 六、补抓清单

- [ ] 当前默认选中项的完整 SKU/SBOM、配置与页面标题
- [ ] 所有可见选项逐一点击后的完整组合，而非选项笛卡尔积
- [ ] 颜色、屏幕形态、键盘形态与内存/存储的绑定关系
- [ ] 套装、包装清单、赠品和加购的明确区分
- [ ] 官方产品页、规格页、支持页与商城页的对应关系
- [ ] 关键数字的脚注、测试条件、款式限制和页面位置
- [ ] 页面截图/存档、抓取时间、访问地区和登录状态
- [ ] 差异项、失效链接、待人工核验项、审核人与复核日期

## 七、字段填写正反例

### 名称与款式

合格写法：“商城展示名称按页面原文记录；处理器后缀为页面标题的一部分；基础款另建记录。”不合格写法：“都是同一个系列，参数应该一样。”后者没有对象边界，会把后缀款和基础款混为一谈。

### 配置组合

合格写法：“在该日期逐项选择后，SKU A 显示某内存、某存储和某颜色；其他颜色待核验。”不合格写法：“页面列了三种颜色和四种容量，因此共有十二种配置。”商城并列选项不构成笛卡尔积。

### 页面数字

合格写法：“该数字来自具体规格页，限定词与测试条件见原页脚注。”不合格写法：“专区卡片写了这个卖点，所以所有款式都达到该数值。”缺少款式和条件时，数字只能留作检索线索。

### 动态销售状态

合格写法：“在某日期、某地区、某账号状态下页面显示该活动，当前需重查。”不合格写法：“长期最低价、一直有货、固定赠送。”动态字段不能沉淀为长期产品事实。

## 八、检索示例

### 示例 A：用户问“某系列有哪些内存和颜色”

先按官方系列名检索商城记录，再按 SKU 查看已核实组合。可以回答“在某日期、某页面、某些已验证 SKU 中看到了哪些选项”；不能把颜色列表与内存列表自由组合，也不能声称仍有库存。

### 示例 B：用户问“柔光版是否都用同一种键盘”

检索“屏幕/柔光等款式标识”和“键盘/输入形态”，只输出已绑定同一 SKU 的记录。若页面标题只描述默认项，应写“当前默认项可见，其他配置待逐项核验”。

### 示例 C：内容创作需要一句产品事实

先从 P1 产品事实档案引用稳定规格，再用商城记录说明某日期可见的销售款式。动态价格与活动不进入句子；若规格与商城冲突，内容暂停发布并转审核。

## 九、审核规则

- 每条记录必须有官方 URL、抓取日期和明确的当前选中项。
- 展示名称、后缀、SKU/SBOM 与配置必须指向同一对象。
- 并列选项不得自动排列组合；系列事实不得下沉到未经证实的 SKU。
- 数字、标配和兼容结论必须有对应官方来源及限定条件。
- 价格、库存、活动、补贴、赠品和交期必须与长期事实隔离。
- 页面冲突保留双方证据，状态设为“待审核”，不静默覆盖。
- 用户评论、问答区和第三方媒体只能提供线索，不能单独通过审核。
- 复核者应能从记录重现同一页面、同一选项和同一事实。

审核结果使用“通过 / 有条件通过 / 退回补抓 / 失效待重建”。通过只代表记录方法和证据满足要求，不代表页面内容永久有效。
