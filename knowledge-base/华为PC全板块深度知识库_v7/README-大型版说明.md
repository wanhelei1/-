# 全板块大型知识库说明

## “大”的口径

本版不用文件数量代替内容量。库内文件分为六类，每类承担不同任务：

1. **索引与导航**：用于定位文档，故意保持简洁，不应被当作完整回答。
2. **事实与来源卡**：记录产品、支持文章、竞品页和限定条件，强调可回溯，不自行扩写。
3. **方法、模板与工作表**：要求填写对象、取证、操作、异常处理和审核，不再只有一张空表。
4. **任务卡与话术**：把已确认事实放进用户角色、业务任务或平台格式，并说明限制和追问。
5. **深度正文**：包括完整软文、案例研究、官方支持深度卡、FAQ、排障、课程和行业完整案例。
6. **受控或虚构内容**：P4 只有受控字段与流程；P8 完整案例明确为教学用虚构情境。二者都不能被误读为真实内部政策或客户成果。

## 本版的实质扩充

### 软文与平台案例

P6 中的 80 份完整成稿按“10 型号×8 平台”对齐，不是同一篇文章换标题。公众号、小红书、知乎、短视频、新闻稿、门店长图、直播和销售朋友圈均有独立的受众、结构、图文节奏、交付格式和发布检查。

113 份华为官方传播案例研究用于理解官方如何组织标题、问题、证据、图片与行动引导。65 份多平台公开案例研究用于观察平台习惯与用户问题；其中已区分品牌/企业官方、平台规则、权威媒体、第三方/社区、公开待复核和跨平台适配参照，不伪装成全部都是原平台官方帖。

### 产品与竞品

P1 的重点型号不只保留产品页摘要，还有卖点与限制、图片索引和按维度拆分的深度检索卡。扩展目录为用户需求提供更广的候选范围，但扩展发现卡不假装成已穷尽所有 SKU 的完整规格书。

P3 对 59 个竞品官网产品条目做了深度补证，84 份工作表区分品牌网站的产品主键、系列规则、易混字段与取证路径，21 份案例则展示如何把“产品对产品”改成“具体任务下的条件化比较”。

### 支持、培训和场景

P7 的 79 份官方支持卡不只列链接，而是补入适用范围、问题现象、开始前确认、处理步骤、验证、失败分支、风险与升级。50 份高频问答和 18 份综合排障指南负责把单篇官方文章串成用户可执行的处理路径。

P5 的 40 个课程主题各有讲义、演练和测验；演练包含角色、回合、证据任务和判分，测验包含答案与解析。P8 的 30 类场景每类有五份互补内容，完整案例用于演练“访谈—证据—候选—试点—验收—交付”，不用于声称真实客户成绩。

## 内容长度如何理解

完整成稿、竞品事实卡、深度对比案例、官方支持卡、FAQ、综合排障和行业完整案例以实际任务为单位，长度显著高于索引。课程演练、测验、行业画像和问题清单保持单一训练任务所需的篇幅，它们通过同主题下的其他文件组成完整内容包。索引和来源登记不为追求长度重复正文。

全库的 Markdown 字符总量、中位数、P10、P90 和短文档数量均在 [全库统计与校验报告](全库统计与校验报告.md) 中公开，不用单一“文件数”代替实质内容量。

## 还需要人处理的内容

- 当日价格、补贴、优惠、赠品、库存、交付期和内部政策。
- 未在官方页确认的 SKU 参数、软件兼容性、升级性和外设组合。
- 需要客户授权的业务文件、环境、截图、效果数据和真实案例。
- 图片、人物、字体、音乐、视频和第三方版式的最终发布授权。
- 事故、数据丢失、账号安全、设备进液、异常发热和企业策略冲突等需要授权人员升级的情形。

## 完整性文件

- `全库统计与校验报告.md`：内容规模、板块分布、去重和链接等检查结果。
- `公开来源总表.csv`：去重 URL、来源主体、类型、出现文件和用途。
- `全库文件清单_SHA256.csv`：交付文件的相对路径、字节数和哈希。
- `重点型号构建明细.json`：重点型号目录的文档、图片和公开 URL 统计。
