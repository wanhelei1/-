# 小米笔记本 × 华为｜保修服务与维修取证工作表

> 本模板允许空填，但不允许猜填。只有来源、对象、日期、限定和任务同时完整，字段才可进入对外结论。

## 一、字段定义与完成标准

本维度核对当前地区、具体型号与购买条件下的标准保修、付费服务、维修入口、数据责任和升级方式。产品卖点页不能替代官方服务条款，口头咨询也必须留受理记录。

验收时随机抽取三格反查原页，并由第二人复述测试。凡缺 URL、配置、限定、异常或结论范围者，工作表退回补证。

1. **适用产品与地区**：取证动作是完整型号、购买地和使用地。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
2. **标准保修依据**：取证动作是期限、起算与凭证以当前条款为准。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
3. **覆盖部件**：取证动作是整机、电池、附件和易损件分开。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
4. **除外条件**：取证动作是意外、进液、改装等只按原条款记录。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
5. **服务方式**：取证动作是送修、寄修、上门或现场支持分别核验。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
6. **时效表述**：取证动作是响应、取件、维修完成不能混写。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
7. **数据与隐私**：取证动作是备份、解锁、清除和保密责任。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
8. **付费或项目服务**：取证动作是标准权益与另购服务包分开。填写时附对象和来源等级；没有原页证据时不作肯定或否定。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 小米笔记本 完整对象：先区分 Xiaomi 与 REDMI，再写 Book 或 Book Pro、尺寸、年份、平台变体，以及 product_id 或产品 slug。Xiaomi Book Pro 不能因名称相近并入 REDMI Book Pro。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；导航与 /prod/ 页面用于识别阵容和产品卖点，/shop/buy/detail 的 product_id 用于绑定销售记录。两个页面冲突时分别保留，不把选购页动态状态改写为长期产品事实。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

用一个模拟故障走完整服务发现：输入双方完整型号、地区和购买日期，查官方权益与服务入口，记录是否需要序列号、备份提醒、受理方式、预计节点和升级渠道。不得提交真实维修或泄露设备标识；结果只作为当日流程快照。

POC 归档至少含样机截图、版本、输入、步骤、异常、恢复与完成物。结论只覆盖本次锁定条件，不扩展到系列或其他用户。

## 八、结论句式

- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’

模板不允许总分、星级、赢家或保证性措辞；未知写未知，差异写差异，POC 结果写本任务结果。

## 十一、品牌 × 维度桌面演练

本轮采用反例法。研究者先围绕 小米笔记本 与华为的 保修服务与维修 写一个预期结论，再分别从 **适用产品与地区**、**标准保修依据**、**覆盖部件** 设计会使结论失效的配置、版本或环境变化。若反例成立，原句必须改成带条件的本轮观察；若没有证据排除反例，字段保持待补。观察员不评价文案是否有说服力，只看来源能否反查、任务能否复现、未知是否诚实。最终不得用价格、品牌或单项数值替代用户约束。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
