# 小米笔记本 × 华为｜处理器与显卡取证工作表

> 每次使用都新建副本并写日期。旧表可以追溯，不能在官网、配置或任务变化后继续称为当前事实。

## 一、字段定义与完成标准

本维度记录处理器、图形和 AI 计算平台的官方身份及工作条件，并用真实任务验证是否满足需求。芯片名称、理论算力、核心数或单次峰值不能直接转换成整机体验与品牌胜负。

验收时随机抽取三格反查原页，并由第二人复述测试。凡缺 URL、配置、限定、异常或结论范围者，工作表退回补证。

1. **处理器完整名称**：取证动作是保留厂商、系列、型号和当前 SKU。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
2. **处理器架构与官方说明**：取证动作是只抄官网或芯片厂商已明确内容。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
3. **图形方案**：取证动作是区分集成、独立与可选配置。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
4. **图形内存条件**：取证动作是记录专用或共享口径，不能自行等价。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
5. **NPU或AI字段**：取证动作是保留单位、精度与官网限定。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
6. **供电与性能模式**：取证动作是记录插电、模式和电源条件。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
7. **散热与持续负载条件**：取证动作是没有官方或实测证据则空白。填写时附对象和来源等级；没有原页证据时不作肯定或否定。
8. **软件加速支持**：取证动作是以目标软件版本、驱动和插件核验。填写时附对象和来源等级；没有原页证据时不作肯定或否定。

## 二、小米笔记本 官网定位方法

**身份主键**：先区分 Xiaomi 与 REDMI，再写 Book 或 Book Pro、尺寸、年份、平台变体，以及 product_id 或产品 slug。Xiaomi Book Pro 不能因名称相近并入 REDMI Book Pro。

**取证路线**：导航与 /prod/ 页面用于识别阵容和产品卖点，/shop/buy/detail 的 product_id 用于绑定销售记录。两个页面冲突时分别保留，不把选购页动态状态改写为长期产品事实。

**品牌端高风险点**：Pro、14/16、2025/2026 和锐龙版都是身份字段；跨端能力也必须保留支持设备、系统和账号条件。相似主图或相邻导航不是同一配置证据。

执行时先读 `P3-竞品资料库/05-官方来源登记/小米笔记本.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/小米与REDMI` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `03-性能与存储卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **不可直接对齐**：不同架构的核心、频率或 TOPS 不直接换算。该问题未解决前，表格不得出现优劣形容词。
2. **不可直接对齐**：同名处理器在不同机身条件下表现不等同。该问题未解决前，表格不得出现优劣形容词。
3. **不可直接对齐**：最高可选 GPU 不是当前 SKU。该问题未解决前，表格不得出现优劣形容词。
4. **不可直接对齐**：理论值与目标软件完成时间不是一回事。该问题未解决前，表格不得出现优劣形容词。
5. **不可直接对齐**：第三方跑分不进入官网事实栏。该问题未解决前，表格不得出现优劣形容词。
6. **不可直接对齐**：插电与离电、不同模式结果不能混用。该问题未解决前，表格不得出现优劣形容词。

对不齐的字段应退出结论区，进入待办区。空白、未提供、页面冲突与不支持分别记录，不可用一个‘无’字代替。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 小米笔记本 完整对象：先区分 Xiaomi 与 REDMI，再写 Book 或 Book Pro、尺寸、年份、平台变体，以及 product_id 或产品 slug。Xiaomi Book Pro 不能因名称相近并入 REDMI Book Pro。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；导航与 /prod/ 页面用于识别阵容和产品卖点，/shop/buy/detail 的 product_id 用于绑定销售记录。两个页面冲突时分别保留，不把选购页动态状态改写为长期产品事实。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

使用客户的编译、表格计算、图像、视频或三维样本，锁定软件、插件、驱动、素材和供电模式。双方依次完成打开、编辑、预览、导出或构建；记录是否完成、异常、人工介入和输出一致性。时间只说明本轮条件，不发布普遍跑分。

POC 归档至少含样机截图、版本、输入、步骤、异常、恢复与完成物。结论只覆盖本次锁定条件，不扩展到系列或其他用户。

## 八、结论句式

- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’

模板不允许总分、星级、赢家或保证性措辞；未知写未知，差异写差异，POC 结果写本任务结果。

## 九、更新与合规

1. 更新触发包括URL、型号、配置和页面状态变化。
2. 最高可选起始约等词必须原样保留。
3. 价格促销交付不沉淀为稳定事实。
4. 媒体与论坛只可产生问题线索。
5. 证据冲突时两说并存待复核。
6. 禁止星级、排行榜和唯一推荐。
7. 日志截图遵循最小必要原则。
8. 对外前重跑关键引用和任务。

## 十一、品牌 × 维度桌面演练

角色演练包含取证人、业务用户和审计人。业务用户提出 处理器与显卡 的模糊要求；取证人先用 **处理器完整名称** 把需求具体化，再从 小米笔记本 与华为入口分别记录 **处理器架构与官方说明**，最后把 **图形方案** 放进任务脚本。审计人隐藏一个关键限定或换掉 SKU，取证人必须发现并暂停旧结论。合格交付应能由第三人复跑，且明确哪些句子来自官网、哪些来自本轮观察、哪些仍是空白。若只能复述卖点，说明工作表尚未执行。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
