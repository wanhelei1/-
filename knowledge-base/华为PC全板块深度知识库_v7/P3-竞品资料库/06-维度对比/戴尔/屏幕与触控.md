# 戴尔 × 华为｜屏幕与触控取证工作表

> 使用者应把华为与竞品看成两个独立证据链；一侧资料更丰富，不能成为替另一侧补空的理由。

## 一、字段定义与完成标准

本维度把尺寸、比例、分辨率、刷新、亮度、色彩、表面处理、触控与笔输入分开。官网屏幕名称只能作身份线索；是否适合阅读、创作或批注需用同内容和同环境验证。

提交前应看见两条独立证据链：各自 SKU、原始页面、字段摘录和验证日志。只完成一边，产物仍是待办单而不是比较稿。

1. **尺寸与比例**：对戴尔及华为候选都要记录有效显示尺寸和纵横比。只完成一侧时，本行状态仍为未可比。
2. **面板与表面**：对戴尔及华为候选都要OLED、LCD、亮面、雾面或特殊处理分开。只完成一侧时，本行状态仍为未可比。
3. **分辨率与像素密度**：对戴尔及华为候选都要不把分辨率直接写成工作区大小。只完成一侧时，本行状态仍为未可比。
4. **刷新率**：对戴尔及华为候选都要标明固定、可选或动态条件。只完成一侧时，本行状态仍为未可比。
5. **亮度**：对戴尔及华为候选都要区分典型、峰值、HDR局部和测试条件。只完成一侧时，本行状态仍为未可比。
6. **色彩**：对戴尔及华为候选都要记录色域标准、色准口径与模式。只完成一侧时，本行状态仍为未可比。
7. **触控与笔**：对戴尔及华为候选都要确认是否为当前配置及配件条件。只完成一侧时，本行状态仍为未可比。
8. **缩放与应用显示**：对戴尔及华为候选都要用目标软件核对字体、界面与输出。只完成一侧时，本行状态仍为未可比。

## 二、戴尔 官网定位方法

**身份主键**：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。

**取证路线**：戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。

**品牌端高风险点**：同一页面上出现的处理器、显卡、屏幕、系统、服务包上限未必能同时购买。列表页只能说明阵容存在，不能支持端口、重量或具体配置。

执行时先读 `P3-竞品资料库/05-官方来源登记/戴尔.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/戴尔` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `02-屏幕与显示卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **证据边界**：峰值亮度与全屏持续亮度不能互换。先重取同级证据，再判断它是否影响用户任务。
2. **证据边界**：不同色域标准不直接比百分比。先重取同级证据，再判断它是否影响用户任务。
3. **证据边界**：高分辨率不自动等于更大工作区。先重取同级证据，再判断它是否影响用户任务。
4. **证据边界**：刷新率不等于所有应用体验。先重取同级证据，再判断它是否影响用户任务。
5. **证据边界**：触控可选不代表当前 SKU 配备。先重取同级证据，再判断它是否影响用户任务。
6. **证据边界**：护眼宣传不作医疗效果承诺。先重取同级证据，再判断它是否影响用户任务。

信息丰富程度不代表产品能力高低。只有两侧取得相同层级证据时才描述差异，否则标注负责人和复核日期。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 戴尔 完整对象：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

准备相同文档、表格、照片、时间轴和网页，在相近环境光与可解释的视觉亮度下完成阅读、缩放、拖拽、批注和外接显示。记录可见工作区、字体清晰、反光、触控误操作与输出一致性；主观观察由两人独立填写。

双方使用同一任务母版并记录无法对齐之处。证据包缺少配置或环境时，测试只能作为探索，不进入对外差异句。

## 八、结论句式

- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’

禁止以品牌声誉、价格高低或配置上限替用户作选择；只说明已确认事实、任务影响和仍需验证项。

## 九、更新与合规

1. 官网改名或跳转时先判断是否新对象。
2. 测试条件与数值一起引用。
3. 库存和交付承诺由获授权渠道确认。
4. 不把第三方结论升级为品牌事实。
5. 未提供、冲突、不适用和不支持分开。
6. 不输出跨任务的普遍胜负。
7. 个人与企业敏感信息均需遮挡。
8. 发布包附完整配置和证据日期。

## 十一、品牌 × 维度桌面演练

一名研究者仅拿到 戴尔 的系列级页面，另一名拿到华为具体型号卡，业务方要求当天输出“屏幕与触控谁更好”。第一轮先用 **尺寸与比例** 与 **面板与表面** 判断两侧证据等级；第二轮为 **分辨率与像素密度** 写补证责任人和原始页面；第三轮按本表 POC 建立相同任务，不允许用系列声誉补空；第四轮只交付事实句、缺口句和下一步。观察员逐项检查产品 ID 或代际、限定词、日期、失败日志和结论范围。若研究者把页面未提供写成不支持，或在对象未对齐时给赢家，本轮直接重做。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
