# 戴尔 × 华为｜跨设备协同取证工作表

> 这是一份执行型取证表：品牌规则决定去哪里找，维度规则决定找什么，POC 决定怎样验证，结论始终保留范围。

## 一、字段定义与完成标准

本维度把协同拆成具体源设备、目标设备、动作、账号、版本、网络、权限和数据落点。功能名称相似、同品牌或演示成功都不能证明所有设备和全部工作流可用。

提交前应看见两条独立证据链：各自 SKU、原始页面、字段摘录和验证日志。只完成一边，产物仍是待办单而不是比较稿。

1. **源设备与目标设备**：对戴尔及华为候选都要完整型号和系统版本分别记录。只完成一侧时，本行状态仍为未可比。
2. **协同动作**：对戴尔及华为候选都要传文件、投屏、共享输入或继续编辑分开。只完成一侧时，本行状态仍为未可比。
3. **账号条件**：对戴尔及华为候选都要账号体系、登录与组织限制。只完成一侧时，本行状态仍为未可比。
4. **连接条件**：对戴尔及华为候选都要网络、蓝牙、线缆、距离与发现机制。只完成一侧时，本行状态仍为未可比。
5. **支持范围**：对戴尔及华为候选都要机型、系统、应用和地区限制。只完成一侧时，本行状态仍为未可比。
6. **数据路径**：对戴尔及华为候选都要本地直连、局域网或云端不得混写。只完成一侧时，本行状态仍为未可比。
7. **权限与隐私**：对戴尔及华为候选都要剪贴板、相册、通知、摄像头等最小授权。只完成一侧时，本行状态仍为未可比。
8. **失败与回退**：对戴尔及华为候选都要断开、离线、格式和替代传输方式。只完成一侧时，本行状态仍为未可比。

## 二、戴尔 官网定位方法

**身份主键**：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。

**取证路线**：戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。

**品牌端高风险点**：同一页面上出现的处理器、显卡、屏幕、系统、服务包上限未必能同时购买。列表页只能说明阵容存在，不能支持端口、重量或具体配置。

执行时先读 `P3-竞品资料库/05-官方来源登记/戴尔.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/戴尔` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `05-系统协同与兼容卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **证据边界**：同品牌不代表自动支持全部功能。先重取同级证据，再判断它是否影响用户任务。
2. **证据边界**：功能同名不代表数据路径和权限相同。先重取同级证据，再判断它是否影响用户任务。
3. **证据边界**：一次成功不外推所有文件与网络。先重取同级证据，再判断它是否影响用户任务。
4. **证据边界**：云同步、直连传输和备份不是一回事。先重取同级证据，再判断它是否影响用户任务。
5. **证据边界**：宣传动画不能替代目标设备验证。先重取同级证据，再判断它是否影响用户任务。
6. **证据边界**：组织数据策略可能禁止个人云或跨端。先重取同级证据，再判断它是否影响用户任务。

信息丰富程度不代表产品能力高低。只有两侧取得相同层级证据时才描述差异，否则标注负责人和复核日期。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 戴尔 完整对象：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

锁定一组真实设备和版本，使用脱敏文档、图片与剪贴内容执行发现、连接、传输、编辑、保存、断开和再次连接。记录账号、网络、权限、文件落点、失败提示与离线回退；测试后关闭不必要授权。

双方使用同一任务母版并记录无法对齐之处。证据包缺少配置或环境时，测试只能作为探索，不进入对外差异句。

## 八、结论句式

- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’

禁止以品牌声誉、价格高低或配置上限替用户作选择；只说明已确认事实、任务影响和仍需验证项。

## 九、更新与合规

1. 官网改名或跳转时先判断是否新对象。
2. 测试条件与数值一起引用。
3. 库存和交付承诺由获授权渠道确认。
4. 不把第三方结论升级为品牌事实。
5. 未提供、冲突、不适用和不支持分开。
6. 不输出跨任务的普遍胜负。
7. 个人与企业敏感信息均需遮挡。
8. 发布包附完整配置和证据日期。

## 十一、品牌 × 维度桌面演练

本轮采用反例法。研究者先围绕 戴尔 与华为的 跨设备协同 写一个预期结论，再分别从 **源设备与目标设备**、**协同动作**、**账号条件** 设计会使结论失效的配置、版本或环境变化。若反例成立，原句必须改成带条件的本轮观察；若没有证据排除反例，字段保持待补。观察员不评价文案是否有说服力，只看来源能否反查、任务能否复现、未知是否诚实。最终不得用价格、品牌或单项数值替代用户约束。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
