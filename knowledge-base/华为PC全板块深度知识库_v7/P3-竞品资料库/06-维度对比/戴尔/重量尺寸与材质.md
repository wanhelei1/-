# 戴尔 × 华为｜重量尺寸与材质取证工作表

> 本模板允许空填，但不允许猜填。只有来源、对象、日期、限定和任务同时完整，字段才可进入对外结论。

## 一、字段定义与完成标准

本维度区分官网起始或约重、具体配置实重、三边尺寸、局部厚度、机身材质和整套携带负担。材质名称与轻薄定位不自动证明耐用、触感或适合所有人。

提交前应看见两条独立证据链：各自 SKU、原始页面、字段摘录和验证日志。只完成一边，产物仍是待办单而不是比较稿。

1. **整机重量**：对戴尔及华为候选都要记录起始、约重、配置和测量条件。只完成一侧时，本行状态仍为未可比。
2. **电源与附件重量**：对戴尔及华为候选都要形成包内总负担。只完成一侧时，本行状态仍为未可比。
3. **长宽厚**：对戴尔及华为候选都要方向、最薄或最大厚度分开。只完成一侧时，本行状态仍为未可比。
4. **屏幕与机身形态**：对戴尔及华为候选都要翻盖、翻转、双屏或折叠分别记录。只完成一侧时，本行状态仍为未可比。
5. **外壳材质**：对戴尔及华为候选都要A/C/D 面等部位不混写。只完成一侧时，本行状态仍为未可比。
6. **表面工艺与颜色**：对戴尔及华为候选都要不从渲染图推断手感或耐磨。只完成一侧时，本行状态仍为未可比。
7. **结构或耐用证据**：对戴尔及华为候选都要标准、测试范围与当前型号绑定。只完成一侧时，本行状态仍为未可比。
8. **携带与桌面适配**：对戴尔及华为候选都要包、托盘、支架和工位空间实测。只完成一侧时，本行状态仍为未可比。

## 二、戴尔 官网定位方法

**身份主键**：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。

**取证路线**：戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。

**品牌端高风险点**：同一页面上出现的处理器、显卡、屏幕、系统、服务包上限未必能同时购买。列表页只能说明阵容存在，不能支持端口、重量或具体配置。

执行时先读 `P3-竞品资料库/05-官方来源登记/戴尔.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/戴尔` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `04-便携续航接口卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **证据边界**：起始重量不是所有配置重量。先重取同级证据，再判断它是否影响用户任务。
2. **证据边界**：裸机与含电源重量不能混比。先重取同级证据，再判断它是否影响用户任务。
3. **证据边界**：最薄点不等于整机厚度。先重取同级证据，再判断它是否影响用户任务。
4. **证据边界**：材料名称不能推出抗摔或寿命。先重取同级证据，再判断它是否影响用户任务。
5. **证据边界**：军标或耐用宣传需看测试范围。先重取同级证据，再判断它是否影响用户任务。
6. **证据边界**：主观手感不升级为官方事实。先重取同级证据，再判断它是否影响用户任务。

信息丰富程度不代表产品能力高低。只有两侧取得相同层级证据时才描述差异，否则标注负责人和复核日期。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 戴尔 完整对象：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

核对样机配置后使用同一台秤与测量方法记录裸机、电源、常用转接器和包内总重；完成单手取放、通勤装包、窄桌会议、屏幕开合与端口插拔。两名用户分别记录可接受性，不用平均主观分数判赢家。

双方使用同一任务母版并记录无法对齐之处。证据包缺少配置或环境时，测试只能作为探索，不进入对外差异句。

## 八、结论句式

- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’

禁止以品牌声誉、价格高低或配置上限替用户作选择；只说明已确认事实、任务影响和仍需验证项。

## 九、更新与合规

1. 官网改名或跳转时先判断是否新对象。
2. 测试条件与数值一起引用。
3. 库存和交付承诺由获授权渠道确认。
4. 不把第三方结论升级为品牌事实。
5. 未提供、冲突、不适用和不支持分开。
6. 不输出跨任务的普遍胜负。
7. 个人与企业敏感信息均需遮挡。
8. 发布包附完整配置和证据日期。

## 十一、品牌 × 维度桌面演练

角色演练包含取证人、业务用户和审计人。业务用户提出 重量尺寸与材质 的模糊要求；取证人先用 **整机重量** 把需求具体化，再从 戴尔 与华为入口分别记录 **电源与附件重量**，最后把 **长宽厚** 放进任务脚本。审计人隐藏一个关键限定或换掉 SKU，取证人必须发现并暂停旧结论。合格交付应能由第三人复跑，且明确哪些句子来自官网、哪些来自本轮观察、哪些仍是空白。若只能复述卖点，说明工作表尚未执行。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
