# 戴尔 × 华为｜保修服务与维修取证工作表

> 每次使用都新建副本并写日期。旧表可以追溯，不能在官网、配置或任务变化后继续称为当前事实。

## 一、字段定义与完成标准

本维度核对当前地区、具体型号与购买条件下的标准保修、付费服务、维修入口、数据责任和升级方式。产品卖点页不能替代官方服务条款，口头咨询也必须留受理记录。

提交前应看见两条独立证据链：各自 SKU、原始页面、字段摘录和验证日志。只完成一边，产物仍是待办单而不是比较稿。

1. **适用产品与地区**：对戴尔及华为候选都要完整型号、购买地和使用地。只完成一侧时，本行状态仍为未可比。
2. **标准保修依据**：对戴尔及华为候选都要期限、起算与凭证以当前条款为准。只完成一侧时，本行状态仍为未可比。
3. **覆盖部件**：对戴尔及华为候选都要整机、电池、附件和易损件分开。只完成一侧时，本行状态仍为未可比。
4. **除外条件**：对戴尔及华为候选都要意外、进液、改装等只按原条款记录。只完成一侧时，本行状态仍为未可比。
5. **服务方式**：对戴尔及华为候选都要送修、寄修、上门或现场支持分别核验。只完成一侧时，本行状态仍为未可比。
6. **时效表述**：对戴尔及华为候选都要响应、取件、维修完成不能混写。只完成一侧时，本行状态仍为未可比。
7. **数据与隐私**：对戴尔及华为候选都要备份、解锁、清除和保密责任。只完成一侧时，本行状态仍为未可比。
8. **付费或项目服务**：对戴尔及华为候选都要标准权益与另购服务包分开。只完成一侧时，本行状态仍为未可比。

## 二、戴尔 官网定位方法

**身份主键**：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。

**取证路线**：戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。

**品牌端高风险点**：同一页面上出现的处理器、显卡、屏幕、系统、服务包上限未必能同时购买。列表页只能说明阵容存在，不能支持端口、重量或具体配置。

执行时先读 `P3-竞品资料库/05-官方来源登记/戴尔.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/戴尔` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P7-常见问题库/02-售后政策/官方售后入口.md`。该专题由常见问题库的官方售后入口提供；具体权益仍按型号、地区与服务时点复核，产品身份从 P1 固定。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **证据边界**：不同地区保修条款不能互换。先重取同级证据，再判断它是否影响用户任务。
2. **证据边界**：标准保修与付费服务包不能合并。先重取同级证据，再判断它是否影响用户任务。
3. **证据边界**：响应时间不等于修复时间。先重取同级证据，再判断它是否影响用户任务。
4. **证据边界**：系列宣传不能证明当前序列号权益。先重取同级证据，再判断它是否影响用户任务。
5. **证据边界**：备件价格和库存属于动态信息。先重取同级证据，再判断它是否影响用户任务。
6. **证据边界**：法规权利与厂商商业政策分别说明。先重取同级证据，再判断它是否影响用户任务。

信息丰富程度不代表产品能力高低。只有两侧取得相同层级证据时才描述差异，否则标注负责人和复核日期。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 戴尔 完整对象：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

用一个模拟故障走完整服务发现：输入双方完整型号、地区和购买日期，查官方权益与服务入口，记录是否需要序列号、备份提醒、受理方式、预计节点和升级渠道。不得提交真实维修或泄露设备标识；结果只作为当日流程快照。

双方使用同一任务母版并记录无法对齐之处。证据包缺少配置或环境时，测试只能作为探索，不进入对外差异句。

## 八、结论句式

- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’

禁止以品牌声誉、价格高低或配置上限替用户作选择；只说明已确认事实、任务影响和仍需验证项。

## 九、更新与合规

1. 官网改名或跳转时先判断是否新对象。
2. 测试条件与数值一起引用。
3. 库存和交付承诺由获授权渠道确认。
4. 不把第三方结论升级为品牌事实。
5. 未提供、冲突、不适用和不支持分开。
6. 不输出跨任务的普遍胜负。
7. 个人与企业敏感信息均需遮挡。
8. 发布包附完整配置和证据日期。

## 十一、品牌 × 维度桌面演练

一名研究者仅拿到 戴尔 的系列级页面，另一名拿到华为具体型号卡，业务方要求当天输出“保修服务与维修谁更好”。第一轮先用 **适用产品与地区** 与 **标准保修依据** 判断两侧证据等级；第二轮为 **覆盖部件** 写补证责任人和原始页面；第三轮按本表 POC 建立相同任务，不允许用系列声誉补空；第四轮只交付事实句、缺口句和下一步。观察员逐项检查产品 ID 或代际、限定词、日期、失败日志和结论范围。若研究者把页面未提供写成不支持，或在对象未对齐时给赢家，本轮直接重做。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
