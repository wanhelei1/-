# 戴尔 × 华为｜同期价格与促销取证工作表

> 先固定对象与任务，再填写字段。任何一侧仍停留在系列宣传时，本维度只能形成补证清单，不能形成赢家。

## 一、字段定义与完成标准

本维度只建立同一时间、地区、渠道和完整 SKU 的购买条件快照。价格不是稳定产品参数；券、补贴、折抵、分期、赠品、套装和库存必须拆开，过期快照仅用于追溯。

提交前应看见两条独立证据链：各自 SKU、原始页面、字段摘录和验证日志。只完成一边，产物仍是待办单而不是比较稿。

1. **完整 SKU**：对戴尔及华为候选都要系统、平台、内存、存储、颜色与套装写全。只完成一侧时，本行状态仍为未可比。
2. **官方标示价**：对戴尔及华为候选都要记录页面原词与时间，不作长期事实。只完成一侧时，本行状态仍为未可比。
3. **活动后条件**：对戴尔及华为候选都要券、会员、支付、地区与名额逐项。只完成一侧时，本行状态仍为未可比。
4. **补贴**：对戴尔及华为候选都要国家或地方、资格、核销和有效期。只完成一侧时，本行状态仍为未可比。
5. **折抵或以旧换新**：对戴尔及华为候选都要估值与成交价分开。只完成一侧时，本行状态仍为未可比。
6. **赠品与套装**：对戴尔及华为候选都要型号、数量、价值表述和退货影响。只完成一侧时，本行状态仍为未可比。
7. **库存与交付**：对戴尔及华为候选都要地区、仓库、下单时点和预计状态。只完成一侧时，本行状态仍为未可比。
8. **报价有效性**：对戴尔及华为候选都要截图、URL、配置和复核节点齐全。只完成一侧时，本行状态仍为未可比。

## 二、戴尔 官网定位方法

**身份主键**：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。

**取证路线**：戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。

**品牌端高风险点**：同一页面上出现的处理器、显卡、屏幕、系统、服务包上限未必能同时购买。列表页只能说明阵容存在，不能支持端口、重量或具体配置。

执行时先读 `P3-竞品资料库/05-官方来源登记/戴尔.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/戴尔` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P4-价格政策库（机密）/对外报价合规检查.md`。该专题由受控价格目录提供；仅限获授权人员按当前记录使用，产品身份仍从 P1 固定。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **证据边界**：原价、到手价与补贴后价不能混写。先重取同级证据，再判断它是否影响用户任务。
2. **证据边界**：不同渠道券和赠品不能跨用。先重取同级证据，再判断它是否影响用户任务。
3. **证据边界**：教育、企业与个人条件不同。先重取同级证据，再判断它是否影响用户任务。
4. **证据边界**：分期月供不等于总成本。先重取同级证据，再判断它是否影响用户任务。
5. **证据边界**：有货与可按期交付不是一回事。先重取同级证据，再判断它是否影响用户任务。
6. **证据边界**：历史最低、全网最低和保价不得无证据使用。先重取同级证据，再判断它是否影响用户任务。

信息丰富程度不代表产品能力高低。只有两侧取得相同层级证据时才描述差异，否则标注负责人和复核日期。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 戴尔 完整对象：主键写产品线、完整营销名、尺寸或层级、型号代码，以及存在时的 bto/xcto 配置路径。Dell Pro、Premium、Pro Max、XPS 与 Alienware 不按尺寸合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；戴尔目录页用于发现，/spd/ 专属页与配置器用于锁定型号代码和当次选项。保存完整 URL 与已选配置；默认项变化时建立新记录，不静默覆盖旧快照。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

执行双人报价复现：甲按既定地区、渠道和完整配置生成当日快照，乙仅凭记录重新定位同一对象并核对活动条件、库存和有效期。任何不可复现项转为待确认。工作表不预填金额，对外前由获授权人员在下单节点再次查询。

双方使用同一任务母版并记录无法对齐之处。证据包缺少配置或环境时，测试只能作为探索，不进入对外差异句。

## 八、结论句式

- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’

禁止以品牌声誉、价格高低或配置上限替用户作选择；只说明已确认事实、任务影响和仍需验证项。

## 九、更新与合规

1. 官网改名或跳转时先判断是否新对象。
2. 测试条件与数值一起引用。
3. 库存和交付承诺由获授权渠道确认。
4. 不把第三方结论升级为品牌事实。
5. 未提供、冲突、不适用和不支持分开。
6. 不输出跨任务的普遍胜负。
7. 个人与企业敏感信息均需遮挡。
8. 发布包附完整配置和证据日期。

## 十一、品牌 × 维度桌面演练

桌面题设：客户拿 戴尔 商品页与华为系列宣传页询问 同期价格与促销。执行者先把两边都降回可核验层级，分别确认 **完整 SKU**、**官方标示价**、**活动后条件**；再列出哪些信息只能支持发现产品，哪些能够支持具体 SKU。随后用一项用户任务建立验证脚本，明确样本、环境、通过和停止条件。交付物包括空白仍为空的证据表、三条允许表述和三条禁止外推。只要出现跨配置拼接、旧页面冒充当前状态或口头经验替代来源，就判为未通过。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
