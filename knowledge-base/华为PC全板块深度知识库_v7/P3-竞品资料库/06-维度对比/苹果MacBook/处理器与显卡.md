# 苹果MacBook × 华为｜处理器与显卡取证工作表

> 本页的目标是获得可审计差异，而非收集尽可能多的形容词。比较失败也应留下明确的缺口和下一动作。

## 一、字段定义与完成标准

本维度记录处理器、图形和 AI 计算平台的官方身份及工作条件，并用真实任务验证是否满足需求。芯片名称、理论算力、核心数或单次峰值不能直接转换成整机体验与品牌胜负。

表格验收包含身份、字段、条件、来源、日期、POC 和更新状态七项；任何一项无法追踪，都停止对外使用并保留问题单。

1. **处理器完整名称**：把‘保留厂商、系列、型号和当前 SKU’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
2. **处理器架构与官方说明**：把‘只抄官网或芯片厂商已明确内容’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
3. **图形方案**：把‘区分集成、独立与可选配置’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
4. **图形内存条件**：把‘记录专用或共享口径，不能自行等价’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
5. **NPU或AI字段**：把‘保留单位、精度与官网限定’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
6. **供电与性能模式**：把‘记录插电、模式和电源条件’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
7. **散热与持续负载条件**：把‘没有官方或实测证据则空白’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。
8. **软件加速支持**：把‘以目标软件版本、驱动和插件核验’转成两侧同口径字段；网页没有说明时写缺口，不凭产品定位推断。

## 二、苹果MacBook 官网定位方法

**身份主键**：主键使用 MacBook 系列、标称尺寸和芯片名称；Air 两个尺寸、Pro 的不同尺寸与 M5/M5 Pro/M5 Max、Neo A18 Pro 分别建档。共享 URL 不能作为合并理由。

**取证路线**：Mac 家族页发现阵容，Air、Pro、Neo 系列页定位产品，再用机型比较页交叉核对尺寸与芯片组合。具体配置仍回到相应官方页面和限定词。

**品牌端高风险点**：系列页面的最高统一内存、最高存储或最长续航不能自动下放到每个芯片和尺寸；统一内存也不能与其他平台内存自行换算性能等价。

执行时先读 `P3-竞品资料库/05-官方来源登记/苹果MacBook.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/苹果` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `03-性能与存储卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **发布限制**：不同架构的核心、频率或 TOPS 不直接换算。缺少同条件材料时，本项保持空白并给出补证动作。
2. **发布限制**：同名处理器在不同机身条件下表现不等同。缺少同条件材料时，本项保持空白并给出补证动作。
3. **发布限制**：最高可选 GPU 不是当前 SKU。缺少同条件材料时，本项保持空白并给出补证动作。
4. **发布限制**：理论值与目标软件完成时间不是一回事。缺少同条件材料时，本项保持空白并给出补证动作。
5. **发布限制**：第三方跑分不进入官网事实栏。缺少同条件材料时，本项保持空白并给出补证动作。
6. **发布限制**：插电与离电、不同模式结果不能混用。缺少同条件材料时，本项保持空白并给出补证动作。

官网沉默不构成否定事实，营销命名也不构成性能事实。两类内容都不能越过证据闸门进入胜负表达。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 苹果MacBook 完整对象：主键使用 MacBook 系列、标称尺寸和芯片名称；Air 两个尺寸、Pro 的不同尺寸与 M5/M5 Pro/M5 Max、Neo A18 Pro 分别建档。共享 URL 不能作为合并理由。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；Mac 家族页发现阵容，Air、Pro、Neo 系列页定位产品，再用机型比较页交叉核对尺寸与芯片组合。具体配置仍回到相应官方页面和限定词。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

使用客户的编译、表格计算、图像、视频或三维样本，锁定软件、插件、驱动、素材和供电模式。双方依次完成打开、编辑、预览、导出或构建；记录是否完成、异常、人工介入和输出一致性。时间只说明本轮条件，不发布普遍跑分。

POC 只提供场景证据。材料包括对象、版本、授权样本、外设网络、步骤日志、异常和复核；不得产生整机总分。

## 八、结论句式

- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’

本表的合规结果可以是不形成推荐。没有同口径证据时，暂停发布优于生成看似完整的胜负表。

## 九、更新与合规

1. 新页面不覆盖旧日期快照，二者并列归档。
2. 所有限定、单位和适用对象完整引用。
3. 金额、优惠和库存不在通用模板预填。
4. 不引用跑分、销量或市场份额判产品。
5. 页面沉默不能作为负面证据。
6. 采购结论不由单维度模板自动生成。
7. 截图与录屏按组织安全规则保存。
8. 最终稿审查身份、来源、范围和待办。

## 十一、品牌 × 维度桌面演练

一名研究者仅拿到 苹果MacBook 的系列级页面，另一名拿到华为具体型号卡，业务方要求当天输出“处理器与显卡谁更好”。第一轮先用 **处理器完整名称** 与 **处理器架构与官方说明** 判断两侧证据等级；第二轮为 **图形方案** 写补证责任人和原始页面；第三轮按本表 POC 建立相同任务，不允许用系列声誉补空；第四轮只交付事实句、缺口句和下一步。观察员逐项检查产品 ID 或代际、限定词、日期、失败日志和结论范围。若研究者把页面未提供写成不支持，或在对象未对齐时给赢家，本轮直接重做。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
