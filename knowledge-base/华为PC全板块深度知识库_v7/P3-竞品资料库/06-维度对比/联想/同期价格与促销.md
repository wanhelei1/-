# 联想 × 华为｜同期价格与促销取证工作表

> 每次使用都新建副本并写日期。旧表可以追溯，不能在官网、配置或任务变化后继续称为当前事实。

## 一、字段定义与完成标准

本维度只建立同一时间、地区、渠道和完整 SKU 的购买条件快照。价格不是稳定产品参数；券、补贴、折抵、分期、赠品、套装和库存必须拆开，过期快照仅用于追溯。

完成标准以可复核为准：陌生同事无需口头提示即可找到双方页面、识别空缺、执行脚本并得出同一范围的结论。

1. **完整 SKU**：审核者将检查是否做到系统、平台、内存、存储、颜色与套装写全。事实、条件、链接和时间缺一项，本行不得进入结论。
2. **官方标示价**：审核者将检查是否做到记录页面原词与时间，不作长期事实。事实、条件、链接和时间缺一项，本行不得进入结论。
3. **活动后条件**：审核者将检查是否做到券、会员、支付、地区与名额逐项。事实、条件、链接和时间缺一项，本行不得进入结论。
4. **补贴**：审核者将检查是否做到国家或地方、资格、核销和有效期。事实、条件、链接和时间缺一项，本行不得进入结论。
5. **折抵或以旧换新**：审核者将检查是否做到估值与成交价分开。事实、条件、链接和时间缺一项，本行不得进入结论。
6. **赠品与套装**：审核者将检查是否做到型号、数量、价值表述和退货影响。事实、条件、链接和时间缺一项，本行不得进入结论。
7. **库存与交付**：审核者将检查是否做到地区、仓库、下单时点和预计状态。事实、条件、链接和时间缺一项，本行不得进入结论。
8. **报价有效性**：审核者将检查是否做到截图、URL、配置和复核节点齐全。事实、条件、链接和时间缺一项，本行不得进入结论。

## 二、联想 官网定位方法

**身份主键**：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。

**取证路线**：消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。

**品牌端高风险点**：联想与 ThinkPad 虽共享部分商城体系，产品线事实仍分开；商品页配置与系列宣传也分开。页面增删 AI、新款等词时，先看产品 ID 与硬件是否变化。

执行时先读 `P3-竞品资料库/05-官方来源登记/联想.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/联想` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P4-价格政策库（机密）/对外报价合规检查.md`。该专题由受控价格目录提供；仅限获授权人员按当前记录使用，产品身份仍从 P1 固定。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **比较阻断**：原价、到手价与补贴后价不能混写。不要用平均、折算或经验把两种资料强行对齐。
2. **比较阻断**：不同渠道券和赠品不能跨用。不要用平均、折算或经验把两种资料强行对齐。
3. **比较阻断**：教育、企业与个人条件不同。不要用平均、折算或经验把两种资料强行对齐。
4. **比较阻断**：分期月供不等于总成本。不要用平均、折算或经验把两种资料强行对齐。
5. **比较阻断**：有货与可按期交付不是一回事。不要用平均、折算或经验把两种资料强行对齐。
6. **比较阻断**：历史最低、全网最低和保价不得无证据使用。不要用平均、折算或经验把两种资料强行对齐。

出现口径冲突时保留两份原文和时间戳，不自行择利采用；冲突解决之前，用户只能看到中性的待核验说明。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 联想 完整对象：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

执行双人报价复现：甲按既定地区、渠道和完整配置生成当日快照，乙仅凭记录重新定位同一对象并核对活动条件、库存和有效期。任何不可复现项转为待确认。工作表不预填金额，对外前由获授权人员在下单节点再次查询。

每轮都要能回答谁、用哪台、在何环境、做何步骤、得到什么、怎样恢复。无法回答时状态保持未执行。

## 八、结论句式

- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’

任何‘都、绝对、必然、最’都需要可核验范围；无法给范围就删去，不用营销语气掩盖证据空白。

## 九、更新与合规

1. 版本日志说明谁因何证据改了哪一行。
2. 系列范围不能下放为全系标配。
3. 动态字段在发布与下单两次复核。
4. 测试结果只属于所列样机和环境。
5. 空格保留到原始证据取得为止。
6. 推荐必须回到用户约束与取舍。
7. 素材、账号和网络均使用授权环境。
8. 复核者抽三条事实一分钟反查。

## 十一、品牌 × 维度桌面演练

演练从一张未完成表开始：联想 侧只有 P3/07 摘要，华为侧只有型号名称。学员需在二十分钟内为 **完整 SKU** 找到正确入口，为 **官方标示价** 标注证据等级，为 **活动后条件** 设计 POC；找不到的信息写清原因，不追求填满。复核员交换双方证据后盲查原页，并故意改变一个配置或版本，观察结论是否随之收窄。最终答案不得出现总分，只允许确认事实、不可比口径、任务结果和补证排期。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
