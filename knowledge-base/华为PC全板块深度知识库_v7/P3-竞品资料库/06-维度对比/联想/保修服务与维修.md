# 联想 × 华为｜保修服务与维修取证工作表

> 使用者应把华为与竞品看成两个独立证据链；一侧资料更丰富，不能成为替另一侧补空的理由。

## 一、字段定义与完成标准

本维度核对当前地区、具体型号与购买条件下的标准保修、付费服务、维修入口、数据责任和升级方式。产品卖点页不能替代官方服务条款，口头咨询也必须留受理记录。

完成标准以可复核为准：陌生同事无需口头提示即可找到双方页面、识别空缺、执行脚本并得出同一范围的结论。

1. **适用产品与地区**：审核者将检查是否做到完整型号、购买地和使用地。事实、条件、链接和时间缺一项，本行不得进入结论。
2. **标准保修依据**：审核者将检查是否做到期限、起算与凭证以当前条款为准。事实、条件、链接和时间缺一项，本行不得进入结论。
3. **覆盖部件**：审核者将检查是否做到整机、电池、附件和易损件分开。事实、条件、链接和时间缺一项，本行不得进入结论。
4. **除外条件**：审核者将检查是否做到意外、进液、改装等只按原条款记录。事实、条件、链接和时间缺一项，本行不得进入结论。
5. **服务方式**：审核者将检查是否做到送修、寄修、上门或现场支持分别核验。事实、条件、链接和时间缺一项，本行不得进入结论。
6. **时效表述**：审核者将检查是否做到响应、取件、维修完成不能混写。事实、条件、链接和时间缺一项，本行不得进入结论。
7. **数据与隐私**：审核者将检查是否做到备份、解锁、清除和保密责任。事实、条件、链接和时间缺一项，本行不得进入结论。
8. **付费或项目服务**：审核者将检查是否做到标准权益与另购服务包分开。事实、条件、链接和时间缺一项，本行不得进入结论。

## 二、联想 官网定位方法

**身份主键**：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。

**取证路线**：消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。

**品牌端高风险点**：联想与 ThinkPad 虽共享部分商城体系，产品线事实仍分开；商品页配置与系列宣传也分开。页面增删 AI、新款等词时，先看产品 ID 与硬件是否变化。

执行时先读 `P3-竞品资料库/05-官方来源登记/联想.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/联想` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P7-常见问题库/02-售后政策/官方售后入口.md`。该专题由常见问题库的官方售后入口提供；具体权益仍按型号、地区与服务时点复核，产品身份从 P1 固定。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **比较阻断**：不同地区保修条款不能互换。不要用平均、折算或经验把两种资料强行对齐。
2. **比较阻断**：标准保修与付费服务包不能合并。不要用平均、折算或经验把两种资料强行对齐。
3. **比较阻断**：响应时间不等于修复时间。不要用平均、折算或经验把两种资料强行对齐。
4. **比较阻断**：系列宣传不能证明当前序列号权益。不要用平均、折算或经验把两种资料强行对齐。
5. **比较阻断**：备件价格和库存属于动态信息。不要用平均、折算或经验把两种资料强行对齐。
6. **比较阻断**：法规权利与厂商商业政策分别说明。不要用平均、折算或经验把两种资料强行对齐。

出现口径冲突时保留两份原文和时间戳，不自行择利采用；冲突解决之前，用户只能看到中性的待核验说明。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 联想 完整对象：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

用一个模拟故障走完整服务发现：输入双方完整型号、地区和购买日期，查官方权益与服务入口，记录是否需要序列号、备份提醒、受理方式、预计节点和升级渠道。不得提交真实维修或泄露设备标识；结果只作为当日流程快照。

每轮都要能回答谁、用哪台、在何环境、做何步骤、得到什么、怎样恢复。无法回答时状态保持未执行。

## 八、结论句式

- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’

任何‘都、绝对、必然、最’都需要可核验范围；无法给范围就删去，不用营销语气掩盖证据空白。

## 九、更新与合规

1. 版本日志说明谁因何证据改了哪一行。
2. 系列范围不能下放为全系标配。
3. 动态字段在发布与下单两次复核。
4. 测试结果只属于所列样机和环境。
5. 空格保留到原始证据取得为止。
6. 推荐必须回到用户约束与取舍。
7. 素材、账号和网络均使用授权环境。
8. 复核者抽三条事实一分钟反查。

## 十一、品牌 × 维度桌面演练

桌面题设：客户拿 联想 商品页与华为系列宣传页询问 保修服务与维修。执行者先把两边都降回可核验层级，分别确认 **适用产品与地区**、**标准保修依据**、**覆盖部件**；再列出哪些信息只能支持发现产品，哪些能够支持具体 SKU。随后用一项用户任务建立验证脚本，明确样本、环境、通过和停止条件。交付物包括空白仍为空的证据表、三条允许表述和三条禁止外推。只要出现跨配置拼接、旧页面冒充当前状态或口头经验替代来源，就判为未通过。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
