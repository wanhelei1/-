# 联想 × 华为｜跨设备协同取证工作表

> 本表用于把官网线索转换成双侧证据与可复现任务，不是排名表。空白表示尚未取得证据，不表示没有该能力。

## 一、字段定义与完成标准

本维度把协同拆成具体源设备、目标设备、动作、账号、版本、网络、权限和数据落点。功能名称相似、同品牌或演示成功都不能证明所有设备和全部工作流可用。

完成标准以可复核为准：陌生同事无需口头提示即可找到双方页面、识别空缺、执行脚本并得出同一范围的结论。

1. **源设备与目标设备**：审核者将检查是否做到完整型号和系统版本分别记录。事实、条件、链接和时间缺一项，本行不得进入结论。
2. **协同动作**：审核者将检查是否做到传文件、投屏、共享输入或继续编辑分开。事实、条件、链接和时间缺一项，本行不得进入结论。
3. **账号条件**：审核者将检查是否做到账号体系、登录与组织限制。事实、条件、链接和时间缺一项，本行不得进入结论。
4. **连接条件**：审核者将检查是否做到网络、蓝牙、线缆、距离与发现机制。事实、条件、链接和时间缺一项，本行不得进入结论。
5. **支持范围**：审核者将检查是否做到机型、系统、应用和地区限制。事实、条件、链接和时间缺一项，本行不得进入结论。
6. **数据路径**：审核者将检查是否做到本地直连、局域网或云端不得混写。事实、条件、链接和时间缺一项，本行不得进入结论。
7. **权限与隐私**：审核者将检查是否做到剪贴板、相册、通知、摄像头等最小授权。事实、条件、链接和时间缺一项，本行不得进入结论。
8. **失败与回退**：审核者将检查是否做到断开、离线、格式和替代传输方式。事实、条件、链接和时间缺一项，本行不得进入结论。

**身份主键**：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。

执行时先读 `P3-竞品资料库/05-官方来源登记/联想.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/联想` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 四、不可直接比较的口径

1. **比较阻断**：同品牌不代表自动支持全部功能。不要用平均、折算或经验把两种资料强行对齐。
2. **比较阻断**：功能同名不代表数据路径和权限相同。不要用平均、折算或经验把两种资料强行对齐。
3. **比较阻断**：一次成功不外推所有文件与网络。不要用平均、折算或经验把两种资料强行对齐。
4. **比较阻断**：云同步、直连传输和备份不是一回事。不要用平均、折算或经验把两种资料强行对齐。
5. **比较阻断**：宣传动画不能替代目标设备验证。不要用平均、折算或经验把两种资料强行对齐。
6. **比较阻断**：组织数据策略可能禁止个人云或跨端。不要用平均、折算或经验把两种资料强行对齐。

出现口径冲突时保留两份原文和时间戳，不自行择利采用；冲突解决之前，用户只能看到中性的待核验说明。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 联想 完整对象：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

锁定一组真实设备和版本，使用脱敏文档、图片与剪贴内容执行发现、连接、传输、编辑、保存、断开和再次连接。记录账号、网络、权限、文件落点、失败提示与离线回退；测试后关闭不必要授权。

每轮都要能回答谁、用哪台、在何环境、做何步骤、得到什么、怎样恢复。无法回答时状态保持未执行。

## 八、结论句式

- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’

任何‘都、绝对、必然、最’都需要可核验范围；无法给范围就删去，不用营销语气掩盖证据空白。

## 九、更新与合规

1. 版本日志说明谁因何证据改了哪一行。
2. 系列范围不能下放为全系标配。
3. 动态字段在发布与下单两次复核。
4. 测试结果只属于所列样机和环境。
5. 空格保留到原始证据取得为止。
6. 推荐必须回到用户约束与取舍。
7. 素材、账号和网络均使用授权环境。
8. 复核者抽三条事实一分钟反查。
