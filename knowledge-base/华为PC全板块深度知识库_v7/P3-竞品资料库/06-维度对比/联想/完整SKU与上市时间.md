# 联想 × 华为｜完整SKU与上市时间取证工作表

> 先固定对象与任务，再填写字段。任何一侧仍停留在系列宣传时，本维度只能形成补证清单，不能形成赢家。

## 一、字段定义与完成标准

本维度先证明双方比较的是哪一个可识别销售对象，以及证据处于什么日期和销售状态。系列名称、上市宣传和当前可购是三类事实，必须分栏保存。只有完整主键与日期可回查，其他维度才允许开始。

完成标准以可复核为准：陌生同事无需口头提示即可找到双方页面、识别空缺、执行脚本并得出同一范围的结论。

1. **完整销售名称**：审核者将检查是否做到保留品牌、系列、尺寸、代际、后缀和平台词。事实、条件、链接和时间缺一项，本行不得进入结论。
2. **型号或商品代码**：审核者将检查是否做到记录官网代码、产品 ID 或配置路径。事实、条件、链接和时间缺一项，本行不得进入结论。
3. **系统路线**：审核者将检查是否做到按当前 SKU 明示系统记录；未提供则空白。事实、条件、链接和时间缺一项，本行不得进入结论。
4. **处理平台**：审核者将检查是否做到只写当前配置，不抄系列最高选项。事实、条件、链接和时间缺一项，本行不得进入结论。
5. **内存与存储组合**：审核者将检查是否做到形成购买对象的一部分，不以范围替代。事实、条件、链接和时间缺一项，本行不得进入结论。
6. **颜色与套装**：审核者将检查是否做到区分本体配置、附件与套装。事实、条件、链接和时间缺一项，本行不得进入结论。
7. **页面状态**：审核者将检查是否做到预告、在售、缺货、下架只按核验日记录。事实、条件、链接和时间缺一项，本行不得进入结论。
8. **首次发现与复核日期**：审核者将检查是否做到分别记录，不把页面更新当首次上市。事实、条件、链接和时间缺一项，本行不得进入结论。

## 二、联想 官网定位方法

**身份主键**：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。

**取证路线**：消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。

**品牌端高风险点**：联想与 ThinkPad 虽共享部分商城体系，产品线事实仍分开；商品页配置与系列宣传也分开。页面增删 AI、新款等词时，先看产品 ID 与硬件是否变化。

执行时先读 `P3-竞品资料库/05-官方来源登记/联想.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/联想` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 四、不可直接比较的口径

1. **比较阻断**：系列页与具体 SKU 不是同一证据等级。不要用平均、折算或经验把两种资料强行对齐。
2. **比较阻断**：发布时间、抓取日和购买日不能互换。不要用平均、折算或经验把两种资料强行对齐。
3. **比较阻断**：官网陈列不等于库存可下单。不要用平均、折算或经验把两种资料强行对齐。
4. **比较阻断**：共享 URL 不表示尺寸或芯片相同。不要用平均、折算或经验把两种资料强行对齐。
5. **比较阻断**：新款、AI 等营销词不能替代型号代码。不要用平均、折算或经验把两种资料强行对齐。
6. **比较阻断**：跨地区、跨渠道对象不能直接合并。不要用平均、折算或经验把两种资料强行对齐。

出现口径冲突时保留两份原文和时间戳，不自行择利采用；冲突解决之前，用户只能看到中性的待核验说明。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 联想 完整对象：产品线、完整商品名、年份、尺寸或平台变体、补充码和产品 ID 共同去重。ThinkBook 名称中的加号、04CD，小新 IPH11 与 YOGA Aura 等都不能清洗掉。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；消费站和笔记本目录发现 YOGA、小新、拯救者；ThinkBook 可从 ThinkPad/ThinkBook 商城发现，随后都回到 item 或 tk 的具体商品页并保存产品 ID。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

进行身份盲核：执行者甲从系统信息或商品配置生成主键，执行者乙仅凭主键回到双方官网定位页面。二者分别复述系统、平台、内存存储和页面状态；任一字段只能到系列层时标为系列证据。输出一份身份差异单，不做性能判断。

每轮都要能回答谁、用哪台、在何环境、做何步骤、得到什么、怎样恢复。无法回答时状态保持未执行。

## 八、结论句式

- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’

任何‘都、绝对、必然、最’都需要可核验范围；无法给范围就删去，不用营销语气掩盖证据空白。

## 九、更新与合规

1. 版本日志说明谁因何证据改了哪一行。
2. 系列范围不能下放为全系标配。
3. 动态字段在发布与下单两次复核。
4. 测试结果只属于所列样机和环境。
5. 空格保留到原始证据取得为止。
6. 推荐必须回到用户约束与取舍。
7. 素材、账号和网络均使用授权环境。
8. 复核者抽三条事实一分钟反查。

## 十一、品牌 × 维度桌面演练

本轮采用反例法。研究者先围绕 联想 与华为的 完整SKU与上市时间 写一个预期结论，再分别从 **完整销售名称**、**型号或商品代码**、**系统路线** 设计会使结论失效的配置、版本或环境变化。若反例成立，原句必须改成带条件的本轮观察；若没有证据排除反例，字段保持待补。观察员不评价文案是否有说服力，只看来源能否反查、任务能否复现、未知是否诚实。最终不得用价格、品牌或单项数值替代用户约束。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
