# 华硕 × 华为｜保修服务与维修取证工作表

> 本页的目标是获得可审计差异，而非收集尽可能多的形容词。比较失败也应留下明确的缺口和下一动作。

## 一、字段定义与完成标准

本维度核对当前地区、具体型号与购买条件下的标准保修、付费服务、维修入口、数据责任和升级方式。产品卖点页不能替代官方服务条款，口头咨询也必须留受理记录。

完成状态不是表格写满，而是每格都能回答对象、来源、日期和条件；未知项有负责人，任务验证可复跑，系列口号未被当作 SKU。

1. **适用产品与地区**：本项要求完整型号、购买地和使用地。华硕证据与华为证据独立登记，禁止用相邻型号替空。
2. **标准保修依据**：本项要求期限、起算与凭证以当前条款为准。华硕证据与华为证据独立登记，禁止用相邻型号替空。
3. **覆盖部件**：本项要求整机、电池、附件和易损件分开。华硕证据与华为证据独立登记，禁止用相邻型号替空。
4. **除外条件**：本项要求意外、进液、改装等只按原条款记录。华硕证据与华为证据独立登记，禁止用相邻型号替空。
5. **服务方式**：本项要求送修、寄修、上门或现场支持分别核验。华硕证据与华为证据独立登记，禁止用相邻型号替空。
6. **时效表述**：本项要求响应、取件、维修完成不能混写。华硕证据与华为证据独立登记，禁止用相邻型号替空。
7. **数据与隐私**：本项要求备份、解锁、清除和保密责任。华硕证据与华为证据独立登记，禁止用相邻型号替空。
8. **付费或项目服务**：本项要求标准权益与另购服务包分开。华硕证据与华为证据独立登记，禁止用相邻型号替空。

## 二、华硕 官网定位方法

**身份主键**：主键保留中文产品线、完整营销名、年份或平台和机型代码。灵耀、无畏、a豆、天选与 ProArt 形态不同；UX、S、M、FX、H 等代码不能省略。

**取证路线**：产品目录用于发现系列，具体产品页用于定位，techspec 规格页用于配置范围。中文营销名与 URL 中的 zenbook、vivobook、tuf 等词根用机型代码桥接，不凭 URL 猜型号。

**品牌端高风险点**：华硕规格页经常并列多个处理器、显卡或屏幕选项；把所有最高值拼成一台机器会制造不存在的 SKU。筛选目录只能支持陈列与摘要，不能替代专属规格页。

执行时先读 `P3-竞品资料库/05-官方来源登记/华硕.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/华硕` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P7-常见问题库/02-售后政策/官方售后入口.md`。该专题由常见问题库的官方售后入口提供；具体权益仍按型号、地区与服务时点复核，产品身份从 P1 固定。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **暂停项**：不同地区保修条款不能互换。若业务坚持比较，先补双方对象、来源和测试方法。
2. **暂停项**：标准保修与付费服务包不能合并。若业务坚持比较，先补双方对象、来源和测试方法。
3. **暂停项**：响应时间不等于修复时间。若业务坚持比较，先补双方对象、来源和测试方法。
4. **暂停项**：系列宣传不能证明当前序列号权益。若业务坚持比较，先补双方对象、来源和测试方法。
5. **暂停项**：备件价格和库存属于动态信息。若业务坚持比较，先补双方对象、来源和测试方法。
6. **暂停项**：法规权利与厂商商业政策分别说明。若业务坚持比较，先补双方对象、来源和测试方法。

品牌页面证据等级不同并不是产品差异。先把系列、SKU 与实测分层；仍无同级材料时，只发布缺口和下一动作。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 华硕 完整对象：主键保留中文产品线、完整营销名、年份或平台和机型代码。灵耀、无畏、a豆、天选与 ProArt 形态不同；UX、S、M、FX、H 等代码不能省略。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；产品目录用于发现系列，具体产品页用于定位，techspec 规格页用于配置范围。中文营销名与 URL 中的 zenbook、vivobook、tuf 等词根用机型代码桥接，不凭 URL 猜型号。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

用一个模拟故障走完整服务发现：输入双方完整型号、地区和购买日期，查官方权益与服务入口，记录是否需要序列号、备份提醒、受理方式、预计节点和升级渠道。不得提交真实维修或泄露设备标识；结果只作为当日流程快照。

任务执行者须交付可复跑材料：两侧配置、软件驱动、样本校验、网络外设、操作记录、失败日志和签字。未执行绝不能写成不支持。

## 八、结论句式

- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’

结论中删除冠军、碾压、无敌和唯一推荐。任何效率、兼容或续航判断都必须带对象、条件与本轮范围。

## 九、更新与合规

1. 给旧表加失效或历史状态，不静默覆盖。
2. 一方只有系列页时降低结论强度。
3. 销售条件按地区渠道和时点复核。
4. POC观察与官方规格分栏保存。
5. 页面未提及继续写待补。
6. 采购决定另走组织审批。
7. 测试素材先授权和脱敏。
8. 审稿人检查对象、日期与限制。

## 十一、品牌 × 维度桌面演练

质量挑战：给学员两个不同日期的 华硕 页面快照和一张华为事实卡，要求处理 保修服务与维修。先按 **适用产品与地区** 判断是否同一对象，再核对 **标准保修依据** 是否发生口径变化，并为 **覆盖部件** 建立更新记录。学员必须保留旧快照、说明新旧差异、选择可用于本次任务的证据，不得把新上限回填旧配置。随后写一句中性差异和一句暂停原因。审计通过条件是每句话均能回到对象、日期、限定与责任人。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
