# 华硕 × 华为｜操作系统与软件兼容取证工作表

> 每次使用都新建副本并写日期。旧表可以追溯，不能在官网、配置或任务变化后继续称为当前事实。

## 一、字段定义与完成标准

本维度先确认系统路线、处理器架构和用户不可中断的软件工作流，再讨论系统体验。可下载、可安装、可启动、核心功能可用、性能满足与厂商支持是不同层级。

完成状态不是表格写满，而是每格都能回答对象、来源、日期和条件；未知项有负责人，任务验证可复跑，系列口号未被当作 SKU。

1. **预装系统与版本**：本项要求绑定当前 SKU、地区和核验日。华硕证据与华为证据独立登记，禁止用相邻型号替空。
2. **处理器架构**：本项要求用于软件与驱动支持核验。华硕证据与华为证据独立登记，禁止用相邻型号替空。
3. **应用名称与版本**：本项要求禁止用软件类别替代准确版本。华硕证据与华为证据独立登记，禁止用相邻型号替空。
4. **插件、宏与字体**：本项要求逐项确认许可和依赖。华硕证据与华为证据独立登记，禁止用相邻型号替空。
5. **文件格式**：本项要求打开、编辑、保存、导出分别验证。华硕证据与华为证据独立登记，禁止用相邻型号替空。
6. **外设驱动**：本项要求打印、加密狗、采集或专业设备。华硕证据与华为证据独立登记，禁止用相邻型号替空。
7. **虚拟化或兼容层**：本项要求不等同原生支持，记录限制。华硕证据与华为证据独立登记，禁止用相邻型号替空。
8. **企业账号与网络**：本项要求VPN、证书、安全软件和管理策略。华硕证据与华为证据独立登记，禁止用相邻型号替空。

## 二、华硕 官网定位方法

**身份主键**：主键保留中文产品线、完整营销名、年份或平台和机型代码。灵耀、无畏、a豆、天选与 ProArt 形态不同；UX、S、M、FX、H 等代码不能省略。

**取证路线**：产品目录用于发现系列，具体产品页用于定位，techspec 规格页用于配置范围。中文营销名与 URL 中的 zenbook、vivobook、tuf 等词根用机型代码桥接，不凭 URL 猜型号。

**品牌端高风险点**：华硕规格页经常并列多个处理器、显卡或屏幕选项；把所有最高值拼成一台机器会制造不存在的 SKU。筛选目录只能支持陈列与摘要，不能替代专属规格页。

执行时先读 `P3-竞品资料库/05-官方来源登记/华硕.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/华硕` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `05-系统协同与兼容卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **暂停项**：网页可用不等于客户端可用。若业务坚持比较，先补双方对象、来源和测试方法。
2. **暂停项**：能安装不等于核心流程完整。若业务坚持比较，先补双方对象、来源和测试方法。
3. **暂停项**：兼容层不等于原生或厂商支持。若业务坚持比较，先补双方对象、来源和测试方法。
4. **暂停项**：同名应用跨系统功能可能不同。若业务坚持比较，先补双方对象、来源和测试方法。
5. **暂停项**：一次打开文件不代表保存导出无损。若业务坚持比较，先补双方对象、来源和测试方法。
6. **暂停项**：个人环境成功不代替企业验证。若业务坚持比较，先补双方对象、来源和测试方法。

品牌页面证据等级不同并不是产品差异。先把系列、SKU 与实测分层；仍无同级材料时，只发布缺口和下一动作。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 华硕 完整对象：主键保留中文产品线、完整营销名、年份或平台和机型代码。灵耀、无畏、a豆、天选与 ProArt 形态不同；UX、S、M、FX、H 等代码不能省略。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；产品目录用于发现系列，具体产品页用于定位，techspec 规格页用于配置范围。中文营销名与 URL 中的 zenbook、vivobook、tuf 等词根用机型代码桥接，不凭 URL 猜型号。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

由用户提供准确软件、插件、字体、许可和脱敏样本；双方完成取得、安装、登录、打开、编辑、保存、导出、打印或连接外设。记录错误和替代路径；只有业务负责人接受替代，才标条件通过。关键流程失败则停止参数比较。

任务执行者须交付可复跑材料：两侧配置、软件驱动、样本校验、网络外设、操作记录、失败日志和签字。未执行绝不能写成不支持。

## 八、结论句式

- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’

结论中删除冠军、碾压、无敌和唯一推荐。任何效率、兼容或续航判断都必须带对象、条件与本轮范围。

## 九、更新与合规

1. 给旧表加失效或历史状态，不静默覆盖。
2. 一方只有系列页时降低结论强度。
3. 销售条件按地区渠道和时点复核。
4. POC观察与官方规格分栏保存。
5. 页面未提及继续写待补。
6. 采购决定另走组织审批。
7. 测试素材先授权和脱敏。
8. 审稿人检查对象、日期与限制。

## 十一、品牌 × 维度桌面演练

桌面题设：客户拿 华硕 商品页与华为系列宣传页询问 操作系统与软件兼容。执行者先把两边都降回可核验层级，分别确认 **预装系统与版本**、**处理器架构**、**应用名称与版本**；再列出哪些信息只能支持发现产品，哪些能够支持具体 SKU。随后用一项用户任务建立验证脚本，明确样本、环境、通过和停止条件。交付物包括空白仍为空的证据表、三条允许表述和三条禁止外推。只要出现跨配置拼接、旧页面冒充当前状态或口头经验替代来源，就判为未通过。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
