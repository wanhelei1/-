# ThinkPad × 华为｜完整SKU与上市时间取证工作表

> 使用者应把华为与竞品看成两个独立证据链；一侧资料更丰富，不能成为替另一侧补空的理由。

## 一、字段定义与完成标准

本维度先证明双方比较的是哪一个可识别销售对象，以及证据处于什么日期和销售状态。系列名称、上市宣传和当前可购是三类事实，必须分栏保存。只有完整主键与日期可回查，其他维度才允许开始。

交付门槛是：对象与日期可回查，八个字段均有证据或空缺原因，限定词不丢，POC 留下输入、结果与失败。仅贴宣传文案不算完成。

1. **完整销售名称**：保留品牌、系列、尺寸、代际、后缀和平台词。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
2. **型号或商品代码**：记录官网代码、产品 ID 或配置路径。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
3. **系统路线**：按当前 SKU 明示系统记录；未提供则空白。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
4. **处理平台**：只写当前配置，不抄系列最高选项。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
5. **内存与存储组合**：形成购买对象的一部分，不以范围替代。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
6. **颜色与套装**：区分本体配置、附件与套装。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
7. **页面状态**：预告、在售、缺货、下架只按核验日记录。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。
8. **首次发现与复核日期**：分别记录，不把页面更新当首次上市。在华为与ThinkPad两侧分别写原值、限定、页内位置和日期；找不到就留‘待补证’。

## 二、ThinkPad 官网定位方法

**身份主键**：先写全 ThinkPad 系列、代际、标称年份、明示配置和联想产品 ID。X1 Carbon G13 与 X14 2026 是不同对象；ThinkBook 转入联想登记，不能因同属商城而混用。

**取证路线**：先在 ThinkPad/ThinkBook 官方商城或联想笔记本目录发现产品，再进入 item.lenovo.com.cn 的单品页。目录只证明被陈列，商品页才用于锁定对象；配置、价格与销售状态按当日页面复核。

**品牌端高风险点**：ThinkPad 最常见误差是把 Carbon、键盘、安全或商务定位等系列表达，下放为任一 SKU 的固定能力；另一个误差是删去 G 代际、年份、处理器、内存或产品 ID 后合并。

执行时先读 `P3-竞品资料库/05-官方来源登记/ThinkPad.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/ThinkPad` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `01-型号身份卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **口径闸门**：系列页与具体 SKU 不是同一证据等级。条件未统一时只记录差异，不换算、不排名。
2. **口径闸门**：发布时间、抓取日和购买日不能互换。条件未统一时只记录差异，不换算、不排名。
3. **口径闸门**：官网陈列不等于库存可下单。条件未统一时只记录差异，不换算、不排名。
4. **口径闸门**：共享 URL 不表示尺寸或芯片相同。条件未统一时只记录差异，不换算、不排名。
5. **口径闸门**：新款、AI 等营销词不能替代型号代码。条件未统一时只记录差异，不换算、不排名。
6. **口径闸门**：跨地区、跨渠道对象不能直接合并。条件未统一时只记录差异，不换算、不排名。

任一口径无法统一时，可写‘公开资料不可直接对齐’，但不能据此断言缺失能力或形成赢家；未提供也不等于明确不支持。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 ThinkPad 完整对象：先写全 ThinkPad 系列、代际、标称年份、明示配置和联想产品 ID。X1 Carbon G13 与 X14 2026 是不同对象；ThinkBook 转入联想登记，不能因同属商城而混用。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；先在 ThinkPad/ThinkBook 官方商城或联想笔记本目录发现产品，再进入 item.lenovo.com.cn 的单品页。目录只证明被陈列，商品页才用于锁定对象；配置、价格与销售状态按当日页面复核。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

进行身份盲核：执行者甲从系统信息或商品配置生成主键，执行者乙仅凭主键回到双方官网定位页面。二者分别复述系统、平台、内存存储和页面状态；任一字段只能到系列层时标为系列证据。输出一份身份差异单，不做性能判断。

证据包保存身份、版本、脱敏样本、环境、逐步脚本、起止状态、错误、恢复、截图或录屏、输出物和复核人。结果仅用通过、条件通过、不通过或未执行。

## 八、结论句式

- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’

不得使用全面领先、闭眼买、完胜、一定更快、全兼容、全天续航或全网最低；字段再完整也只解释指定任务。

## 九、更新与合规

1. 保留每次版本、执行人和页面日期，变化时另建记录。
2. 限定词与事实相邻，不在摘要中删去。
3. 动态价格库存只在授权节点重查。
4. 第三方跑分和体验不填官网栏。
5. 空白不改成无或不支持。
6. 不制作总分与赢家。
7. 截图清除账号订单和设备标识。
8. 发布前由第二人反查原页。

## 十一、品牌 × 维度桌面演练

一名研究者仅拿到 ThinkPad 的系列级页面，另一名拿到华为具体型号卡，业务方要求当天输出“完整SKU与上市时间谁更好”。第一轮先用 **完整销售名称** 与 **型号或商品代码** 判断两侧证据等级；第二轮为 **系统路线** 写补证责任人和原始页面；第三轮按本表 POC 建立相同任务，不允许用系列声誉补空；第四轮只交付事实句、缺口句和下一步。观察员逐项检查产品 ID 或代际、限定词、日期、失败日志和结论范围。若研究者把页面未提供写成不支持，或在对象未对齐时给赢家，本轮直接重做。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
