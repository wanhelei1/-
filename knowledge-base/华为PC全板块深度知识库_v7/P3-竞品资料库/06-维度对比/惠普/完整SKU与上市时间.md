# 惠普 × 华为｜完整SKU与上市时间取证工作表

> 本页的目标是获得可审计差异，而非收集尽可能多的形容词。比较失败也应留下明确的缺口和下一动作。

## 一、字段定义与完成标准

本维度先证明双方比较的是哪一个可识别销售对象，以及证据处于什么日期和销售状态。系列名称、上市宣传和当前可购是三类事实，必须分栏保存。只有完整主键与日期可回查，其他维度才允许开始。

本表可以有空白，但不能有猜测。双方身份、八项证据、引用时间、限制和任务记录齐全后，才允许形成带范围的差异句。

1. **完整销售名称**：围绕用户任务，保留品牌、系列、尺寸、代际、后缀和平台词。双方均保留最高、可选、约等词，空格交由补证负责人。
2. **型号或商品代码**：围绕用户任务，记录官网代码、产品 ID 或配置路径。双方均保留最高、可选、约等词，空格交由补证负责人。
3. **系统路线**：围绕用户任务，按当前 SKU 明示系统记录；未提供则空白。双方均保留最高、可选、约等词，空格交由补证负责人。
4. **处理平台**：围绕用户任务，只写当前配置，不抄系列最高选项。双方均保留最高、可选、约等词，空格交由补证负责人。
5. **内存与存储组合**：围绕用户任务，形成购买对象的一部分，不以范围替代。双方均保留最高、可选、约等词，空格交由补证负责人。
6. **颜色与套装**：围绕用户任务，区分本体配置、附件与套装。双方均保留最高、可选、约等词，空格交由补证负责人。
7. **页面状态**：围绕用户任务，预告、在售、缺货、下架只按核验日记录。双方均保留最高、可选、约等词，空格交由补证负责人。
8. **首次发现与复核日期**：围绕用户任务，分别记录，不把页面更新当首次上市。双方均保留最高、可选、约等词，空格交由补证负责人。

## 二、惠普 官网定位方法

**身份主键**：按家用、EliteBook、ProBook、ZBook 与游戏产品线建主键；X/Ultra/8/6、Flip、G 代际、i/a/q 平台后缀和尺寸均保留。组合页中的相邻变体不能合并。

**取证路线**：先选家用、商用、工作站或游戏入口，再判断来源是组合页还是专属页。组合页只支持对应行或系列范围；Studio、Fury 等可回到专属页时优先补专属证据。

**品牌端高风险点**：HP 页面常把 G2i、G2a、G2q 与 Flip 并列，重量、屏幕、续航和平台不得跨行拼接；‘即将面市’也必须保留，不能自动更新为已上市。

执行时先读 `P3-竞品资料库/05-官方来源登记/惠普.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/惠普` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P1-产品参数库/06-型号检索卡`。选定具体 MateBook 目录后读取 `01-型号身份卡.md`；同时回查该型号的产品事实与卖点限制。

华为侧同样遵守“系列、具体型号、销售 SKU、动态销售条件分层”。卖点与限制可帮助解释适用场景，但数值仍回到产品事实或型号检索卡。缺少对应字段时写“华为侧待补证”，不得用其他 MateBook 或商城另一配置替代。

## 四、不可直接比较的口径

1. **审计提醒**：系列页与具体 SKU 不是同一证据等级。允许写‘口径不同’，不允许把未知解释成落后。
2. **审计提醒**：发布时间、抓取日和购买日不能互换。允许写‘口径不同’，不允许把未知解释成落后。
3. **审计提醒**：官网陈列不等于库存可下单。允许写‘口径不同’，不允许把未知解释成落后。
4. **审计提醒**：共享 URL 不表示尺寸或芯片相同。允许写‘口径不同’，不允许把未知解释成落后。
5. **审计提醒**：新款、AI 等营销词不能替代型号代码。允许写‘口径不同’，不允许把未知解释成落后。
6. **审计提醒**：跨地区、跨渠道对象不能直接合并。允许写‘口径不同’，不允许把未知解释成落后。

如果同一单位或测试条件仍无法建立，停止横向数值句；可以解释为什么不能比，不能借此暗示某一方较弱。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 惠普 完整对象：按家用、EliteBook、ProBook、ZBook 与游戏产品线建主键；X/Ultra/8/6、Flip、G 代际、i/a/q 平台后缀和尺寸均保留。组合页中的相邻变体不能合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；先选家用、商用、工作站或游戏入口，再判断来源是组合页还是专属页。组合页只支持对应行或系列范围；Studio、Fury 等可回到专属页时优先补专属证据。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

进行身份盲核：执行者甲从系统信息或商品配置生成主键，执行者乙仅凭主键回到双方官网定位页面。二者分别复述系统、平台、内存存储和页面状态；任一字段只能到系列层时标为系列证据。输出一份身份差异单，不做性能判断。

测试不以口头‘正常’结束；需要原始提示、过程留痕、输出文件及第二人复核。绕行被接受时写条件通过，不能隐藏绕行。

## 八、结论句式

- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’
- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’

不要把参数差异改成价值高低，也不要把一次成功写成永久能力。对外句必须同时呈现日期和限制。

## 九、更新与合规

1. 每张表写创建、复核与下次检查日期。
2. 跨版本内容不得合并成一个SKU。
3. 活动数据到期即退出当前结论。
4. 主观感受需双人记录且仍属观察。
5. 缺失字段有责任人而非猜值。
6. 参数差异不直接换成价值判断。
7. 组织数据不得用于未经授权演示。
8. 二审逐项核对链接与结论句。

## 十一、品牌 × 维度桌面演练

角色演练包含取证人、业务用户和审计人。业务用户提出 完整SKU与上市时间 的模糊要求；取证人先用 **完整销售名称** 把需求具体化，再从 惠普 与华为入口分别记录 **型号或商品代码**，最后把 **系统路线** 放进任务脚本。审计人隐藏一个关键限定或换掉 SKU，取证人必须发现并暂停旧结论。合格交付应能由第三人复跑，且明确哪些句子来自官网、哪些来自本轮观察、哪些仍是空白。若只能复述卖点，说明工作表尚未执行。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
