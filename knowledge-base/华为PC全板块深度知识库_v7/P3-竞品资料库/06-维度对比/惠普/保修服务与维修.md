# 惠普 × 华为｜保修服务与维修取证工作表

> 先固定对象与任务，再填写字段。任何一侧仍停留在系列宣传时，本维度只能形成补证清单，不能形成赢家。

## 一、字段定义与完成标准

本维度核对当前地区、具体型号与购买条件下的标准保修、付费服务、维修入口、数据责任和升级方式。产品卖点页不能替代官方服务条款，口头咨询也必须留受理记录。

本表可以有空白，但不能有猜测。双方身份、八项证据、引用时间、限制和任务记录齐全后，才允许形成带范围的差异句。

1. **适用产品与地区**：围绕用户任务，完整型号、购买地和使用地。双方均保留最高、可选、约等词，空格交由补证负责人。
2. **标准保修依据**：围绕用户任务，期限、起算与凭证以当前条款为准。双方均保留最高、可选、约等词，空格交由补证负责人。
3. **覆盖部件**：围绕用户任务，整机、电池、附件和易损件分开。双方均保留最高、可选、约等词，空格交由补证负责人。
4. **除外条件**：围绕用户任务，意外、进液、改装等只按原条款记录。双方均保留最高、可选、约等词，空格交由补证负责人。
5. **服务方式**：围绕用户任务，送修、寄修、上门或现场支持分别核验。双方均保留最高、可选、约等词，空格交由补证负责人。
6. **时效表述**：围绕用户任务，响应、取件、维修完成不能混写。双方均保留最高、可选、约等词，空格交由补证负责人。
7. **数据与隐私**：围绕用户任务，备份、解锁、清除和保密责任。双方均保留最高、可选、约等词，空格交由补证负责人。
8. **付费或项目服务**：围绕用户任务，标准权益与另购服务包分开。双方均保留最高、可选、约等词，空格交由补证负责人。

## 二、惠普 官网定位方法

**身份主键**：按家用、EliteBook、ProBook、ZBook 与游戏产品线建主键；X/Ultra/8/6、Flip、G 代际、i/a/q 平台后缀和尺寸均保留。组合页中的相邻变体不能合并。

**取证路线**：先选家用、商用、工作站或游戏入口，再判断来源是组合页还是专属页。组合页只支持对应行或系列范围；Studio、Fury 等可回到专属页时优先补专属证据。

**品牌端高风险点**：HP 页面常把 G2i、G2a、G2q 与 Flip 并列，重量、屏幕、续航和平台不得跨行拼接；‘即将面市’也必须保留，不能自动更新为已上市。

执行时先读 `P3-竞品资料库/05-官方来源登记/惠普.md`，再进入 `P3-竞品资料库/07-品牌官网当前产品事实/惠普` 选择与用户任务相符的具体产品卡。事实卡只保留其核验日已确认摘要；需要当前配置时必须回到卡内官方 URL。P3/08 案例只示范如何组织证据和 POC，不可把案例中的另一产品事实移入本表。

## 三、华为侧对应证据

先从 `P1-产品参数库/00-全库横向索引/全型号总览.md` 选择具体产品，再固定鸿蒙或 Windows 路线与销售配置。维度入口为 `P7-常见问题库/02-售后政策/官方售后入口.md`。该专题由常见问题库的官方售后入口提供；具体权益仍按型号、地区与服务时点复核，产品身份从 P1 固定。

## 四、不可直接比较的口径

1. **审计提醒**：不同地区保修条款不能互换。允许写‘口径不同’，不允许把未知解释成落后。
2. **审计提醒**：标准保修与付费服务包不能合并。允许写‘口径不同’，不允许把未知解释成落后。
3. **审计提醒**：响应时间不等于修复时间。允许写‘口径不同’，不允许把未知解释成落后。
4. **审计提醒**：系列宣传不能证明当前序列号权益。允许写‘口径不同’，不允许把未知解释成落后。
5. **审计提醒**：备件价格和库存属于动态信息。允许写‘口径不同’，不允许把未知解释成落后。
6. **审计提醒**：法规权利与厂商商业政策分别说明。允许写‘口径不同’，不允许把未知解释成落后。

如果同一单位或测试条件仍无法建立，停止横向数值句；可以解释为什么不能比，不能借此暗示某一方较弱。

## 五、取证步骤

1. 建立用户任务、成功标准和不可接受结果，禁止先选品牌再反推场景。
2. 按品牌登记锁定 惠普 完整对象：按家用、EliteBook、ProBook、ZBook 与游戏产品线建主键；X/Ultra/8/6、Flip、G 代际、i/a/q 平台后缀和尺寸均保留。组合页中的相邻变体不能合并。
3. 从 P3/07 事实卡进入官网，依据本维度八个字段逐项摘录；先选家用、商用、工作站或游戏入口，再判断来源是组合页还是专属页。组合页只支持对应行或系列范围；Studio、Fury 等可回到专属页时优先补专属证据。
4. 在 P1 固定华为具体型号、系统路线和 SKU；同一字段找不到时保留空白。
5. 做口径审查：单位、配置、最高/可选/起始/约、测试环境、地区和日期逐项对齐。
6. 执行 POC，只记录本轮输入、步骤、结果、异常和恢复；不把第三方跑分或个人体验放入事实栏。
7. 两人交叉复核 URL、本地路径和结论范围；动态信息在发布或下单节点再次查询。

## 七、POC 任务

用一个模拟故障走完整服务发现：输入双方完整型号、地区和购买日期，查官方权益与服务入口，记录是否需要序列号、备份提醒、受理方式、预计节点和升级渠道。不得提交真实维修或泄露设备标识；结果只作为当日流程快照。

测试不以口头‘正常’结束；需要原始提示、过程留痕、输出文件及第二人复核。绕行被接受时写条件通过，不能隐藏绕行。

## 八、结论句式

- 差异句：‘双方在【字段】上的公开口径为【A】与【B】；该差异是否影响【任务】仍需按【脚本】验证。’
- POC句：‘在【样机/版本/环境】下，【任务】结果为通过、条件通过或不通过；结论仅覆盖本轮。’
- 缺口句：‘【字段】一侧仅有系列级资料或未提供，因此暂不比较，补证责任人为【角色】。’
- 更新句：‘原结论基于【日期】快照；页面或配置变化后已暂停复用，等待重新核验。’
- 事实句：‘在【日期】核验的【完整 SKU】官方资料中，双方分别确认到【字段】，适用范围为【条件】。’

不要把参数差异改成价值高低，也不要把一次成功写成永久能力。对外句必须同时呈现日期和限制。

## 九、更新与合规

1. 每张表写创建、复核与下次检查日期。
2. 跨版本内容不得合并成一个SKU。
3. 活动数据到期即退出当前结论。
4. 主观感受需双人记录且仍属观察。
5. 缺失字段有责任人而非猜值。
6. 参数差异不直接换成价值判断。
7. 组织数据不得用于未经授权演示。
8. 二审逐项核对链接与结论句。

## 十一、品牌 × 维度桌面演练

交接演练要求甲只负责 惠普，乙只负责华为，双方不得互抄。甲为 **适用产品与地区** 提供对象级或系列级证据，乙为 **标准保修依据** 做同样记录；两人在 **覆盖部件** 上若口径不同，必须共同写不可比原因和补证方法。第三人拿到材料后复跑 POC，并检查动态信息是否重新查询。合格输出包括双方证据链、差异表、失败分支、更新状态和限制句；任一侧资料更少时，不以另一侧的丰富内容替其推断。

演练记录附在工作表副本中，不回填为品牌事实；只有重新取得官网证据或完成锁定条件下的 POC，字段状态才可改变。
