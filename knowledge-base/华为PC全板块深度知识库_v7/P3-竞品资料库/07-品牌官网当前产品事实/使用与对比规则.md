# 竞品官网事实卡使用与对比规则

## 适用范围

本目录用于竞品识别、同期产品定位分析和对比问题拆解，不直接构成优劣结论。事实卡记录的是抓取日品牌中国官网公开的产品名称、定位和卖点摘要，不代表所有 SKU 都具备相同配置。

## 参数与动态信息

- 同一系列的处理器、屏幕、内存、存储、续航和接口可能随具体 SKU 变化。
- 回答精确参数问题时，必须回到事实卡中的官方页面核验具体配置，并保留“最高”“最长”“可选”“起始”等限定词。
- 价格、促销、库存、交付期和在售状态属于动态信息，不在本地知识库中固化；使用时按当前官网重新核验。
- 双方官方资料均无法确认的字段标为“待核验”，不得补写推测参数。

## 对比步骤

1. 先确认预算、系统偏好、主要软件、移动频率、屏幕需求和售后要求。
2. 选择同尺寸、同定位、同期在售的华为与竞品机型，避免跨代或跨级别直接下结论。
3. 逐项列出双方官方可核验字段，并分别附原始页面；动态字段标注核验日期。
4. 将用户场景与参数影响分开说明，不把单项参数自动写成整机优劣结论。
5. 输出前复核型号、SKU、地区版本和限定词。

## 事实卡能回答什么

事实卡可用于确认某个品牌官网在记录日展示了哪些产品、官方如何表述其定位和卖点、还需补哪些字段才能进行同口径比较。它不能单独回答某个当日销售 SKU 的全部参数、库存、实付价、区域服务或应用兼容性。

当用户问“这两台哪台好”时，不直接把事实卡的营销摘要并排。先追问用户的必须任务、软件版本、外设、携带频率、屏幕偏好、现有设备生态和可接受的折中，再进入字段取证。

## 产品身份解析

同一系列名下可能存在尺寸、年份、代际、处理器平台、屏幕版本、内存、存储、系统和销售地区差异。使用前按下列顺序识别：

1. 记录页面展示的完整产品名称和官方 URL，不用搜索引擎标题代替。
2. 查找型号代码、产品 ID、规格页或官方商城配置标识，作为防止同名错配的主键。
3. 保留“可选”“至高”“某配置支持”等限定词，不把系列上限写成每台机器的标配。
4. 将地区、语言和页面日期与产品身份一起记录，不跨地区拼接配置。

## 字段取证规则

### 系统与软件

先确认出厂系统与具体 SKU，再验证用户所需软件的官方支持范围。“可通过浏览器使用”、“可通过远程桌面使用”和“本地原生客户端完整支持”是不同结论，必须分开记录。

### 屏幕与显示

尺寸、分辨率、比例、亮度、色域、刷新率、触控、表面处理和护眼特性要逐项对齐。若官方给出的数值附带测试条件，条件与数值必须同时保留。外观图或产品名不能证明具体屏幕配置。

### 性能、内存与存储

处理器名称、功耗模式、图形配置、内存容量和存储容量都要对应同一 SKU。不把实验室跑分直接改写成所有业务的效率结论；要用用户自己的文件、软件和操作流程进行可重复验证。

### 接口、无线与外设

接口数量、形态、协议、视频输出、充电与数据能力不得相互代替。对扩展坞、显示器、高速存储或特殊外设，应记录完整型号、线材、分辨率、刷新率和供电条件，再做实机测试。

### 重量、续航与服务

官方重量和续航数据可能因配置、测量方法、亮度、网络和负载不同而变化。对移动用户，还要把适配器、转接器和保护装备纳入携带任务。保修、上门、送修和退换货条件必须核对地区、渠道、购买日期和具体产品。

## 从事实到结论的写法

先列事实，再解释它对特定任务可能产生的影响，最后给出现场验证。例如，不写“某接口更专业”，而写“官方规格显示该 SKU 具有____接口；对需连接____的用户，还需用具体线材验证____。竞品对应字段尚未核实，因此暂不作优劣判断”。

如果用户已给出硬性要求，可输出“满足/不满足/待验证”，但必须指向某项具体任务和证据，不扩大为品牌或整机的绝对排名。

## 冲突、缺失与更新

- 同一官网的产品页与规格页不一致：保留两个 URL、页面标题、核验日期和冲突字段，标记“需官方确认”。
- 商城页与品牌概述页不一致：先确认是否为同地区、同一 SKU 和同一时期；不同对象不做强行合并。
- 仅有媒体评测或用户反馈：用它发现需验证的问题，不将其中参数直接写入官网事实卡。
- 原页失效：保留原 URL 和原核验日期，寻找品牌官网新入口；无法复核的字段降级为待核验。
- 产品更新换代：新建或更新对应日期的事实记录，不静默覆盖历史对象。

## 审核清单

- [ ] 产品名称、型号/SKU、地区、页面和日期可追溯。
- [ ] 系列级宣称没有被改写为所有 SKU 的标配。
- [ ] 参数与其限定词、测试条件和适用版本一起保留。
- [ ] 价格、促销、库存、交付和政策等动态信息已标注核验日期。
- [ ] 华为与竞品使用同一字段定义和证据标准。
- [ ] 缺失信息明确标为“待核验”，未使用常识或相似机型补写。
- [ ] 结论回到具体用户任务，且给出了可执行的验证步骤。
