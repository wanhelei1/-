# 零售话术框架

## 用途

帮助门店或在线顾问从任务出发推荐候选，不把参数堆砌成单向推销。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

一位顾客预算尚未完全确定，平时写文档、开会议，偶尔剪短视频，每天通勤并使用华为手机。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 最不能妥协的任务是什么？

**为什么要问：** 先找软件或外设门槛。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 常用软件的准确名称和版本是什么？

**为什么要问：** 决定系统路线与实机测试。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 每天携带多久、是否能充电？

**为什么要问：** 影响重量、电源和续航验证。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 屏幕更看重文字、反光还是色彩？

**为什么要问：** 避免只按分辨率推荐。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 已有手机、平板和显示器型号是什么？

**为什么要问：** 核验协同与接口。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 预算包含主机还是还包括配件服务？

**为什么要问：** 避免在错误总成本上比较。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 复述任务并让顾客确认。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 先排除不满足必用软件或接口的方案。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 只给两个差异明确的候选并说明取舍。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 用顾客自己的文件、外设或账号做低风险体验。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 结尾列明已确认、待确认和当日动态信息。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 一位顾客预算尚未完全确定，平时写文档、开会议，偶尔剪短视频，每天通勤并使用华为手机。

**示范处理：** 顾问先说：‘你每天通勤，文档和会议是刚需，剪辑属于偶发任务；先确认剪辑软件和素材规格，再在轻量与持续负载之间取舍。’随后展示两个具体SKU：一个偏移动，一个偏接口或性能；每项只引用P1事实，并提醒价格和赠品以当日页面为准。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 开口先问预算后直接推最贵配置
- 把屏幕、处理器和协同卖点连续背诵，却没有对应用户任务
- 说‘这个软件肯定能用’而未问版本和插件
- 用‘最后一台’‘马上涨价’制造未经核验的稀缺

## 证据路径

- P2/07对应型号角色卡

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
