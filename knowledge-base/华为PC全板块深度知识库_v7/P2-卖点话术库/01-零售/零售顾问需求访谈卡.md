# 零售顾问需求访谈

## 用途

把五分钟问答变成能影响选型的记录，而不是泛泛聊天。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

顾客只说‘想买一台轻薄、性能好、能多用几年’，同伴不断询问优惠。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 一周中耗时最长的三项任务是什么？

**为什么要问：** 用频率和时长替代笼统标签。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 有哪些必须安装的软件、插件和外设？

**为什么要问：** 建立硬门槛。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 旧机目前最影响工作的现象是什么？

**为什么要问：** 区分性能、容量、网络和软件问题。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 是否需要每天携带，包含哪些配件？

**为什么要问：** 计算完整携带负担。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 资料是否需要从旧机迁移？

**为什么要问：** 提前识别备份与授权。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 哪个风险会让你放弃购买？

**为什么要问：** 找到最终决策阈值。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 先问任务，再问现状和不能接受的问题。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 把回答填入必须、偏好、可放弃三栏。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 为每个必须项匹配证据或测试动作。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 未知项不塞进推荐结论。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 用一句话复述需求后才进入产品演示。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 顾客只说‘想买一台轻薄、性能好、能多用几年’，同伴不断询问优惠。

**示范处理：** 完整示范：顾客说明工作以表格和会议为主、每月剪两次1080p视频、每天背电脑通勤、必须连接现有投影仪。顾问因此先核对会议与剪辑软件版本、投影接口和通勤总重量；存储容量与屏幕偏好放在第二层；价格在具体SKU确认后实时查询。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 把‘轻薄’理解成只看裸机重量
- 顾客说‘设计’就默认需要某类显卡
- 没有记录软件版本和外设型号
- 访谈结束仍无法说出一条必须满足与一条可取舍需求

## 证据路径

- P1型号矩阵与产品事实
- P5需求诊断课程
- P7迁移、显示与外设支持
- 顾客提供的非敏感样例文件和设备型号

## 输出记录模板

- 用户/客户任务：
- 完整产品与SKU：
- 系统、软件、插件和外设：
- 必须满足 / 希望改善 / 可以放弃：
- 已确认事实、来源与日期：
- 待核验项、影响与责任人：
- 候选方案及各自取舍：
- 演示或试点步骤与通过标准：
- 动态价格/库存/权益核验人和时间：
- 最终答复与下一步：

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
