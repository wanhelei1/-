# 教育话术框架

## 用途

区分行政、教师、学生、机房和实验室任务，用课程与平台兼容驱动选型。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

学校希望教师和学生共用一套推荐清单，但不同学科的软件、教室投影和账号管理差异明显。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

### 3. 教室投影、打印和实验外设型号是什么？

**为什么要问：** 验证真实环境。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 设备是否个人持有或集中管理？

**为什么要问：** 决定账号、镜像和维护。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 未成年人数据与课堂录制如何处理？

**为什么要问：** 控制隐私风险。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 先按角色和学科拆分，不以‘教育本’概括。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 用一节真实课程验证登录、课件、投屏、音视频和作业。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 专业软件与实验外设由学科负责人确认。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 教学收益只描述流程变化，不虚构提分或健康效果。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 把培训、备机和课间恢复写入方案。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 学校希望教师和学生共用一套推荐清单，但不同学科的软件、教室投影和账号管理差异明显。

**示范处理：** 内容示例从‘一节课会经过哪些设备和步骤’切入：教师备课、进教室连接、播放课件、互动、收作业和课后归档。每一步列出应用、网络与外设条件，再选择候选SKU；不把屏幕认证写成医学承诺。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 把教师办公、学生学习和实验室软件混为一类
- 只看硬件参数，不到教室测试投影与网络
- 用‘保护视力’‘提升成绩’作无依据承诺
- 在共享知识库放入学生姓名、账号或作品

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
