# 话术事实边界

## 用途

规定销售、方案和内容创作在事实、推断、体验与动态信息之间的边界。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

创作者拿到一个系列名称和几张产品图，希望直接生成一篇带价格、续航和软件兼容结论的推荐文章。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 完整型号和SKU是什么？

**为什么要问：** 决定参数能否落到具体销售版本。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 系统路线和版本是否明确？

**为什么要问：** 鸿蒙、Windows或其他路线的能力不能混用。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 数字来自哪一页、哪一天？

**为什么要问：** 识别系列最高值、实验室条件和动态变化。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 体验由谁在什么环境获得？

**为什么要问：** 避免虚构第一人称体验。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 价格、库存和权益由谁授权？

**为什么要问：** 动态字段必须实时核验。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 哪些结论仍缺证据？

**为什么要问：** 允许输出待核验而不是补写。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 把每句话标成事实、条件性事实、场景推断、创作表达或动态字段。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 硬事实回到P1/P7与官方原页，第三方内容只用于发现问题和结构。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 把最高、可选、典型、实验条件和版本限制留在句子里。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 无法确认时缩小结论并给出核验动作。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 发布前逐句检查型号、数字、图片、价格和体验来源。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 创作者拿到一个系列名称和几张产品图，希望直接生成一篇带价格、续航和软件兼容结论的推荐文章。

**示范处理：** 可写：‘该型号官方规格页列出了14.2英寸3:2屏幕；是否为柔光版本需按当前SKU确认。’不可写：‘我连续用了一个月，所有版本都不反光而且续航一整天。’前者区分事实与配置，后者同时虚构体验、泛化版本和承诺续航。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 把同系列不同配置拼成一台不存在的标准机
- 用搜索摘要或媒体转述替代官方原页
- 把作者体验写成所有用户都会得到的效果
- 为了文案完整而补造价格、销量、库存或软件兼容

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
