# 政企话术框架

## 用途

把产品介绍转成可验证的业务、部署、运维和服务方案。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

某单位计划更换办公终端，岗位包含普通办公、财务和会议支持，要求统一管理但存量应用与外设尚未盘点。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 覆盖哪些岗位、地点和数量？

**为什么要问：** 确定是否能采用统一基线。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 必装应用、插件、证书和外设是什么？

**为什么要问：** 建立兼容清单。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 账号、网络和安全策略由谁管理？

**为什么要问：** 识别权限与测试环境。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 数据怎样迁移、备份和退出？

**为什么要问：** 控制交付风险。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 什么条件算试点通过？

**为什么要问：** 避免演示代替验收。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 报修、备机与生命周期由谁负责？

**为什么要问：** 说明服务边界。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 先画业务链路，再映射终端能力。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 按岗位分层，不强行一个配置覆盖所有人。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 每个关键结论附官方证据或POC用例。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 把待验证项、失败回退和责任人写进方案。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 价格与交期单独引用获授权记录，不混入公开事实。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 某单位计划更换办公终端，岗位包含普通办公、财务和会议支持，要求统一管理但存量应用与外设尚未盘点。

**示范处理：** 方案表达示例：‘普通办公组先验证OA、会议与打印；财务组增加税务控件、UKey和大表格；会议支持组增加投屏、音频和多接口。试点通过标准由客户签字确认，未验证的安全认证不写成已满足。’

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 只讲轻薄、性能和生态，不讲存量系统
- 用消费级体验词替代安全、兼容和运维证据
- 把一次演示成功写成全量部署可行
- 未经授权承诺交期、服务等级或合规结论

## 证据路径

- P8对应行业完整参考案例
- P1商用与具体型号事实
- P7部署、网络、外设和恢复指南
- 客户授权的技术规范与验收文档

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
