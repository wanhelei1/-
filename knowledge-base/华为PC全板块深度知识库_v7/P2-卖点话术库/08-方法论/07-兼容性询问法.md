# 兼容性询问法

## 用途

把‘能不能用’拆成软件、版本、插件、项目、授权、外设和组织策略。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

用户询问某专业软件在目标电脑上是否兼容，但只提供了软件简称。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 身份？

**为什么要问：** 软件全名、版本、架构与授权。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 依赖？

**为什么要问：** 插件、驱动、运行库和账号。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 项目？

**为什么要问：** 文件格式、规模和核心操作。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 外设？

**为什么要问：** 加密狗、采集卡、打印或存储。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 证据？

**为什么要问：** 软件厂商要求、华为支持和实机记录。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 结论？

**为什么要问：** 安装、可启动、核心功能与性能分开。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 身份：软件全名、版本、架构与授权。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 依赖：插件、驱动、运行库和账号。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 项目：文件格式、规模和核心操作。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 外设：加密狗、采集卡、打印或存储。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 证据：软件厂商要求、华为支持和实机记录。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
6. 结论：安装、可启动、核心功能与性能分开。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 用户询问某专业软件在目标电脑上是否兼容，但只提供了软件简称。

**示范处理：** ‘能打开安装包’不能代表完整兼容。应先查软件厂商系统要求，再用脱敏项目测试打开、编辑、导出、插件和外设；未知项保留为待核验。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 跳过需求直接输出结论
- 引用了数字却没有型号、来源或条件
- 把一个人的体验泛化为所有用户
- 发现未知项时用模糊形容词掩盖

## 证据路径

- P1具体型号事实与限制
- P7官方支持与综合指南
- P3同期竞品官方证据（仅在需要比较时）
- P4获授权动态记录（仅在需要价格/政策时）

## 输出记录模板

- 用户/客户任务：
- 完整产品与SKU：
- 系统、软件、插件和外设：
- 必须满足 / 希望改善 / 可以放弃：
- 已确认事实、来源与日期：
- 待核验项、影响与责任人：
- 候选方案及各自取舍：
- 演示或试点步骤与通过标准：
- 动态价格/库存/权益核验人和时间：
- 最终答复与下一步：

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
