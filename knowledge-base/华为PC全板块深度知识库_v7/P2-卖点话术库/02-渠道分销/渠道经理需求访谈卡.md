# 渠道经理需求访谈

## 用途

在铺货和物料制作前，把客群、SKU、库存节奏、培训与服务责任问清。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

渠道经理计划下月做校园和商圈联动活动，希望先要‘一套全平台物料’，但尚未确认SKU和库存。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 活动覆盖哪些城市、门店和线上账号？

**为什么要问：** 确定版本、口径和责任范围。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 每个渠道实际拿到哪些SKU？

**为什么要问：** 防止配置错位。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 客群、价位与高频任务分别是什么？

**为什么要问：** 形成不同内容主线。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 库存和活动信息多久更新一次？

**为什么要问：** 设置失效机制。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 门店和主播已掌握哪些知识？

**为什么要问：** 决定培训深度。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 咨询、售后和异常价格由谁处理？

**为什么要问：** 建立升级路径。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 把活动拆成渠道×SKU×客群矩阵。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 先做事实卡和禁说清单，再做创意物料。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 为动态字段预留人工填写区，不写死在长期模板。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 上线前做一次错误配置和缺货演练。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 活动结束回收旧物料并复盘高频问题。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 渠道经理计划下月做校园和商圈联动活动，希望先要‘一套全平台物料’，但尚未确认SKU和库存。

**示范处理：** 示例输出包含三张表：SKU与证据表、平台物料表、责任与时效表。校园账号用学习与软件核验角度，商圈门店用通勤和实机体验角度；同一数字只从对应SKU事实页引用，活动价留给当日授权记录。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 先做海报再确认销售配置
- 所有平台只裁剪同一篇长文
- 库存不足时继续用倒计时制造紧迫
- 活动结束后不撤下过期价格与权益

## 证据路径

- P1销售版本与图片索引
- P4授权库存/价格/活动记录
- P5渠道培训课程
- P6平台模板与完整成稿案例

## 输出记录模板

- 用户/客户任务：
- 完整产品与SKU：
- 系统、软件、插件和外设：
- 必须满足 / 希望改善 / 可以放弃：
- 已确认事实、来源与日期：
- 待核验项、影响与责任人：
- 候选方案及各自取舍：
- 演示或试点步骤与通过标准：
- 动态价格/库存/权益核验人和时间：
- 最终答复与下一步：

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
