# 渠道分销话术框架

## 用途

围绕可售SKU、目标客群、证据物料、培训和交付风险组织渠道沟通。

本文件用于训练与生成，不直接替代具体型号事实。任何参数、功能、支持范围、服务和动态信息都要回到相应来源；资料不足时允许给出有限结论和验证计划，不为追求顺畅话术补造信息。

## 使用情境

区域渠道希望主推一款电脑，但线上、门店和政企客户的配置与需求不同，现有物料只写了系列卖点。

## 开始前准备

- 记录用户原话、任务频率、不能接受的风险和期望完成时间。
- 获取完整型号/SKU、系统与软件版本；涉及外设时记录品牌、型号、接口和连接链路。
- 打开P1事实、P7支持与必要的厂商官方页面，不用记忆或搜索摘要代替原页。
- 将价格、库存、赠品、服务权益和交期放进单独的动态字段，并标注核验人和时间。

## 关键问题树

### 1. 本次可销售的具体SKU和区域是什么？

**为什么要问：** 避免拿不可售配置培训。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 2. 目标客群与主任务是什么？

**为什么要问：** 决定物料角度。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 3. 哪些参数是全系、可选或最高值？

**为什么要问：** 防止门店误讲。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 4. 价格、库存和权益由谁更新？

**为什么要问：** 建立动态字段责任。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 5. 一线最常遇到的三个异议是什么？

**为什么要问：** 决定培训和FAQ。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

### 6. 交付、退换和售后由哪个渠道承接？

**为什么要问：** 避免越权承诺。如果这一项无法确认，不应把受它影响的参数、兼容性或推荐写成确定结论。

## 执行步骤

1. 先锁定SKU与渠道，再写定位。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
2. 为每个卖点配事实页、适用场景和一句限制。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
3. 按门店、直播、企业销售拆分物料，不共用一套话术。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
4. 建立活动、库存和政策失效时间。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。
5. 上线前让一线用真实问题反向测试物料。完成后把结果标成‘已确认 / 待测试 / 不适用’，并附证据位置。

## 完整示范

**情境：** 区域渠道希望主推一款电脑，但线上、门店和政企客户的配置与需求不同，现有物料只写了系列卖点。

**示范处理：** 渠道简报不写‘全系顶配’，而写‘本批次SKU为【完整配置】，适合【任务】，需要确认【软件/接口】；屏幕款式、价格与赠品按区域当日表执行。’培训中用三个顾客问题演练，并把答不上来的内容进入待核验表。

**建议收口：** ‘以上结论只对应已经确认的型号、版本和任务；未确认项已列入验证清单。你可以带常用文件、软件版本或外设完成实机核验，价格与权益则以当日授权页面或结算信息为准。’

## 正确表达与错误表达

- 正确：先给有限结论，再说明证据、适用条件和下一步。
- 正确：主动说出不适合的人群或需要先验证的门槛。
- 错误：‘肯定都能用’‘全系都是这个配置’‘任何情况都可以’。
- 错误：虚构第一人称体验、用户评价、销量、库存或无法核验的效率百分比。

### 本主题常见错误

- 用系列最高参数代替可售SKU
- 把总部新闻稿直接当成门店销售话术
- 没有给价格、权益和物料设置失效日期
- 只教卖点不教限制、异议与转人工路径

## 证据路径

- P1具体SKU与产品事实
- P4获授权渠道/活动记录
- P6对应平台成稿与图片索引
- P7售后与退换官方入口

## 发布或交付前检查

- □ 型号、SKU、系统路线和版本没有混用。
- □ 每个数字都能回到当前适用的官方页面，并保留限定词。
- □ 第三方案例只用于研究问题与结构，没有当成产品事实。
- □ 体验来自真实、获授权的测试，没有伪造人物或使用时长。
- □ 价格、库存、活动、交期和服务权益带有日期与责任人。
- □ 已说明限制、不适用情形、待核验项和转人工路径。
