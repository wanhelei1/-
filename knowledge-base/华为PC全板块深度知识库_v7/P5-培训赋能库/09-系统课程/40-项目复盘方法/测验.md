# 项目复盘方法｜测验

## 题目

1. 复盘首先回看什么？
2. 事实与解释怎样分开？
3. 复盘为什么不应只列问题？
4. 行动项怎样才可执行？
5. 复盘如何反哺知识库？

## 参考答案与解析

### 第1题

**答案：** 回看原目标、成功标准、范围和假设，避免仅凭最后印象评价。

**解析：** 这道题考查能否把“复盘首先回看什么？”放回具体任务、版本与证据条件中。只写一个肯定或否定结论得不到满分；还需说明结论适用对象、不能推断的部分，以及应到哪里继续核验。

### 第2题

**答案：** 事实记录发生了什么和证据；解释说明可能原因，并标注尚待验证的假设。

**解析：** 这道题考查能否把“事实与解释怎样分开？”放回具体任务、版本与证据条件中。只写一个肯定或否定结论得不到满分；还需说明结论适用对象、不能推断的部分，以及应到哪里继续核验。

### 第3题

**答案：** 还要识别有效做法、可复用材料和应保持的流程。

**解析：** 这道题考查能否把“复盘为什么不应只列问题？”放回具体任务、版本与证据条件中。只写一个肯定或否定结论得不到满分；还需说明结论适用对象、不能推断的部分，以及应到哪里继续核验。

### 第4题

**答案：** 写明具体动作、负责人、截止时间、验收标准和依赖。

**解析：** 这道题考查能否把“行动项怎样才可执行？”放回具体任务、版本与证据条件中。只写一个肯定或否定结论得不到满分；还需说明结论适用对象、不能推断的部分，以及应到哪里继续核验。

### 第5题

**答案：** 把新事实、FAQ、失败条件、话术和演示步骤送审核，更新版本并通知受影响内容。

**解析：** 这道题考查能否把“复盘如何反哺知识库？”放回具体任务、版本与证据条件中。只写一个肯定或否定结论得不到满分；还需说明结论适用对象、不能推断的部分，以及应到哪里继续核验。

## 综合应用题

情境：一次企业演示中协同功能成功，但行业软件测试失败；团队会后只说“现场网络不好”。

任务：用时间线和证据复盘，区分已知事实与假设，生成三个有负责人和验收标准的行动项。

### 综合题参考作答

- 重建环境、版本和操作时间线。
- 网络只是待验证假设。
- 保留成功与失败证据。
- 把兼容结论、演示前检查和复测结果更新到相应库。

作答还应附一条证据路径、一项待核验信息和一个可验收的下一步。若资料不足，应主动缩小结论，不得把未证实内容补成完整答案。

## 常见失分原因

- 只背“项目复盘方法”的定义，没有把它转成用户任务和决策条件。
- 引用系列宣传、第三方体验或搜索摘要，却没有核对具体型号、配置、版本和日期。
- 写出参数后直接得出“更好”“一定适合”，没有解释取舍和不适用场景。
- 发现证据不足仍继续猜测，或只说“以实际为准”而不给核验动作。

## 评分与补学路径

- 基础题每题2分：结论正确1分，能说出条件、限制或证据路径1分，共10分。
- 综合应用题5分：需求拆解、证据、边界、方案和下一步各1分。
- 总分15分；12分及以上通过。9—11分回看对应核心知识并重答错题；低于9分先重做情景演练，再用另一型号或场景完成一次迁移练习。

## 推荐复习证据

项目需求、验收记录、问题日志、版本变更和知识库审核流程。
