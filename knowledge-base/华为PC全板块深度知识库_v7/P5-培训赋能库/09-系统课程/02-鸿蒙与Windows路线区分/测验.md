# 鸿蒙与Windows路线区分｜测验

## 题目

1. 选择系统路线首先看什么？
2. 能否仅凭“办公”判断系统路线？
3. 软件兼容应怎样核验？
4. 生态协同如何表达？
5. 信息不全时推荐原则是什么？

## 综合应用题

情境：一名用户主要写文档、开视频会议，但每月还需使用单位发放的专用报税插件；他同时拥有华为手机。

任务：设计五个追问，给出推荐前的验证动作，并分别写出“可确认兼容”和“尚未确认兼容”两种回答。

### 综合题参考作答

- 专用插件是决策门槛，须确认名称、版本与系统要求。
- 手机协同是收益项，不能覆盖软件兼容门槛。
- 会议软件也需确认版本和摄像头权限。
- 无法确认时建议实机或软件厂商验证。

作答还应附一条证据路径、一项待核验信息和一个可验收的下一步。若资料不足，应主动缩小结论，不得把未证实内容补成完整答案。

## 常见失分原因

- 只背“鸿蒙与Windows路线区分”的定义，没有把它转成用户任务和决策条件。
- 引用系列宣传、第三方体验或搜索摘要，却没有核对具体型号、配置、版本和日期。
- 写出参数后直接得出“更好”“一定适合”，没有解释取舍和不适用场景。
- 发现证据不足仍继续猜测，或只说“以实际为准”而不给核验动作。

## 评分与补学路径

- 基础题每题2分：结论正确1分，能说出条件、限制或证据路径1分，共10分。
- 综合应用题5分：需求拆解、证据、边界、方案和下一步各1分。
- 总分15分；12分及以上通过。9—11分回看对应核心知识并重答错题；低于9分先重做情景演练，再用另一型号或场景完成一次迁移练习。
