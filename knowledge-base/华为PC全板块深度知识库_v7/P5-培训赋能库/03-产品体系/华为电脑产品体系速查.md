# 华为电脑产品体系速查

## 一、这张速查表解决什么问题

本材料训练学员正确识别“正在谈哪一台电脑”，再依据用户任务进入具体资料。它不提供一份永久不变的在售清单，也不把系列定位当成具体产品参数。产品名称、配置、销售状态会变化，实际结论以 `P1-产品参数库/00-全库横向索引/全型号总览.md`、当前官方产品页和销售配置页为准。

最重要的规则是：先区分系统路线，再识别系列、机型、代际或年份、完整型号、销售配置和渠道对象。任一层级不同，都可能导致参数、功能、图片和服务信息不能复用。

## 二、产品身份的六个层级

| 层级 | 回答的问题 | 可以用于什么 | 不能直接推出什么 |
|---|---|---|---|
| 系统路线 | 设备采用哪条系统与应用生态路线 | 决定兼容性核验方向和学习入口 | 某应用一定可用、所有协同功能均支持 |
| 产品系列 | 属于哪个产品家族 | 初步理解形态和目标任务 | 某一具体屏幕、接口、处理器或重量 |
| 机型/代际 | 哪一代或哪一年份的具体产品 | 进入对应规格、支持和图片资料 | 当前渠道售卖的具体配置 |
| 完整型号 | 设备或商品的精确身份字段 | 核对说明书、驱动、支持范围 | 仍可能存在多个销售组合或可选项 |
| 销售配置/SKU | 本次购买对象的处理器、内存、存储、颜色等组合 | 成交前核对实际对象 | 动态价格、库存、赠品或交期 |
| 渠道与时间 | 在哪个渠道、地区、什么时间查询 | 核验当前销售与政策信息 | 对其他渠道和未来时点的承诺 |

用户只说“MateBook”“某数字系列”或“鸿蒙电脑”时，信息通常不够。合格追问是：“请提供商品页完整名称和配置，或设备系统信息中的型号；同时告诉我采用的系统路线。你要确认的是规格、软件、图片还是服务？”

## 三、系统路线先分流

### 鸿蒙电脑路线

先查当前鸿蒙电脑官方页面与 P1 中对应条目，再确认目标应用、文件格式、账号、外设和跨设备需求。不能因为某项系统能力在官方页面出现，就默认所有型号、版本、账号和配套设备均具备相同体验。

### Windows 电脑路线

先查具体机型资料，再根据 Windows 版本、驱动、软件厂商要求和外设链路判断。不能仅因软件“有 Windows 版本”就承诺其在用户的插件、组织网络或特殊外设下完整可用。

### 为什么不能混写

两条路线可能存在相近的产品名称或用户任务，但应用取得方式、协同条件、系统设置和服务排查入口不同。内容制作时，标题、正文、界面截图、操作步骤与图片必须属于同一路线；确需对比时，要分别列证据和条件。

## 四、产品系列不是配置表

系列信息用于帮助提出问题，不用于直接下结论。面对任一系列，都从以下七个维度观察：

1. **形态与使用地点**：经常携带、固定工位、频繁会议或多地点切换。
2. **屏幕任务**：阅读、表格、图像、视频、触控或多人观看；具体字段再查当前型号。
3. **计算任务**：应用名称、版本、文件规模、并发方式和加速要求。
4. **接口与外设**：显示器、投影、存储、打印、音视频、扩展坞和供电链路。
5. **系统与软件**：系统路线、应用、账号、插件、组织策略与数据流转。
6. **移动与供电**：携带频率、包内总重量、充电条件、离电任务；续航必须保留测试条件。
7. **部署与服务**：个人使用还是组织资产，是否需要批量部署、迁移、培训和服务衔接。

只有这些需求明确后，系列定位才有筛选价值。不要用“高端、旗舰、轻薄、专业”等营销词代替字段判断。

## 五、从目录到具体条目的检索路线

1. 在 `P1-产品参数库/00-全库横向索引/全型号总览.md` 查名称与系统路线。
2. 进入该产品所在目录，核对是否有具体型号、销售配置、图片索引和来源记录。
3. 对照当前官方产品页，核对发布日期或访问日期以及“最高、可选、视配置”等限定。
4. 若是商城对象，再查 `P1-产品参数库/04-华为商城销售款式/商城在售款式快照.md`；快照只说明记录时点，不等同当前在售。
5. 软件与外设问题进入 `P7-常见问题库/01-售前FAQ/软件与兼容FAQ.md`，必要时查软件或外设厂商官方说明并做目标环境验证。
6. 输出时记录本地路径、官方 URL、访问日期、完整对象、引用字段和未确认项。

## 六、选型字段表

| 用户语言 | 需要追问 | 候选比较字段 | 风险提示 |
|---|---|---|---|
| “经常背着跑” | 每周携带频率、是否带电源与外设、交通方式 | 尺寸、整机与电源重量、接口、供电条件 | 不能只比较裸机重量；实际体验需试拿 |
| “表格和窗口很多” | 应用数量、数据规模、外接屏、持续时间 | 处理器、内存、屏幕、接口、散热条件 | 单个参数不能保证不卡顿 |
| “要做设计/视频” | 软件版本、插件、素材、导出要求、外设 | CPU/GPU、内存、存储、屏幕、接口、软件支持 | 必须核验软件架构与加速支持 |
| “经常开会” | 会议软件、环境、摄像头麦克风、投屏方式 | 音视频、无线、接口、隐私权限、协同条件 | 会议应用内部设置可能独立于系统 |
| “手机平板一起用” | 设备型号、系统版本、账号、目标动作 | 具体协同功能及前置条件 | 不将一次演示扩展到所有设备 |
| “公司统一采购” | 用户规模、镜像、账号、网络、安全、服务 | 管理、部署、兼容、交付、验收 | 消费端体验不能替代项目验证 |

## 七、三个场景练习

### 场景 A：移动办公

客户常在不同地点写文档、开视频会议并连接投影。学员先问每周携带天数、会议软件、网络、投影接口、文件流转和供电环境。然后从 P1 选择不超过三条候选路径，比较与任务有关的字段；明确仍需验证的软件、投影链路和协同条件。不得以“最轻”或“续航最长”作无来源结论。

### 场景 B：固定工位大屏办公

客户主要处理多列表格，较少移动，希望连接现有显示器、键鼠和网络设备。学员要区分“希望内置大屏”和“可接受外接屏”，记录桌面接口与扩展设备，比较屏幕任务、键盘输入、接口、无线和维护方式。候选理由必须能回到用户工作动作。

### 场景 C：内容创作

客户使用指定版本应用处理图片和视频。学员收集素材类型、典型规模、导出格式、插件、显示要求、存储和备份方式。先完成软件兼容核验，再谈处理器、图形、内存、屏幕与存储；如果目标应用无可靠支持信息，方案应保留原工作路径或安排样机测试。

## 八、事实表达示例

不合格：“这个系列都配某项能力，很适合设计师。”系列范围和“适合”都没有证据。

合格：“当前资料在【具体型号/配置】中列出【字段】；它与用户的【任务】相关，但真实效果还受【软件、文件、环境】影响。我们将用【样本与步骤】验证，结论只适用于本次测试条件。”

不合格：“鸿蒙版和 Windows 版只是系统不同。”这忽略应用生态、设置、协同和支持路线。

合格：“两条路线需要分别核验目标应用、外设、账号、网络和工作流。先列出不可中断的任务，再选路线，不从外观或系列名推断。”

## 九、学员测验与判分

题一：给出一个只有系列名的咨询，写最少五个澄清问题。题二：从 P1 选两个真实条目，建立同口径比较字段，不要求得出优劣。题三：用户更改一个关键软件版本后，说明候选为何需要重新验证。题四：指出“系列最高配置”被写成“当前配置”的错误并修正。题五：为一张产品图片写对象、来源、用途与图注。

每题 20 分。对象识别 20、系统路线 15、需求到字段 20、证据与条件 20、兼容边界 15、表达清楚 10。总分至少 82；对象识别和证据条件均不低于各自 80%。编造参数、混用图片、把可选写成标配或作无条件兼容承诺，直接退回。

官方入口：https://consumer.huawei.com/cn/laptops/ 与 https://consumer.huawei.com/cn/harmonyos-computer/ 。使用时记录访问日期，不把页面结构和在售状态视为永久不变。
