# 知识库使用快速入门

## 一、先理解知识库解决什么问题

本知识库帮助使用者从公开资料中快速找到产品事实、表达方法、竞品公开信息、培训资料、营销模板、常见问题和客户场景。它不自动保证所有内容永远最新，也不替代受控的价格政策、项目审批、合同、目标软件的兼容测试或官方人工服务。

正确使用方式不是搜到一句就复制，而是完成“识别对象—选择目录—组合检索—核对来源—保留条件—组织回答—记录引用”七步。首次使用可用 20 分钟完成下面练习。

## 二、目录地图

| 问题类型 | 首查目录 | 使用提示 |
|---|---|---|
| 具体型号、销售配置、产品图片 | `P1-产品参数库` | 必须确认完整型号、配置和系统路线 |
| 场景表达、访谈、异议结构 | `P2-卖点话术库` | 方法不能替代事实，数字仍回到 P1 |
| 竞品公开规格与对比字段 | `P3-竞品资料库` | 同口径、同日期、同销售对象比较 |
| 价格、库存、活动与项目政策 | `P4-价格政策库（机密）` | 仅授权人员按当前记录使用，不对外暴露内部信息 |
| 培训、测验、演练 | `P5-培训赋能库` | 用于学习方法，不当作产品事实源 |
| 平台模板、图片规则、内容案例 | `P6-营销素材库` | 先核验事实与图片来源，再套平台结构 |
| 售前售后 FAQ、故障与服务入口 | `P7-常见问题库` | 操作前识别数据风险和升级条件 |

## 三、七步检索法

### 第 1 步：把问题改写成可检索对象

原问：“这款怎么样？”不能直接检索。先补齐：完整销售名称或型号、系统路线、用户要完成的任务、特别关注的字段、所在渠道与时间条件。

示例改写：“用户询问某完整型号、某销售配置在其当前系统路线下能否连接指定外设；需要确认接口与兼容条件。”这样可以分别查 P1 的产品事实和 P7 的兼容性方法。

### 第 2 步：判断问题属于事实、方法还是动态信息

“有几个接口”是产品事实；“怎样向会议用户解释接口取舍”是表达方法；“今天是否有货”是动态信息；“某专业软件能否运行”既需要公开信息，也需要目标版本和环境验证。一个问题可以跨目录，但每类信息须来自对应资料。

### 第 3 步：组合关键词

优先使用“完整型号 + 字段”“系统路线 + 功能 + 条件”“症状 + 场景 + 版本”。搜索不到时依次去掉营销称呼、改用标准术语、搜索上级目录索引，再查官方 URL。不要只搜宽泛词“华为电脑”“协同”“性能”。

关键词迭代示例：`系列名 触控` → 结果太多；改为 `完整型号 触控 规格` → 找到具体配置；再核对该配置是否为当前提问对象。

### 第 4 步：读完整条目而非摘一句

同时阅读标题、适用对象、发布日期或访问日期、正文限定和来源。看到“最高、最长、可选、部分、支持至、视配置而定、需升级”等词，必须把条件带入回答。系列页的能力不能直接等于每个 SKU 标配。

### 第 5 步：处理冲突与缺口

不同资料不一致时，记录两个说法、各自对象、来源和日期，依据 `00-建库规范/05-版本管理/冲突信息处理.md` 处理。不要拼成一个看似完整的新结论。找不到可靠来源时写“当前资料不足，需要核验”，同时说明需要什么信息以及谁去确认。

### 第 6 步：用固定骨架回答

建议结构为：

1. **结论**：当前能够确认什么。
2. **对象**：适用于哪个完整型号、配置、系统或场景。
3. **证据**：资料标题、关键字段和来源。
4. **限制**：版本、可选项、账号、网络、外设或测试条件。
5. **下一步**：用户如何验证或由谁确认。

示例：“当前资料能确认该条目描述了某能力，但能否用于你的指定软件还不能仅凭产品规格判断。请补充软件准确名称、版本、插件和外设；随后查看软件官方支持范围，并在目标设备上用脱敏样本验证。现阶段不作无条件兼容承诺。”

### 第 7 步：保存最小证据包

对外内容至少保留：问题原文；对象信息；使用的本地文件；官方 URL；访问日期；引用事实及条件；无法确认项；图片文件名与来源；审核人和版本号。聊天记录可作为需求背景，不应成为唯一事实来源。

## 四、图片检索与引用

先确认图片对应的具体产品，再判断是官方渲染图、实拍、功能示意、界面截图还是第三方图片。使用前阅读 `00-建库规范/04-内容审核/图片核验流程.md` 和 `P6-营销素材库/04-图片/图片选用与命名指南.md`。

图片命名建议包含品牌、系列或型号、视角或场景、颜色或关键特征、来源类型和序号，例如“品牌_型号_左侧接口_官方产品页_01”。形容词可以用于帮助搜索，但不能暗示图片未能证明的性能。图注写清“展示什么、适用对象、来源”，概念图或示意图要明确标注。

禁止做法：用另一型号图片代替；裁切后删除必要说明；把第三方体验图写成官方效果；未经授权下载再传播；仅凭文件名判断型号；在截图中泄露账号、订单或设备标识。

## 五、三类完整示例

### 示例 A：查询某机型屏幕是否支持某特性

先取得完整型号和销售配置；进入 P1 的具体资料；查看该字段是否写“可选”或仅存在于系列页；再核对官方 URL 与日期。回答中写明适用配置。若知识库只有系列级描述，不能答“全部支持”，应请用户查看当前商品规格或设备信息。

### 示例 B：用户问专业软件能否安装

先问软件全名、版本、许可方式、插件、文件格式和必须连接的外设；查 `P7-常见问题库/01-售前FAQ/软件与兼容FAQ.md` 以及软件厂商公开要求；区分“可安装、可启动、核心流程可用、性能满足、厂商支持”五个层级；最终以目标环境验证为准。

### 示例 C：内容人员需要一张产品图

先把正文中的完整型号、颜色和场景写成选图条件；到对应图片目录核对来源和说明；记录原 URL、访问日期、文件名、用途、裁切要求和图注；发布前由另一人核对图文型号一致。没有合适图片时不要“找一张相似的”，可改用经审核的结构图或不配图。

## 六、常见错误与修正

| 错误 | 为什么危险 | 修正动作 |
|---|---|---|
| 只凭系列名回答 | 同系列可有不同代际、配置和系统 | 补完整型号、销售配置、系统路线 |
| 复制搜索摘要 | 摘要可能截断条件或过期 | 打开原文并记录访问日期 |
| 把“最高/可选”写成标配 | 扩大了事实范围 | 保留限定并核对当前 SKU |
| 用话术文件证明参数 | 表达方法不是事实来源 | 回到 P1 或官方页面 |
| 用旧价格截图对外承诺 | 动态信息可能已变化 | 当次受控查询，并写有效范围 |
| 说“兼容”但未问版本 | 不同版本和插件条件可能不同 | 完成兼容问题清单和验证 |
| 没找到就补全常识 | 会产生无法追溯的内容 | 明确资料不足并安排核验 |

## 七、15 分钟入门练习

第 1 题：选择一个 P1 中已有条目，写出完整对象、五条事实和三条限定。第 2 题：从 P7 找一个操作问题，给出结论、步骤、停止条件和官方入口。第 3 题：从 P6 选择一个平台模板，把同一事实改写成标题和两段正文，不新增任何参数。第 4 题：为一张图片制作来源卡。

每题 25 分。对象准确 20；来源和日期 20；条件完整 20；回答结构 15；图片与引用 15；缺口和下一步 10。总分至少 80，且对象准确和条件完整不得低于各自 16 分。编造参数、泄露受限信息、虚构来源或使用未经确认的动态价格，直接重做。

## 八、发布前自检

我回答的是具体对象吗？数值来自哪份资料？限定词是否保留？来源和日期能回查吗？图与型号一致吗？事实、体验和建议是否分开？动态信息是否当次确认？无法确认的内容是否明确？下一步能由用户或同事执行吗？若其中任一项答不上来，先不要发布。
