# 元数据模板

## 目标

规定事实、图片、案例和动态记录至少要保存哪些字段，保证答案可复查、可更新。

## 适用范围

本规则适用于知识采集、清洗、入库、智能体检索、内容生成、人工审核、发布和归档。它不授权访问受限系统，也不允许用公开资料推断内部价格、客户信息或未发布产品。

## 核心规则

### 1. 事实记录产品/SKU、系统或版本、字段、值、限定词、来源URL、页面标题、抓取日期和审核状态

执行时记录操作者、来源或输入、日期、判断结果与下一步。若该规则依赖具体型号、版本、渠道或权限，必须把适用条件写进同一句结论。

### 2. 图片记录文件名、画面、对应型号/款式、原图URL、来源页、尺寸、版权/使用边界

执行时记录操作者、来源或输入、日期、判断结果与下一步。若该规则依赖具体型号、版本、渠道或权限，必须把适用条件写进同一句结论。

### 3. 案例记录平台、受众、目标、结构、使用事实、图片、创作日期、审核人与失效条件

执行时记录操作者、来源或输入、日期、判断结果与下一步。若该规则依赖具体型号、版本、渠道或权限，必须把适用条件写进同一句结论。

### 4. 动态信息另记渠道、地区、时间、资格、有效期和授权人

执行时记录操作者、来源或输入、日期、判断结果与下一步。若该规则依赖具体型号、版本、渠道或权限，必须把适用条件写进同一句结论。

### 5. 未知字段留空并写待核验，不使用‘同系列应当一样’补齐

执行时记录操作者、来源或输入、日期、判断结果与下一步。若该规则依赖具体型号、版本、渠道或权限，必须把适用条件写进同一句结论。

## 操作流程

1. 识别任务：这是事实问答、操作支持、竞品比较、动态查询、内容创作还是案例研究。
2. 补齐身份：记录产品/SKU、系统/软件版本、地区、渠道、日期和目标受众。
3. 获取证据：按权威来源顺序打开原页；本地卡片只作导航，不能替代原始核验。
4. 应用本规则：逐项标记通过、需改写、待核验、拒绝或转人工，并写明原因。
5. 复核输出：检查事实、条件、图片、动态字段、敏感信息、版权和平台要求。
6. 保存记录：更新版本、审核人与失效条件；旧版本移入历史归档。

## 正确示例

一条屏幕事实同时记录‘仅柔光版’和抓取日期；成稿引用时把限定词带入正文。

## 错误示例

CSV只有‘型号、参数’两列，既没有SKU也没有来源和日期，后续无法判断是否仍适用。

## 异常与例外

来源页面无法打开时，保留原URL与最后核验日期，状态改为待审核，并寻找同级官方替代来源。

若例外会改变公开结论，先把相关文件移入待审核；若涉及数据删除、安全策略、凭证、内部政策或客户信息，停止自动处理并转有权限人员。

## 审核记录

- 任务与内容类型：
- 产品/SKU/系统/渠道/日期：
- 使用的官方来源与本地路径：
- 规则检查结果：通过 / 需改写 / 待核验 / 拒绝 / 转人工
- 冲突、未知项与风险：
- 修改内容与影响文件：
- 审核人、时间和下次复核日期：

## 最终检查

- □ 结论没有超出证据适用范围。
- □ 系列、型号、SKU、系统与时间没有混用。
- □ 不确定信息没有被模板或形容词补齐。
- □ 动态、敏感和受控内容进入了正确流程。
- □ 读者能够从引用回到原始来源并复核。
- □ 文件名、元数据、版本与审核状态已同步。
