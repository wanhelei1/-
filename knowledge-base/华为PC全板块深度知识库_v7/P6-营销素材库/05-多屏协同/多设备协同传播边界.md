# 多设备协同传播边界

协同类内容必须写清参与设备、系统版本、账号、网络、蓝牙或近场条件，不把某一组合演示扩展为所有手机、平板和电脑均可使用。

## 图文结构

1. 用一个具体任务开场，例如手机素材进入电脑文档、平板作为扩展屏或会议资料跨设备流转。
2. 列出设备名称、系统和连接前提，再描述操作路径。
3. 每一步配对应的官方或已登记图片，并标注图片展示的是界面、连接关系还是结果。
4. 单列“不适用或待确认”，包括企业策略、账号限制、文件类型、网络环境和第三方设备兼容。

发布前用目标设备完整走一遍连接、授权、传输、断线恢复和权限撤销。无法复现的功能不写成操作教程，只能引用官方页面并提示按当前版本核验。

## 先定义具体任务

“协同”不是一个可直接发布的结论。选题要落到可观察任务，例如：把手机里的三张照片放进电脑文档、在平板上扩展一个参考窗口、会议中调用手机摄像头、在两台已登录设备之间继续编辑文件。每篇只围绕一条链路说明，避免把多种功能拼成“所有设备无缝互联”。

## 前置条件表

发布前填写参与设备完整名称、系统版本、应用/电脑管家版本、账号、网络、蓝牙或近场状态、权限、线缆与配件。若功能只适用于指定区域、机型、系统或应用，应在标题附近和操作步骤前同时提醒。企业网络、终端管理、访客模式或安全软件可能改变结果，不能为了演示擅自关闭策略。

## 证据层级

1. 官方产品或功能页证明页面在核验日展示的能力与条件。
2. 官方支持页证明具体系统和版本的操作、限制与排障方式。
3. 目标设备实测证明本次组合和环境中的结果。
4. 场景图片只解释人物与任务，不证明兼容和性能。

只有第 1—3 层能够进入功能结论，且实测不能超出测试组合。第三方体验可帮助发现问题，但不作为官方承诺。

## 演示脚本

1. 镜头或图一先展示源文件、目标文件和人物要完成的任务。
2. 信息卡列出两端设备、系统、账号与网络条件。
3. 完整记录发现设备、授权、传输或投屏、结果确认的过程，不剪掉权限弹窗。
4. 人为断开一次连接，展示恢复或重新授权；若无法恢复，保留失败而不是换机后假装同一次成功。
5. 最后撤销不再需要的权限或连接，提示共享设备与敏感文件的安全边界。

## 常见失败分支

- 搜不到设备：确认型号、系统版本、网络/蓝牙/近场状态、可发现性和账号条件。
- 能连接但功能不可用：检查应用版本、权限、文件类型、企业策略及是否属于支持范围。
- 传输中断或结果不完整：记录文件大小、网络、错误提示和重试条件，不声称“稳定无感”。
- 休眠、切网或退出账号后失效：按官方支持路径重新核验，并在文章中说明触发条件。
- 第三方设备：同时查询对方官方文档；华为一侧页面不能单独证明双向兼容。

## 文案改写示例

不写“所有设备都能无缝协同”，可写“在已登记的设备、系统、账号和网络条件下，本次演示完成了手机照片进入电脑文档的流程；其他型号或企业环境需按官方支持范围重新验证”。不写“效率翻倍”，可写“原流程包含导出、发送、下载三步，本次流程记录为具体步骤；是否节省时间取决于文件、网络和组织权限”。

## 最终检查

- [ ] 参与设备、系统、账号、网络和权限写清。
- [ ] 每个画面与事实一一对应，没有用氛围图证明功能。
- [ ] 失败、断线恢复和权限撤销已经验证或明确待核验。
- [ ] 文件和屏幕内容脱敏，真实客户或业务资料已获授权。
- [ ] 标题、封面和 CTA 没有把本次组合外推成普遍兼容。
