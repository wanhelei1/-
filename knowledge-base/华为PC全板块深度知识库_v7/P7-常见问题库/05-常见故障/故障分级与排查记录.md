# 常见故障分级与排查记录｜安全、数据、业务三条线同时判断

> 目标：在不扩大损坏的前提下，把现象分级、建立可复现证据、选择最小风险动作并形成可交接记录。  
> 本指南是总入口；具体设备、系统和现象必须转到相应官方支持条目执行。

## 适用范围

适用于华为笔记本无法开机、断电、充电/电池、发热/风扇、系统、网络、显示、音频、键盘/触控、USB/外设、打印、协同和应用类故障的首次分诊。它不指导拆机、带电检修、刷写固件或绕过安全策略，不替授权服务中心判断硬件原因。

每个故障同时看三种影响：人身/电气安全，数据与账号安全，业务连续性。严重级别按最高一项确定；例如电脑还能用但电池鼓包，仍按安全紧急处理；设备无物理风险但唯一数据无法读取，应按数据高风险停止写入。

## 判断树

```text
收到故障
├─ 有冒烟、异味、鼓包、进液、烧蚀、异常高温、变形或裸露线缆？
│  ├─ 是 → P0：停止使用/充电，安全隔离并联系官方服务
│  └─ 否 → 继续
├─ 有唯一数据、磁盘异响/锁定、账号异常或疑似安全事件？
│  ├─ 是 → P1：停止破坏性操作，保护证据，升级数据/安全负责人
│  └─ 否 → 继续
├─ 是否造成关键业务中断且无替代？
│  ├─ 是 → P1：先启用经批准的业务替代，同时保留故障现场
│  └─ 否 → P2/P3 常规排障
├─ 问题范围？
│  ├─ 单应用/账号/网络/外设 → 先隔离该对象
│  ├─ 多功能同时异常 → 查共同电源、系统、更新、扩展坞或网络
│  └─ 偶发 → 建立时间、频率与触发条件记录
└─ 可逆步骤是否解决？
   ├─ 是 → 原任务 + 重启/重连复测，进入观察期
   └─ 否 → 软件/驱动/官方恢复评估或送修；高风险前再确认备份
```

## 步骤与追问

### 1. 先做 P0 安全筛查

询问进液、跌落、受压、异味、烟雾、火花、鼓包、异常高温、外壳翘起、适配器/线缆破损和是否仍通电。存在风险时，在不危及人员的情况下断开电源并停止使用，远离易燃物，联系官方服务；不要反复开机、继续充电、挤压/刺破电池、用热风吹或自行拆机。记录现象与时间，但不为拍摄靠近危险设备。

### 2. 判断数据与账号风险

询问数据是否唯一、是否有备份、磁盘是否加密、是否出现锁定/恢复密钥、是否有异常登录或恶意软件迹象。唯一数据、磁盘异响、反复掉盘时停止重装、格式化和反复写入。账号安全事件先隔离网络并交安全人员，不能只当普通应用故障。

### 3. 采集标准基线

记录完整型号、S/N 后四位或脱敏标识、系统和版本、最近更新/安装/跌落/外设变更、首次和最近时间、频率、原始错误、从哪个动作到哪个结果、是否能稳定复现。列出当前电源、网络、账号、应用、外设和扩展坞拓扑。截图应遮盖账号、联系人、网络、证书和完整 S/N。

### 4. 用范围定位层级

只在一个应用发生，先检查应用版本、账号、权限和样例文件；只在一个网络发生，做热点/同网设备对照；只在一个外设发生，直连并换已知正常线缆/端口；所有外设同时异常，检查共同扩展坞、供电和系统更新；多个功能同时异常，优先查看共同依赖而不是逐个重装。

### 5. 按可逆顺序处理

顺序建议为：保存工作与建立对照；检查连接/供电/选择项；退出并重新进入应用；在安全情况下重启；按具体型号和系统的官方条目核对权限、设置、更新和官方驱动；隔离第三方外设/软件；最后才评估系统恢复或送修。一次只改一个变量，记录原值、动作和结果；成功后停止继续改动。

### 6. 为不同故障选专属条目

Windows 身份、更新/恢复、密码/BitLocker、磁盘/开机、输入、显示/音频/USB/打印、WLAN、蓝牙、投屏和电池/散热分别进入 P7/08 对应指南。鸿蒙权限、网络/公司网/NAS、分享协同、迁移、外设和电池/散热也分别处理。不要因标题相似跨系统套菜单；具体步骤要回到 P7/07 官方条目和当前官方原文。

### 7. 管理业务连续性

关键会议、交付或生产受阻时，先由业务负责人选择获批替代：备用机、网页版、远程环境、其他网络或延后窗口。替代方案与根因修复分开记录，避免“暂时换设备”被写成故障解决。涉及企业数据时，替代环境也必须符合安全策略。

## 验证与完成标准

解决标准必须对应原任务：用同一应用/文件/网络/外设完成失败动作；至少重复两次；必要时重启或重连再试；确认没有引入新故障。安全类由专业人员确认可恢复使用；数据类要验证文件可读和备份；业务类要由使用者确认交付物符合要求。

结果只允许四类：“已解决”（复测通过且原因/动作可记录）、“临时绕过”（业务恢复但根因未解决）、“待复测”（现场未复现或观察期）、“升级/送修”（超出安全或权限边界）。一次未复现只能进入待复测，不能标永久解决。

## 失败分支

- 无法复现：记录频率、最近时间、环境与触发前状态，建立观察期，不连续改多项设置。
- 可逆步骤无效：确认使用了正确系统/型号条目，保存日志，再决定官方恢复或送修。
- 更新/驱动后更严重：记录版本和时间，停止叠加更新，按官方回退/支持路径处理。
- 只有更换线材/网络暂时恢复：标记临时绕过，保留原件和对照结果，不直接判设备硬件故障。
- 用户无备份却要求重装：拒绝破坏性操作，先完成可读备份或正式接受数据风险。
- 企业策略阻止操作：交 IT，不要求用户关闭防护、卸载管理或借用个人账号。
- 送修后故障仍在：沿原服务单提交相同复现证据和维修记录，不从头重复无关步骤。

## 风险升级

P0 安全风险立即停机并联系官方；P1 数据、账号、安全和关键业务风险升级组织 IT/安全/业务负责人。反复断电、无法开机且有重要数据、疑似主板/存储、恢复密钥缺失、企业加密设备、非授权拆修史或多次远程排障无效，转授权服务。任何要求拆电池、短接、刷未知固件、下载非官方镜像、公开凭据或绕过加密的建议应终止。

## 记录字段

工单编号、严重级别与判定依据、完整型号、S/N 脱敏、系统/版本、设备归属、现象、原始错误、首次/最近时间、频率、复现步骤、安全筛查、数据/备份/加密、业务影响与替代、最近变更、电源/网络/账号/应用/外设拓扑、对照组、每步原值/动作/结果、日志/截图、引用条目与 URL、结论类别、观察期、服务单、责任方和复核人。

## 分级例子、值班交接与复盘方法

### 分级不是按“用户着急程度”

P0 示例包括电池鼓包顶起外壳、冒烟/异味、进液后仍通电、适配器烧蚀或机身异常烫手；动作是停止使用和充电、在安全条件下隔离并联系官方。P1 包括唯一数据所在磁盘异常、恢复密钥缺失、账号疑似被接管、关键业务整组中断且无替代；动作是保护证据、限制进一步变化并同步数据/安全/业务负责人。P2 是影响工作但有替代且无安全数据风险；P3 是偶发、低影响或咨询类，可按计划排查。

严重级别可上调或下调，但要写原因与时间。例如最初的“无法充电”若发现外壳鼓起，应立即从 P2 上调 P0；“会议软件偶发无声”如果有备用设备且无其他异常，可先 P2/P3 记录。级别变化不能删除原判断，这有助于复盘何时出现关键信号。

### 完整案例的记录方式

不要写“USB 坏，重装后好”。应写：某完整型号、某系统版本，在某端口通过某扩展坞连接某设备时不识别；直连正常、换线正常/异常、同扩展坞接另一电脑结果；何时更新；执行哪一个官方条目；改变哪个变量后恢复；重连两次和原任务是否通过。这样下一位能判断问题在端口、线材、扩展坞、供电、驱动还是偶发，而不是重复重装。

网络、音频、显示和充电也按同一原则记录“拓扑”。拓扑包括电脑端口、线缆、转接/扩展、外设和供电；软件问题拓扑包括系统、应用、账号、网络、文件和插件。只记录末端现象会遗漏共同依赖，多设备同时异常时尤其容易误判主机。

### 值班交接

交接摘要用七项：当前级别及理由；设备和系统；原始现象和最短复现；安全/数据/业务状态；已做动作与明确排除项；当前临时绕行；下一步、负责人和截止时间。附件指向统一证据位置，不散落在个人聊天。未执行的建议与已经执行的动作分开，避免下一班误以为某项已验证。

如果等待用户、IT、软件厂商或服务中心，写清等待的具体问题，例如“请确认此证书是否适用于目标网络”，而不是“等回复”。超过约定时间按业务影响升级；没有新证据时不重复让用户执行相同高风险动作。

### 复盘关注点

复盘不只问“谁操作错了”，而要看是否过早重置、是否遗漏安全筛查、是否一次改多项、是否缺少型号/版本、是否在成功点继续操作、是否把临时绕行当修复。将可复用部分更新为提问字段或判断分支，不把某一设备的未经验证原因写成通用事实。

关闭后对日志、截图和备份按隐私规则处理：保留必要的脱敏结论与服务凭证，删除临时包含账号、客户数据或完整序列号的副本。设备返还时让用户确认外观、附件、数据和核心任务；用户未确认前，技术完成状态不等于业务关闭。
