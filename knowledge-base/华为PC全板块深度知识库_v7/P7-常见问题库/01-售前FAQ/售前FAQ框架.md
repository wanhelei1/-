# 售前 FAQ 执行框架

> 用途：把一句模糊的购机问题，转成“对象明确、事实有源、限制完整、下一步可执行”的答复。  
> 证据基准日：2026-10-17。产品页、销售配置、活动与服务政策可能变化，回答当天仍需复核官方原文。

## 适用范围

本指南用于华为笔记本售前咨询的受理、检索、答复和复核，包括型号差异、系统路线、处理器与存储、屏幕、重量、接口、续航、协同能力、软件/外设适配及购买服务。它不替代购买渠道的实时库存与合同，不替代软件厂商的兼容承诺，也不替代授权服务中心对保修的判断。

开始前先把“用户问什么”与“用户真正要完成什么”分开。例如“哪台性能好”通常还缺软件、项目规模、是否移动使用和预算边界；“能不能接显示器”还缺电脑完整型号、目标分辨率/刷新率、接口协议、线材和扩展坞。信息不全时应继续追问，不用一个系列名直接给结论。

## 判断树

```text
收到售前问题
├─ 是否能确认具体型号、销售配置、操作系统和地区？
│  ├─ 否 → 先取订单/商品页完整名称、配置、系统；只给核验方法
│  └─ 是 → 进入需求判断
├─ 问题是否涉及实时价格、库存、赠品、活动或交期？
│  ├─ 是 → 只引用带时间戳的当前渠道页面；没有快照就标“待渠道确认”
│  └─ 否 → 进入事实检索
├─ 是产品参数，还是软件/外设/服务能力？
│  ├─ 参数 → 回到 P1 对应型号事实和限定条件
│  ├─ 软件/外设 → 同时查软件或外设厂商兼容说明，并安排 POC
│  └─ 服务/政策 → 打开当前官方服务原文并按 S/N、凭证、地区核验
└─ 证据是否足以支持一句确定结论？
   ├─ 否 → 写明缺口、验证方法和责任方
   └─ 是 → 输出结论、证据、条件、限制、下一步
```

判断树的停止条件很重要：完整型号无法确认、官方来源冲突、关键软件没有厂商支持信息、企业安全要求不清、或用户要求承诺实时价格/库存时，不继续生成确定性答案。

## 步骤与追问

### 1. 建立对象身份

至少追问：设备/候选的完整产品名是什么；是哪一年或哪一代；处理器、内存、存储、屏幕与系统配置是什么；购买地区与渠道是什么；信息页面日期是什么。系列名只能用于检索，不能代替销售配置。设备在场时可交叉核对系统设备信息、机身铭牌和包装；未购买时保存商品页完整标题及 SKU 截图。

### 2. 把需求改写成任务

不要只记录“办公、设计、学习”。改写为可验证任务，例如：“同时打开 5 万行表格、20 个网页和会议客户端”“使用某软件准确版本与两个插件打开既有项目”“每天通勤并接一个 4K 显示器”“需要企业证书、VPN 和打印”。同时记录必须满足、可以妥协、明确不要三组条件。

### 3. 按证据层级检索

第一层是目标型号的华为官方产品页/规格页和 P1 产品事实；第二层是华为官方支持条目；第三层是软件、外设或服务提供方的官方说明。搜索摘要、媒体评测、电商问答和用户口碑只能形成待验证问题，不能填进官方事实栏。出现“最高、最长、可选、起始、约、仅限某系统”等词时必须连同限定条件保留。

### 4. 形成五段式答案

先给一句结论，但只覆盖已确认对象和任务；随后列证据及日期；第三段说明适用条件；第四段列限制与未确认项；最后给下一步，如补 SKU、向软件厂商确认、借机 POC、或打开服务原文。若结论是“暂不能确认”，也要说明缺什么、从哪里取得，而不是只写“咨询客服”。

### 5. 做交叉复核

把答复中的每个数字和能力反向指到来源。检查是否把另一个年份、同名不同系统或不同屏幕版本拼在一起；是否把包装附件当成机内配置；是否把“有接口”写成“支持全部协议”；是否把实验室续航写成个人保证。答复涉及企业场景时，再由 IT 核对域、证书、VPN、终端管理、加密、日志和数据策略。

### 6. 用一条示例检查答复是否闭环

假设用户问“这台能不能用于出差做报表并连接会议室屏幕”。合格记录应先写候选完整 SKU 和系统，再写真实报表规模、会议软件版本、显示器接口/目标分辨率和每天携带条件；从 P1 取屏幕、重量、接口与配置事实，从软件和显示设备厂商确认支持；最后回答“哪些已经确认、哪些需带同一份表格和线材试机、失败时回退到什么方案”。只写“轻薄、性能强、支持 Type-C”无法指导购买，也无法在出错后追溯。

可把答案交给未参与咨询的同事复述：若对方不能说出具体机型、任务、证据日期、限制和下一步，说明信息仍停留在宣传词层面，应退回补问。

## 验证与完成标准

一条合格售前答复应同时满足：对象可识别到具体销售配置；用户任务可复述；关键事实有官方 URL 或本地事实卡；系统与版本条件明确；未确认项没有被补猜；对价格/政策等动态内容有核验时间；下一步能由用户、渠道、厂商或 IT 中的明确责任方执行。

抽查时任选三项事实，从答案回到本地路径，再回到官方入口；路径断裂或原页已变化就不能标记“已确认”。对软件、外设或协同能力，用真实文件、账号、线材和设备完成一次核心任务才算场景验证；“能下载”“能插入”“能打开首页”都不等于完整可用。

## 失败分支

- 只有系列名：返回型号识别清单，不做配置推荐。
- 用户只说“越强越好”：要求给出任务、软件、移动频率、接口与预算优先级；不输出排行榜。
- 官方页与渠道页不一致：分别保存日期与页面，按当前待购 SKU 向渠道书面确认，不自行裁决。
- 软件官网未列目标系统/架构：标记“未获官方兼容确认”，安排试用或向厂商提交版本信息。
- 需要实时价格或赠品但没有当天页面：只提供核价字段，不引用历史数字。
- 用户要求“一定能用、一定续航多久”：解释测试条件与责任边界，改为可验证条件和 POC。

## 风险升级

涉及企业批量采购、关键生产软件、医疗/金融等受控数据、加密与证书、无障碍刚需、跨境服务条款或合同承诺时，升级给采购、法务、信息安全、软件厂商与华为官方共同确认。来源冲突、页面下线、型号身份无法闭合时转人工审核。任何可能诱导拆机、刷机、关闭安全策略或公开完整 S/N/账号的建议应立即停止。

## 记录字段

工单至少保存：咨询日期；用户任务；候选完整型号与 SKU；系统；处理器/内存/存储/屏幕；地区与渠道；必须软件及版本；外设型号与连接拓扑；协同设备与账号条件；动态信息核验时间；引用 URL；本地事实路径；限定词；未确认项；建议验证动作；责任方；复核人；结论有效范围。公开稿只展示完成判断所需的信息，S/N、订单号、账号和企业凭据必须脱敏。

## 售前答复质检与交接练习

### 一次咨询怎样从模糊变清楚

可用“对象—任务—边界—证据—动作”五栏现场工作表。对象栏不只写“MateBook”，而要写完整型号、系统和销售配置；任务栏写输入、动作与输出，例如“打开某版本软件中的既有工程，连接指定采集卡并导出某格式”；边界栏写预算、携带、网络、企业策略和不可接受项；证据栏逐句填官方页面、P1 卡片或厂商说明；动作栏填谁在何时补证或测试。五栏中有一栏为空，就不能把答案写成确定承诺。

### 常见错误的改写方式

- 原句“这款续航很好”应改为“官方页面在特定条件下给出某续航描述；你的会议、亮度、网络和后台任务不同，购买前需按目标配置实测”。
- 原句“Type-C 可以接所有设备”应改为“接口外形已经确认，数据、视频、供电协议及扩展坞兼容仍需按两端规格核对”。
- 原句“这个软件有网页版所以能用”应改为“网页版入口存在，但离线、插件、批量、字体、文件格式和数据上传要求尚未验证”。
- 原句“同系列选高配就行”应改为“先锁系统与必须任务，再确认这个高配 SKU 是否实际在售、是否具备目标屏幕/接口和对应附件”。
- 原句“还在保，维修免费”应改为“权益查询显示仍有期限；故障部件、原因和是否免费仍待授权服务中心检测”。

### 发布前的双人复核

第一位复核事实：每个数字、能力、版本和期限能否返回当前官方来源，限定词是否完整。第二位复核任务：答案能否指导用户下一步，是否混淆了购买渠道、软件厂商、企业 IT 和华为服务的责任。两人都要检查是否泄露 S/N、订单、账号、证书、许可证或客户文件。若作者与复核者对同一事实理解不同，将原文摘成短句并保留上下文，不通过投票决定事实。

### 交给下一位处理者的最小摘要

摘要应包含：用户要完成的真实任务；已经锁定的型号/SKU/系统；三条最关键的官方事实；两条限制或缺口；已经联系过的责任方；下一次验证所需的文件、外设、账号和时间。不要复制整段聊天让下一位自行猜重点。用户后来更换 SKU、软件版本或网络条件时，应新建版本记录并说明旧结论哪些失效，而不是在旧答复上悄悄改字。

最后做一个反证问题：“在什么条件下这条建议会失败？”若答案没有系统版本、软件、外设、配置或政策变化等边界，说明答复过度概括。售前 FAQ 的价值不是把所有问题回答成“可以买”，而是让用户知道哪些已确认、哪些仍要验证，以及验证失败后怎样避免损失。
