# 软件与兼容 FAQ｜从“能装吗”到“业务能闭环吗”

> 核心原则：下载、安装、启动、打开样例、完成真实项目和获得厂商支持，是六个不同层级。  
> 基准日：2026-10-17。软件版本、授权、插件、驱动和支持矩阵会更新，关键结论须复核软件/外设厂商当前原文。

## 适用范围

本指南用于购买前确认专业软件、办公应用、网页版服务、插件、字体、加密狗、打印机、采集卡、扩展坞、显示器、移动存储及手机/平板协同。它适用于 Windows 与鸿蒙候选的任务比较，但不把同名应用在不同系统上的功能视为相同，也不替第三方厂商承诺兼容。

兼容性不是单个“是/否”。至少包括系统/处理器架构、应用版本、授权登录、插件与驱动、文件格式、硬件加速、外设协议、企业策略、网络依赖和数据合规。任何一项是关键阻断，都可能使整套工作流不可用。

## 判断树

```text
用户问某软件或外设能否使用
├─ 能否给出准确对象？
│  ├─ 无软件版本/外设型号/电脑 SKU → 先补身份，不承诺
│  └─ 已明确 → 查两端官方支持
├─ 厂商是否明确列出目标系统、架构与版本？
│  ├─ 明确支持 → 继续核对配置、插件、授权和外设
│  ├─ 明确不支持 → 标记不适合原生工作流，讨论获批替代
│  └─ 未说明 → 记为未确认，向厂商问询或做受控 POC
├─ 是否属于关键生产任务？
│  ├─ 是 → 用真实项目、账号、插件、外设做完整验收
│  └─ 否 → 用代表性样例做功能验证
└─ 是否涉及企业数据/安全？
   ├─ 是 → IT/安全审批账号、云端、证书、驱动与外设
   └─ 否 → 仍需记录来源与失败回退
```

## 步骤与追问

### 1. 固定软件或外设身份

软件需记录完整名称、版本、发行渠道、订阅/永久/企业授权、处理器架构、插件、字体、模板、数据库、浏览器组件与许可证服务器。外设需记录品牌、完整型号、硬件版本、接口外形与协议、供电、线材、转接器、驱动/固件和目标功能。只说“PS、CAD、打印机、Type-C 扩展坞”不足以判断。

### 2. 固定电脑与系统

记录目标电脑完整型号和销售配置、操作系统与版本、处理器、内存、存储、图形能力、接口协议和企业管理状态。相同系列不同年份或不同系统可能使用不同驱动与能力。USB-C 外形相同也不等于都支持充电、显示与同一数据速率；必须回到对应型号规格和外设要求。

### 3. 对照厂商原文

优先查软件或外设厂商的系统要求、兼容列表、驱动下载、已知问题和支持生命周期，再对照华为产品/支持资料。官网未列目标系统时不能因为“网上有人装过”写成支持；“有网页版”也要核对离线、插件、快捷键、文件格式、硬件加速、批量处理和数据上传限制。

### 4. 设计分层 POC

第一级验证安装与授权；第二级打开真实文件并保持格式；第三级执行核心动作，如编译、渲染、打印、采集或外接显示；第四级验证导出物能被上下游打开；第五级在目标网络、账号、VPN、安全策略和外设拓扑下连续运行。为每一级设置通过条件和失败截图，不在失败后临时换版本掩盖问题。

### 5. 协同能力专项追问

涉及手机/平板时，记录双方设备型号、系统版本、账号归属、网络/蓝牙/近场条件、文件类型、是否允许云端和组织策略。功能名称相似不代表支持矩阵相同。要验证真实任务，例如导入 30 张照片、跨设备粘贴一段含格式文本或共享窗口，而不是只看到设备图标就判定成功。

### 6. 外设专项追问

画出“电脑端口—线材—转接器/扩展坞—外设—电源”的连接图。用原装或规格明确的线材，先单设备直连，再逐步加入转接和其他外设。打印、采集、音频和加密狗需确认厂商驱动是否支持目标系统；企业环境不得为测试关闭终端防护或安装未知来源驱动。

若用户同时依赖多个对象，建立依赖顺序而不是分别问“能不能”：先验证软件和授权，再验证项目文件，再接加密狗/采集卡，最后加入扩展坞、显示器和企业网络。前一层失败时暂停后一层，可明确阻断来自哪里。测试结束保存成功拓扑和线缆规格，避免换会议室或换一根线后把旧结论继续套用。

## 验证与完成标准

软件完成标准不是“打开了”：应使用目标账号打开真实项目，执行关键编辑/计算，调用必要插件与外设，保存并导出，再由另一台已知正常设备核对结果；重启后授权和配置仍可用。外设应在目标端口和供电下完成实际功能，重连后仍识别，且不破坏其他设备。协同应记录支持设备、版本、账号、网络、传输方向、文件大小/类型和结果校验。

输出结论分为“厂商明确支持且 POC 通过”“厂商明确支持但本环境待测”“厂商未给支持结论，POC 仅证明本次可用”“明确不支持或核心任务失败”。不得把第三类写成长期兼容承诺。

## 失败分支

- 能下载但不能安装：保存原始提示，核对系统/架构、权限、存储和安装包来源，不关闭安全策略绕过。
- 能安装但不能授权：核对许可类型、账号、时间、网络、许可证服务器和设备数量，交软件供应商处理。
- 能打开但项目缺功能：检查版本、插件、字体、编解码器、GPU/驱动和文件依赖，避免用空白样例替代真实项目。
- 外设不识别：先直连、换已知正常线缆/端口/供电，再查厂商驱动；不要连续安装多个未知驱动。
- 网页版可用但业务不闭环：把离线、批量、插件、格式和数据合规缺口列出，交业务决定是否接受替代。
- 一台手机能协同、另一台不能：按双方具体型号和系统版本分别记录，不外推到整个品牌或系统。

## 风险升级

关键生产软件、财务/医疗/工业外设、USB 加密狗、内核驱动、虚拟化、数据库客户端、企业证书、涉密或受监管数据必须升级给软件/外设厂商与组织 IT。测试若要求关闭防护、修改固件、安装非官方镜像或上传敏感文件，立即停止。替代方案涉及远程桌面、云端处理或兼容层时，由安全与业务共同接受数据路径、时延、功能缺口和支持责任。

## 记录字段

电脑型号/SKU、系统与版本、处理器架构、内存/存储/图形、软件名称/版本/来源、授权类型、插件/字体/模板、真实项目摘要、外设型号/固件/供电、端口与线缆拓扑、账号/网络/VPN、厂商支持 URL 与日期、每级 POC 结果、原始错误、日志位置、替代路径、风险审批、复核人和结论有效范围。凭据、许可证密钥、完整账号和企业文件不得写入公开记录。

## 兼容性 POC 工作表

### 测试包的组成

准备一份不含敏感信息、但能代表真实难度的测试包：主项目或等比例样例、关联字体和插件、输入素材、目标导出格式、外设、许可证测试账号、失败时可对照的已知正常设备。记录每个文件的版本和必要时的校验值。不能用空白新建文件代替含复杂图层、宏、引用、编码、模型或数据库连接的真实项目，因为它只证明程序能启动。

测试环境表要写电脑 SKU、系统/补丁、应用/插件/驱动、网络、账号、外设固件、线材和供电。若比较两个系统，允许各自采用官方推荐路径，但输入和验收结果保持一致；不能一侧用原生客户端、另一侧只看网页首页后宣布等价。计时可以作为本轮观察，却不能在没有多轮控制条件时发布成普遍性能结论。

### 五段验收

第一段“取得”：从官方渠道找到适用版本并核对签名/发布者。第二段“授权”：登录、许可证、企业服务器或加密狗在目标网络下生效。第三段“编辑”：打开真实项目，使用必须工具、插件、字体、快捷键和硬件加速。第四段“交付”：按指定格式导出，另一台已知正常设备能打开，内容、布局和数据无损。第五段“持续”：重启、断网/恢复、连接外设并完成一段连续工作，确认设置和授权保持。

每段只给通过、条件通过、失败或未测。条件通过必须写绕行方案及代价，例如只能通过网页、不能离线、缺插件、需远程环境或文件要转换；由业务和安全负责人接受后才可作为候选。未测绝不能换成“应该可以”。

### 外设兼容的对照矩阵

至少做四格：目标外设直连目标端口；同外设换已知正常线缆；目标线缆接已知正常外设；加入扩展坞后的完整拓扑。记录供电是否独立、端口协议、显示信号、数据速率和是否同时连接其他设备。只有加入扩展坞后失败，不能直接判电脑或外设不兼容；要把扩展坞、供电和带宽作为共同依赖。

### 结论写法

“厂商明确支持 + 本场景 POC 通过”可以说明在记录环境下完成任务；“厂商未列支持但本轮可运行”只能作为临时风险记录；“通过兼容层/远程运行”必须标明不是原生路径；“未获许可或无法访问真实项目”应写未测。结论附日期和版本，应用、系统、插件、驱动或组织策略变化后自动进入复核。

测试材料交接时删除许可证密钥、个人账号和客户数据，只保留脱敏样例、错误、配置和输出。若无法制作合规样例，应由组织 IT 在受控环境执行，知识库只记录结论范围与证据位置，不复制敏感日志。
