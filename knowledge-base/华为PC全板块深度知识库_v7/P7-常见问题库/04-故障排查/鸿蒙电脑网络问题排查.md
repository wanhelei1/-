# 鸿蒙电脑网络问题排查｜先分“全局断网”与“部分应用断网”

> 适用系统：官方本地条目记录为 HarmonyOS 5.0 及以上；实际版本与界面须在设备和当前官方原文中复核。  
> 安全边界：不为排障关闭企业防火墙、绕过证书或修改未获授权的路由/上网策略。

## 适用范围

用于鸿蒙电脑连接普通、隐藏、校园或企业无线网络，以及“已连接但无法访问”“只有部分应用无法联网”“公司网络需要证书”“访问 NAS/网络邻居失败”等场景的初步隔离。它不替网络管理员修改接入策略，不把切换热点成功自动解释为电脑正常，也不提供未知证书或代理的安装方式。

网络问题至少分终端、无线接入点/路由器、上游网络、认证/证书、名称解析、IPv4/IPv6、应用权限或应用服务端。一次测试只能缩小范围，不能在证据不足时确定责任方。

## 判断树

```text
网络异常
├─ WLAN 图标/开关是否可见，能否看到目标网络？
│  ├─ 都不可见 → 核对设备/系统与官方无线条目，必要时转服务
│  ├─ 看不到一个 SSID → 判断隐藏、频段、距离或接入点状态
│  └─ 能看到 → 继续认证
├─ 能否连接并获得“已连接”状态？
│  ├─ 不能 → 区分密码、隐藏网、企业证书/认证和路由器限制
│  └─ 能 → 继续访问测试
├─ 是所有应用失败还是部分应用失败？
│  ├─ 所有应用 → 比较手机热点、同网其他设备和基础网页/内网
│  ├─ 部分应用 → 查应用权限、坚盾守护、路由/防火墙、IPv6支持
│  └─ 只某资源 → 查 DNS、代理、证书、服务端或组织策略
├─ 换已知正常手机热点是否恢复？
│  ├─ 恢复 → 当前网络/认证/策略方向，交网络管理员核对
│  └─ 不恢复 → 终端或应用方向，继续官方条目
└─ 涉及企业证书、校园认证或 NAS？
   ├─ 是 → 只按管理员材料与官方原文，禁止自行降级安全
   └─ 否 → 完成重连和真实任务验证
```

## 步骤与追问

### 1. 采集基线

记录电脑完整型号、HarmonyOS 版本、问题开始时间、是否更新过系统/应用、目标网络类型、SSID 脱敏名、信号位置、是否首次连接、错误全文、所有还是部分应用、同网其他设备、换热点结果。企业/校园网还要记录认证方式、是否需网页门户、用户证书/密码由谁提供、IT 联系人；不在工单保存证书密码。

### 2. 先观察，不先重置

确认无线功能状态、是否能看到目标网络、是否显示已连接、设备时间是否合理。保存正在编辑的文件，关闭会产生大量同步的非必要任务。不要一上来重置网络、删除全部已知网络或重启路由器，因为这会破坏现场并影响他人；先建立同网其他设备和手机热点两个对照。

### 3. 区分发现、认证与访问

看不到 SSID 时，确认是否隐藏、距离和接入点是否正常；隐藏网络用对应官方条目，名称和安全类型必须由网络所有者提供。能看到但连接失败时，重新核对凭据与认证材料，不反复猜密码触发锁定。显示已连接但不能访问时，用一个允许访问的基础网页/内网目标判断，再区分所有资源或某一域名/服务。

### 4. 用手机热点做受控对照

在政策允许且不传输敏感数据时，用已知正常的手机热点测试同一应用和同一公开资源。热点恢复说明当前网络环境、认证、路由或策略值得排查；热点也失败则保留终端/应用方向。热点测试只改变网络变量，不同时更新应用、修改权限和重启路由器。

### 5. 处理“部分应用无法上网”

先验证其他应用确实能访问，再列出受影响应用和版本。根据本地官方摘要，需关注路由器/网络防火墙限制；现有短条目也提示核对坚盾守护模式和应用对 IPv6 的支持。具体权限、坚盾守护、IPv6 或网络菜单路径若本卡没有完整保留，必须打开官方原文，不凭记忆关闭保护。企业网络限制应由 IT 在策略侧核对。

### 6. 处理企业/校园网络

问清是否需要证书、用户名域、代理、网页认证、设备登记或特定时间/位置。用户证书应由企业 IT 提供，文件格式、密码、有效期和网络配置按官方证书条目与组织流程执行；不从聊天附件或搜索站点下载证书。校园门户打不开时记录跳转、浏览器和网络状态，交学校网络支持确认账号/设备限制。

### 7. 处理 NAS 与网络邻居

先确认基础网络、目标地址、同一网络/路由可达、共享协议和账号授权；用已知正常设备访问同一资源做对照。不要为访问共享而关闭整个防火墙、开放匿名共享或把企业凭据交给非管理员。具体设置按鸿蒙网络邻居官方条目与 NAS 厂商当前说明。

## 验证与完成标准

普通联网成功应满足：目标网络连接状态正常；重连后仍可用；至少一个基础资源和用户真实任务完成；其他应用未受影响。部分应用修复要在原网络和原应用完成登录/同步/下载等真实动作，并复测一个原本正常应用。企业网络还需访问获授权内网资源并符合证书/策略；热点可用只能作为定位证据，不是企业网络修复结果。

至少记录一组对照：同机换网络、同网换设备、或同应用换公开样例。修改过的权限/网络设置应有原值和回退方法。成功后停止继续更改，避免“顺手优化”引入新问题。

## 失败分支

- WLAN 入口或设备信息与官方条目不符：核对系统版本与产品，打开当前原文；不要套 Windows 菜单。
- 目标网络看不到但其他设备可见：记录位置、频段/隐藏信息，联系网络所有者和官方支持，不猜安全类型。
- 热点可用、企业网不可用：将证书/认证/代理/防火墙证据交 IT，不关闭保护绕过。
- 所有网络都失败：保存系统/网络状态，按官方通用连接条目继续；高风险重置前确认影响。
- 只有一个应用失败：转部分应用分支并提交应用反馈；不要重装整个系统。
- 证书过期或密码不明：由 IT 重新提供，客服不收集、不生成。
- 问题偶发：记录时间、位置、SSID 脱敏、受影响应用与频率，避免把一次恢复写成永久解决。

## 风险升级

企业证书、VPN、代理、网络准入、客户数据、疑似账号劫持或广泛业务中断立即升级组织 IT/安全。安装未知证书、要求关闭防火墙/坚盾守护、修改路由器影响他人、公开网络抓包含敏感数据等操作应停止。设备在多条已知正常网络均无法连接且基础入口异常时升级华为官方服务。

## 记录字段

设备型号、系统/版本、时间、目标网络类型、SSID 脱敏、信号位置、是否首次连接、发现/认证/访问阶段、错误全文、所有/部分应用、应用版本、基础网页/内网结果、同网其他设备、手机热点对照、IPv4/IPv6线索、权限/坚盾守护、证书/门户/代理是否涉及、已改设置与原值、官方条目/URL、IT 服务单、验证和观察期。

## 网络对照矩阵与变更回退表

### 二乘三对照

准备两台设备（问题电脑与已知正常设备）和三种条件（目标网络、允许的手机热点、另一个已知正常网络）。每格只做获授权的相同任务：连接、访问一个基础资源、再完成受影响应用的实际联网动作。结果可以帮助区分“只这台设备”“只这个网络”“只这个应用组合”或“服务端普遍异常”。没有第二台设备时至少保留同机换网络，但结论相应降低。

对照过程中保持账号、应用版本和样例一致；不要同时升级应用或清除数据。企业网络禁止把真实客户数据带到个人热点，热点只访问公开样例。测试完成后删除热点凭据和临时样例，恢复组织要求的网络。每格记录时间，因为门户会话、令牌、服务端故障或网络高峰可能改变结果。

### 连接阶段记录

发现阶段记录是否能看到 SSID、是否隐藏、信号位置和同网其他设备；认证阶段记录密码/证书/门户由谁提供及错误全文，不保存密码；地址与访问阶段记录是否显示已连接、基础网页/内网、域名和 IP 类目标的差异；应用阶段记录只有哪些应用失败、账号和 IPv6/代理/权限线索。把阶段分开可避免“显示已连接”被误认为互联网和业务均可用。

### 变更与回退

建立三列表：原值、改动、结果/回退。忘记单个网络、调整某应用权限或按管理员要求更新证书，都要能恢复。网络重置、删除全部网络、修改 DNS/代理、关闭安全组件和重启共享路由器属于影响较大的动作，只有对应官方原文/管理员授权、备份现有配置并安排维护窗口后才执行。成功点出现时停止，不继续叠加“优化”。

### 校园与企业网补充问卷

询问接入是个人账号、设备登记还是证书；是否有网页登录、有效期、多设备上限、指定浏览器、代理、VPN、内网 DNS 或时间同步；问题是否只在某建筑/接入点/时间；同部门其他设备是否受影响。将这些字段交网络管理员，比让用户反复输入密码更有效。管理员给出的证书和配置要核对来源、有效期和目标网络。

### 服务端与账号分支

若同一应用在多台设备、多个网络同时失败，查应用官方状态和账号状态，不继续改电脑网络。若只有一个账号失败，用获授权测试账号对照并联系应用方；不让用户共享个人密码。若基础网页和其他应用均正常，网络层可能只提供背景条件，反馈重点应转应用错误、权限、域名或服务端。

### 关闭与观察

修复后至少重连一次，并在原位置/原网络完成真实任务；企业网还要在组织允许的重启或重新认证后复核。记录最终有效动作和原理层级，不只写“重启好了”。偶发断网设置观察期，记录断开时间、接入点、信号、前台应用与恢复方式；达到阈值后带数据升级，而不是持续修改设备。
