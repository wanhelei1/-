# 系统安装与恢复安全说明｜先保护数据，再选最小破坏路径

> 高风险提示：恢复出厂、重装、分区、格式化、启动项修改和加密处理可能造成不可逆数据丢失或业务中断。  
> 本指南只给决策与安全检查；具体菜单、键位、支持型号和顺序必须在执行当天打开对应官方原文。

## 适用范围

适用于华为 Windows 或鸿蒙电脑出现系统更新失败、启动异常、密码/BitLocker 提示、准备转让、从 Windows 迁移到鸿蒙、希望恢复出厂或重新安装系统时的前置判断。它不提供绕过密码、企业管理或磁盘加密的方法，不把 F10 恢复套到所有型号/系统，也不保证任何恢复操作保留本地文件。

先区分目标：修复单一应用、解决系统故障、清除个人数据、迁移到新机、恢复官方初始状态、还是安装组织镜像。目标不同，风险和路径不同。若电脑仍能进入系统，应优先完成备份与低风险排障；“重装试试”不能作为首个动作。

## 判断树

```text
用户提出重装/恢复
├─ 是否有冒烟、异味、鼓包、进液、磁盘异响或反复掉电？
│  ├─ 是 → 停机，禁止恢复/写盘，联系官方并评估数据
│  └─ 否 → 继续
├─ 数据是否已备份且抽样可读？
│  ├─ 否 → 不执行清除/格式化；先备份或评估数据恢复
│  └─ 是 → 记录备份位置与校验
├─ 是否掌握账号、磁盘恢复密钥、授权与企业许可？
│  ├─ 否 → 停止；由设备所有者/IT找回，不绕过
│  └─ 是 → 继续
├─ 问题能否用可逆修复解决？
│  ├─ 单应用/驱动/网络/更新 → 先走对应官方条目
│  └─ 系统严重损坏/交机清除/官方建议 → 评估恢复路径
├─ 当前系统和型号是否明确支持所选路径？
│  ├─ 否 → 打开官方原文或联系服务中心
│  └─ 是 → 按原文执行并保持稳定电源
└─ 恢复后能否完成基础验收？
   ├─ 否 → 保留报错，不反复重装，转官方服务
   └─ 是 → 恢复数据/应用并形成记录
```

## 步骤与追问

### 1. 建立设备与授权基线

记录完整型号、S/N 脱敏值、当前系统与版本、是否 Windows/Linux/鸿蒙、磁盘数量和分区、设备归属、是否受企业管理。询问谁授权操作、能否进入系统、当前提示全文、首次出现时间、最近更新/分区/驱动变化。企业电脑必须先获得 IT 批准，确认镜像、证书、VPN、加密、资产管理和日志保留要求。

### 2. 做可验证备份

备份桌面、文档、下载、邮件/聊天数据、浏览器资料、应用工程、数据库、虚拟机、字体/模板、许可证信息和外置设备配置。至少选择若干不同类型文件在另一设备或恢复环境中打开；仅看到文件名不算可用。记录备份介质、时间、容量、抽样结果和是否加密。云同步图标也不等于所有本地文件已上传。

### 3. 保护账号、密钥与授权

确认系统账号恢复方式、BitLocker 或其他磁盘加密恢复密钥、企业证书、双因素设备、软件许可证和加密文件口令由授权持有人掌握。密钥不发到公开聊天，不写进普通工单。看到磁盘锁定或恢复密钥提示时，不格式化“解锁”；先核对设备身份、账号和官方 BitLocker 条目，无法取得密钥则停止。

### 4. 优先低风险路径

单应用失败先修应用；单个设备异常先查官方驱动与硬件；网络问题先做网络隔离；系统更新失败按错误码和官方更新条目；忘记密码按账号类型走官方找回。只有这些路径不能解决、用户明确要求清除、或官方诊断建议时，才讨论恢复出厂或重装。不要为了排除一个小故障同时更新 BIOS、驱动、系统并重置设置。

### 5. 选择与系统匹配的官方路径

Windows F10 恢复仅在目标机型、当前系统与官方页面适用时使用；支持范围、前置条件、数据影响和操作步骤须打开 F10 官方原文核对。官方驱动从具体型号支持页或华为官方工具获取。鸿蒙电脑恢复、迁移或数据克隆使用鸿蒙对应官方条目，不能照搬 Windows 键位。组织镜像、双系统、Linux 或改分区设备须由 IT/官方判断，避免破坏恢复分区或加密状态。

### 6. 执行时保持可控

连接稳定电源，断开非必要外设，记录开始前电量、磁盘和报错；不在雷雨、供电不稳、业务高峰或远程无人看守时执行。严格逐项按当前官方原文，不添加网上命令。界面、警告、磁盘数量、分区或目标名称与原文不一致时立即停止并拍照记录，不能凭位置猜按钮。

### 7. 恢复后的最小重建

先确认系统能正常启动、设备身份与磁盘符合预期、网络和基础输入/显示可用，再按官方顺序完成更新与驱动。只安装来源明确的必要应用；验证账号、时间、加密、VPN、打印和关键外设。数据分批恢复，先扫描并核对校验/文件打开，再恢复生产任务。不要一次导入全部旧配置后再排错。

## 验证与完成标准

操作前通过标准：授权明确；备份有抽样可读证据；恢复密钥和账号可用；应用/驱动来源已记录；目标官方路径明确；电源和时间窗口满足；用户理解数据影响。任一项不满足就不开始高风险步骤。

操作后通过标准：连续两次正常启动；系统版本和设备信息可记录；磁盘/分区结果符合授权目标；网络、键盘/触控板、显示、音频和充电基础功能可用；关键账号、VPN、软件与文件完成抽样；加密策略恢复；无未知设备或持续报错；工单保留使用的官方页面与结果。

## 失败分支

- 恢复入口与官方原文不一致：停止，不试按键组合；核对型号/系统并联系官方。
- 备份介质打不开：不清除源盘，先修复备份或评估专业数据恢复。
- BitLocker/磁盘锁定：不格式化、不猜密钥，按账号/IT/官方流程找回。
- 恢复中断或循环重启：保持错误现场和稳定电源，记录阶段与提示，转官方；不反复写盘。
- 恢复后设备缺失：使用对应型号官方驱动路径，逐项安装和验证，不用驱动聚合站。
- 企业应用无法恢复：交 IT 按镜像、证书、许可和安全策略重建，不绕过管理。
- 用户只是要转让设备：先确认数据备份、账号解绑、加密与清除要求，再按当前官方转让/恢复流程；不要只删文件。

## 风险升级

磁盘有物理异常、数据唯一且重要、加密密钥缺失、设备所有权不清、疑似恶意软件、企业受控设备、恢复入口异常或多次失败，应停止并升级官方服务、组织 IT/安全或合规数据恢复。任何要求绕过账号/加密、下载未知镜像、关闭安全启动、刷写固件或删除恢复分区的方案不在本指南授权范围。

## 记录字段

完整型号、S/N 脱敏、系统/版本、设备归属与授权、故障/目标、报错全文、能否启动、磁盘/分区、加密与恢复密钥状态、账号恢复、备份位置/时间/容量/抽样、应用与许可证、企业策略、选定官方条目/URL/日期、执行前状态、每步结果、停止点、恢复后验收、数据恢复、失败证据、升级对象和复核人。

## 高风险操作的放行单与恢复包

### 放行前十项

执行人应逐项回答：设备所有者是否书面授权；完整型号和系统是否确认；官方路径是否明确适用；重要数据是否有至少一份独立且抽样可读的副本；磁盘加密与恢复密钥是否掌握；系统/应用账号能否恢复；企业镜像、证书与管理策略是否由 IT 确认；驱动和安装介质是否来自官方或组织批准来源；稳定电源和足够时间是否具备；失败后由谁接管。十项中任一项回答“不知道”，默认不放行。

备份还应包含“不能直接复制”的内容清单，例如邮件本地库、数据库、虚拟机、浏览器配置、许可证、加密容器、字体模板、聊天记录或同步未完成文件。对每类写恢复方法和抽样证据。备份介质保持与待恢复设备隔离，避免误选目标磁盘；如果使用云端，确认同步完成、版本可回退和账号可登录。

### 制作恢复包

恢复包分为身份、安装和验收三部分。身份部分保存型号、系统、S/N 脱敏、分区示意与授权；安装部分保存官方页面、批准的镜像/驱动来源、网络/证书/VPN 信息和软件清单；验收部分保存代表性文件、外设、业务脚本和通过标准。恢复密钥、账号密码和许可证密钥放在组织批准的安全保管处，只在包中写保管责任人，不写明文。

### 变更窗口纪律

开始前通知受影响人员并冻结新数据写入，记录准确时间。操作过程中每遇到警告、磁盘选择、版本差异或意外重启都拍摄脱敏证据；不要因为已经花了时间就继续。远程指导必须有现场人员观察电源和界面，高风险阶段不能只依赖断线后不可见的远控。

如果操作中发现磁盘容量、分区数量、系统名称或恢复入口与放行单不一致，立即进入暂停状态。由第二人对照设备身份与官方原文，确认后才能继续；禁止根据磁盘排列位置猜目标。这个“双人确认点”应出现在清除数据、格式化、恢复初始状态和导入企业镜像之前。

### 恢复后的分阶段回迁

第一阶段只恢复系统与官方驱动，建立干净基线；第二阶段恢复安全、账号、加密、网络和企业策略；第三阶段安装关键应用并用脱敏样例验证；第四阶段分批回迁用户数据；最后才恢复低优先级个性化设置。每阶段完成一次快照/记录，若故障复发即可定位到引入它的阶段，而不是再次全盘重装。

回迁数据要核对数量、随机抽样打开和必要校验，应用要核对版本、授权与输出，外设要核对原拓扑。旧备份不能在一次开机成功后立即销毁，应按照用户或组织保留规则等待验收；同时避免无限期保留含个人数据的临时副本。

### 关闭条件

设备连续启动、系统和驱动无异常、核心业务与外设通过、账号与加密恢复、数据抽样无误、用户/IT 签字后才能关闭。若只有系统能进入但关键业务未恢复，状态是“基础系统恢复完成，业务重建进行中”，不能写“全部修复”。所有失败和绕行也进入最终记录，供下次更新或恢复判断。
