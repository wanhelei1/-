# 导入 ima 共享知识库说明

## 一、加入举办方提供的共享知识库

1. 使用准备参赛和运行智能体的 ima 账号登录。
2. 打开举办方发出的共享链接，或在 ima 中扫描知识码。
3. 按页面提示确认加入；如知识库需要管理员审核，等待审核通过后再继续配置。
4. 回到同一账号的知识库列表，确认共享库名称、创建方和可见状态。
5. 用一个库内明确存在的词做测试检索，并打开命中的原文，确认不是只看到了链接预览。

界面名称可能随客户端版本调整，但判断是否真正加入的标准不变：该共享库应出现在本人账号可选择的知识来源中，并能检索到库内内容。不要仅以“打开过分享页”作为加入成功的依据。

## 二、调用自己账号下的共享知识库

### 在 ima 页面或智能体中使用

登录已加入共享库的同一账号，在知识库问答、智能体或知识来源设置中选择该共享库。首次配置后，分别测试“型号事实”“官方支持”“场景问题”和“软文案例”四类查询，确认回答能够回溯到库内文件。

### 通过公开接口或 ima skill 使用

1. 在 [ima 官方智能体接口页面](https://ima.qq.com/agent-interface)为当前账号获取有效配置。
2. 在本机或部署环境中完成 skill 安装与配置，凭证只保存在平台建议的安全配置位置。
3. 获取当前账号可访问的知识库列表，按名称或平台返回的唯一标识选择举办方共享库。
4. 先做只读检索，确认返回的知识库、文件标题和引用来源正确，再接入自研智能体的检索流程。
5. 对接口错误分别记录认证失败、知识库不可见、检索无结果和内容解析失败，不把所有异常都归为“知识库没有内容”。

API 密钥、Client ID、登录信息和知识库内部标识不得写进 GitHub、魔搭、作品说明书、截图、日志或本知识库。若凭证曾在公开场所出现，应立即作废并重新获取。

## 三、推荐上传顺序

本库体量较大，建议按板块分批上传，每批完成后先做抽查再进入下一批。

1. **治理规则**：先上传 `00-建库规范`、`全库导航.md` 和根目录 README，让智能体理解事实分级、命名、审核、版权和拒答边界。
2. **事实底座**：上传 `P1-产品参数库` 与 `P7-常见问题库`。P1/08 公开价格快照应与产品事实一起上传，让智能体能区分“页面价、参考价、条件价、下架、缺货与询价”。
3. **场景与话术**：上传 `P8-客户场景库`、`P2-卖点话术库`，测试能否先追问场景、再给条件化建议。
4. **培训**：上传 `P5-培训赋能库`，检查讲义、演练、测验和答案是否能分别检索。
5. **营销内容**：上传 `P6-营销素材库`。其中 `11-完整软文成稿库`、`12-华为官方传播案例研究`、`13-多平台公开案例研究`建议分成三批，避免上传失败后难以定位。
6. **竞品**：单独上传 `P3-竞品资料库`并设置更短的复核周期，因为品牌页面和在售系列会变化。
7. **受控资料**：`P4-价格政策库（机密）`只在确认共享范围、访问权限和审批规则后上传；当前公开包只有字段与流程模板，不含真实内部价格政策。

`90-待审核`和`99-历史归档`用于流程管理。若 ima 会把所有上传内容都参与回答，应谨慎上传历史归档，并在系统提示词中明确它不能覆盖现行事实。

## 四、文件与目录处理

- 解压后保留顶层板块和中文文件名，不把全部文件平铺到一个目录。
- Markdown、CSV 与图片应按相邻目录成组上传；图片必须与对应 `图片索引.csv` 一起保留。
- 若平台不保留文件夹，可在文件名前补充板块前缀，或按板块建立多个上传批次；不要修改图片基础名称，否则索引引用会失效。
- CSV 使用 UTF-8 编码；若导入后中文乱码，先停止继续上传并修正编码。
- 对单次失败的文件单独重传，不重复上传整批，以免产生多个同名版本。
- 记录每批的上传时间、成功数量、失败文件、重传结果和抽查结论。

## 五、上传后的检索验收

### 事实类

- 查询一个重点型号的屏幕、系统和接口，确认回答指出具体版本及官方来源。
- 查询同系列两个容易混淆的型号，确认没有把参数交叉继承。
- 查询一张图片，确认能返回图片名称、来源、适用型号和用途，而不是只凭文件名猜测。
- 查询一个在售消费型号的不同配置价格，确认回答同时给出配置、价格类型、核验时间、条件和官方 URL；再查询一个商用品，确认无公开金额时不会猜价。

### 支持类

- 查询一个 Windows 问题和一个鸿蒙电脑问题，确认回答先核对适用系统，再给步骤和失败分支。
- 故意输入信息不足的问题，确认智能体会追问或标记待核验，不会补写不存在的菜单或按键。

### 场景类

- 输入一个企业或行业需求，确认回答先问应用、版本、账号、网络、外设和管理要求。
- 检查输出是否包含候选范围、试点方法、验收和限制，而不是只列产品形容词。

### 营销类

- 分别要求公众号、小红书、知乎、短视频和门店长图，检查结构、篇幅、图文节奏和 CTA 是否真正不同。
- 要求引用图片时，检查路径是否存在于 P1 图片索引。
- 要求加入价格、排名或客户评价但不给来源，确认智能体拒绝编造并提示需要当期授权证据。

## 六、建议的自研智能体检索流程

1. 识别平台、受众、业务场景、目标型号和交付格式；缺一项时先追问。
2. 从 P1/P7 取得事实与支持证据；价格查询定向进入 P1/08，不直接从案例、软文或相近型号推断金额。
3. 从 P8 取得业务问题和验收方法，从 P2 取得角色化表达。
4. 从 P6 选择相同平台的指南、完整成稿和案例研究，重新组织原创内容。
5. 价格输出必须绑定具体 SKU、口径、核验时间、条件和官方 URL；页面价不能自动减券，历史参考价不能冒充当前价。
6. 对每张图输出图片名称、来源、插入位置与说明；图片事实不得超出索引。
7. 输出前执行版本、来源、动态信息、版权、客户授权和禁用表达检查。

## 七、更新与安全

- 产品、系统、服务、竞品与商城页面变化后重新核验来源日期。
- 价格、库存、补贴、赠品、交期和内部政策必须设置生效与失效日期。
- 客户数据、账号、证书、合同、真实业务截图和未授权案例不得进入共享知识库。
- 第三方软文案例只用于结构研究；不得复制正文、图片、视频、版式或人物素材。
- 每次大批更新后重新生成 `公开来源总表.csv`、`全库统计与校验报告.md`和 SHA256 文件清单，再上传新版本。
