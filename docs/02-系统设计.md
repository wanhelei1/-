# 02 · 系统设计

## 1. 总体架构

纯 Python 标准库实现（Python ≥ 3.10），无第三方依赖、无网络依赖：

```text
浏览器 index.html（接待/问答/跟进工作台，移动端适配）
        │  HTTP（本地 127.0.0.1:7860 / 托管 0.0.0.0:7860）
        ▼
app.py（标准库 HTTP 服务：路由 / 参数校验 / 静态资源）
        │
        ▼
store_growth_workflow.py（五段流水线装配，模块间不互相复制代码）
  ① customer_insight_agent/kb_agent.py    客户洞察：身份/场景/需求/顾虑优先级/触发点/
  │                                       渠道/顾客原话；缺失项标记「待追问」
  ② 3号(1)/recommendation_engine.py +     需求推荐：明确输入 → 离线检索 + 硬条件评估，
  │  retrieval_adapter.py + mock_retriever.py   未知项不当作满足
  ③ pricing_module.py                     价格核验：只展示带核验日期的官方快照，
  │                                       不能安全展示的金额直接过滤
  ④ marketing_content_module.py           营销草稿：P2/P6 话术 + P1 型号图片来源，
  │                                       输出可审阅草稿
  ⑤ BLOCK-07/block07_compliance.py        合规检查：事实/图片来源、风险词、
                                          人工确认项；未通过仍只输出待审草稿
        │
        ▼
knowledge-base/华为PC全板块深度知识库_v7/（本地事实源，随包分发）
```

## 2. 接口与数据流

- `POST /api/insight`：单独生成洞察卡。
- `POST /api/workflow`：完整串联五段。必填 `customer_task`/`need`；可选 `personas`、`scenes`、`needs`、`concerns`、`priority_concern`、`triggers`、`channels`、`customer_words`。指定 `product` 时价格与营销针对该型号；未指定时仅在推荐阶段有明确证据支持的候选时自动带入首个候选。
- 其余路由：目录、接待、知识问答、跟进计划（`/api/followups/*`）。跟进计划数据仅存使用者浏览器 localStorage，不落服务器。

### 七步业务字段与当前实现边界

七步业务框架与上述五段程序流水线不同；第 5 步自动生成个性化演示脚本尚未实现。

| 步骤 | 输出字段 | 当前实现与边界 |
|---|---|---|
| 1. 客户洞察卡 | 客户身份、使用场景、核心需求、最大顾虑、购买触发点、沟通策略、依据 | 已实现；明确输入之外的信息保留为待追问。 |
| 2. 推荐方案 | 推荐产品、推荐理由、关键产品事实、适配程度、来源 | 已实现推荐/检索适配；默认 Mock 精选检索，未知硬条件不视为通过。 |
| 3. 价格与报价状态 | 具体配置、公开价格、价格口径、基准日期、来源、待人工核验项 | 已实现官方公开快照；非实时成交报价，动态条件须人工核验。 |
| 4. 营销内容 | 平台、内容策略、标题、正文、行动引导、推荐图片与来源 | 已实现草稿；发布前复核事实来源和图片授权。 |
| 5. 3 分钟演示脚本 | 开场、需求确认、产品演示、异议处理、收口 | 自动生成未实现；相关方法资料可由知识库检索。 |
| 6. 成交跟进 | 今天、第 1 天、第 3 天、第 7 天 | 已实现四节点计划；网页端留在当前浏览器，不自动联系顾客。 |
| 7. 依据与合规 | 已引用来源、检测到的风险、待人工确认项 | 已实现规则检查；扫描结果不能替代人工审查。 |

## 4. 可靠性设计（无 Key / 无网 / 断网三套兜底）

- **无 Key**：系统本就不依赖任何 API；`os.environ` 仅作预留（见 `.env.example`），不配置同样完整运行。
- **无外网**：检索、生成、核验全部本地完成。
- **网络全断**：`index.html` 兼作离线演示页；本地 `py -3 app.py` 即可完整演示。

## 5. 部署

- 魔搭 **Docker 创空间**：`python:3.12-slim`，`COPY knowledge-base/ ./knowledge-base/`，监听 `0.0.0.0:7860`；部署日志确认监听后，控制台把可见性改为**公开**，无痕窗口验证。
- GitHub 仓库内容与公开部署包一致，逐文件校验（`bundle-manifest.json`）。
