# 02 · 系统设计

## 1. 总体架构

项目使用 Python 标准库实现，Python >= 3.10，无第三方依赖、无外部网络依赖。根目录保留启动入口，业务实现按职责放在 `modules/`。

```text
浏览器 index.html（接待 / 问答 / 跟进工作台）
        |
        | HTTP 127.0.0.1:7860 或 0.0.0.0:7860
        v
app.py（标准库 HTTP 服务：路由、参数校验、静态资源）
        |
        +--> modules/workflow/store_growth_workflow.py
        |       |
        |       +--> modules/customer_insight/kb_agent.py
        |       +--> modules/recommendation/
        |       +--> modules/pricing/pricing_module.py
        |       +--> modules/marketing/marketing_content_module.py
        |       +--> modules/demo_script/demo_script_module.py
        |       +--> modules/compliance/block07_compliance.py
        |
        +--> modules/follow_up/follow_up_module.py
        |
        v
knowledge-base/华为PC全板块深度知识库_v7/
（公开事实、话术、场景、图片来源和价格快照）
```

## 2. 接口与数据流

- `POST /api/insight`：单独生成客户洞察卡。
- `POST /api/workflow`：完整串联客户洞察、推荐、价格、营销、3 分钟演示脚本和合规。可传 `personas`、`scenes`、`needs`、`concerns`、`priority_concern`、`triggers`、`channels`、`customer_words`、`product` 等字段。
- `POST /api/knowledge-query`：使用明确标注的本地 Mock 检索返回来源片段。
- `POST /api/quote`：读取带核验日期的官方公开价格快照。
- `POST /api/marketing`：输出可审阅营销草稿和来源。
- `POST /api/demo-script`：输出五段式、总时长 180 秒的顾客演示脚本；产品事实附知识库相对路径和行号。
- `POST /api/followups/*`：创建和更新匿名四节点跟进计划。跟进数据只存当前浏览器的 localStorage，不落服务器。

## 3. 七步业务字段与实现边界

七步业务框架是产品工作流；七步均有对应代码实现。第 05 步为规则驱动的可编辑脚本草稿，产品事实带来源定位，未知项明确留待核验。

| 步骤 | 输出字段 | 当前实现与边界 |
|---|---|---|
| 1. 客户洞察卡 | 客户身份、使用场景、核心需求、最大顾虑、购买触发点、沟通策略、依据 | 已实现；明确输入之外的信息保留为待追问。 |
| 2. 推荐方案 | 推荐产品、推荐理由、关键产品事实、适配程度、来源 | 已实现；默认 Mock 精选检索，未知硬条件不视为通过。 |
| 3. 价格与报价状态 | 具体配置、公开价格、价格口径、基准日期、来源、待人工核验项 | 已实现公开价格快照；动态条件须人工核验。 |
| 4. 营销内容 | 平台、内容策略、标题、正文、行动引导、推荐图片与来源 | 已实现草稿；发布前复核事实来源和图片授权。 |
| 5. 3 分钟演示脚本 | 开场、需求确认、产品演示、异议处理、收口 | 已实现 180 秒结构化脚本；事实带知识库路径和行号。未匹配产品事实时不陈述参数；兼容、价格、库存及体验仍待核验。 |
| 6. 成交跟进 | 今天、第 1 天、第 3 天、第 7 天 | 已实现四节点计划；不会自动联系顾客。 |
| 7. 依据与合规 | 已引用来源、检测到的风险、待人工确认项 | 已实现规则检查；扫描结果不能替代人工审查。 |

## 5. 可靠性设计

- **无 Key：** 系统不依赖任何 API；`.env.example` 只保留未来扩展位置。
- **无外网：** 检索、价格读取、规则检查和内容草稿均在本地完成。
- **断网演示：** 启动 `py -3 app.py` 即可使用本地工作台。
- **检索模式：** 默认是 `RETRIEVER_MODE=mock`；真实检索只允许通过 `retrieval_adapter.py` 接入，不改变上层数据契约。

## 6. 部署

- Docker 使用 `python:3.12-slim`，复制 `app.py`、`index.html`、`modules/` 和公开 `knowledge-base/`，监听 `0.0.0.0:7860`。
- ModelScope Docker 创空间应确认公开可见、日志显示监听成功，并用无痕窗口完成访问验证。
- 当前仓库没有已验证的公开 ModelScope 地址；部署完成后再把真实地址写入提交材料。
