# 03 · 演示与测试

## 1. 30 秒演示脚本（现场照此执行）

1. 打开魔搭链接（备用：本地 `http://127.0.0.1:7860`）。
2. 「顾客接待」→ 场景选「门店零售」→ 点示例按钮 → 点「生成接待方案与价格核验」。
3. 指着结果区讲三句话：**方案可执行 / 价格带核验日期 / 每条结论有出处**。
4. 追加 15 秒（加分动作）：切到「价格核验」，指出哪些金额被系统主动过滤、为什么必须人工确认。

## 2. 演示输入（5 组，开赛时填定）

| # | 场景 | 输入 | 期望要点 |
|---|---|---|---|
| 1 | 门店零售 | 【待填】 | 方案 + 推荐带出处 |
| 2 | 学生学习 | 【待填】 | 方案 + 未知项标待追问 |
| 3 | 竞品对比 | 【待填】 | 卖点 + 依据 |
| 4 | 价格核验 | 【待填】 | 出现"人工确认"提示，不展示历史价 |
| 5 | 边界输入（不存在的型号/平台） | 【待填】 | 拒绝编造，返回未知/4xx |

## 3. 自动化测试（`tests/`，共 16 个用例）

- **test_mvp.py（10 个）**：健康检查与引导页、目录与场景加载自知识库、兼容性保持"未验证"标注、营销图片仅用官方来源、未知产品不编造事实与图片、未知平台拒绝、接待/营销/报价端点、统一 workflow 端点、知识问答与跟进路由、未知平台返回 4xx。
- **test_workflow.py（3 个）**：洞察缺失字段保留待追问、完整流程贯通洞察-推荐-价格-合规、无选定产品时后续阶段为空。
- **test_follow_up.py（3 个）**：四阶段计划不含身份字段、更新校验状态/渠道/日期/文本、计划状态与 JSON 持久化。

## 4. 验收命令

```bash
py -3 -m unittest discover -s tests -v
py -3 -m py_compile app.py store_growth_workflow.py marketing_content_module.py pricing_module.py customer_insight_agent/kb_agent.py prepare_public_deploy.py
```
