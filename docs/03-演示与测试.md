# 03 · 演示与测试

## 1. 30 秒演示脚本

1. 打开已核验的公开部署地址；若尚未完成部署，使用本地 `http://127.0.0.1:7860`。
2. 进入「顾客接待」→ 场景选择「门店零售」→ 点击示例按钮 → 点击「生成接待方案与价格核验」。
3. 重点展示三点：方案可执行、价格带核验日期、结论带有来源。
4. 追加展示「价格核验」中的人工确认项，说明系统不会把历史快照当成当前成交价。

## 2. 顾客演示脚本

「3 分钟演示脚本」是面向真实门店顾客的五段式话术草稿，不是上文给评委看的 30 秒软件操作路径。可从侧栏单独生成，也可在完整工作流结果中打开。输入顾客任务、场景、顾虑和待验证条件；产品事实显示知识库文件与行号。没有匹配事实时脚本会明确提示待核验，不补写产品参数。

演示建议：先确认需求，再让顾客用自己的代表性任务体验；兼容、SKU、价格、库存和促销必须按现场信息核验。

## 3. 演示输入清单

| # | 场景 | 输入 | 期望要点 |
|---|---|---|---|
| 1 | 门店零售 | 使用示例按钮 | 方案和推荐带出处 |
| 2 | 学生学习 | 课程资料整理、软件兼容 | 未知项标为待追问或待验证 |
| 3 | 竞品对比 | 明确比较任务 | 只输出有依据的产品事实 |
| 4 | 价格核验 | 指定型号 | 展示核验日期和人工确认项 |
| 5 | 边界输入 | 不存在的型号或平台 | 拒绝编造，返回未知或 4xx |

## 4. 自动化测试

- `test_mvp.py`：健康检查、初始化数据、咨询、营销、报价、知识问答、演示脚本和跟进 HTTP 接口。
- `test_demo_script.py`：五段结构、180 秒时长、来源定位、缺失证据和异议边界。
- `test_workflow.py`：客户洞察、推荐、价格、营销、演示脚本和合规的跨模块串联。
- `test_follow_up.py`：四节点计划、状态校验和 JSON 持久化。

运行全部测试：

```bash
py -3 -m unittest discover -s tests -v
```
