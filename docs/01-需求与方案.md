# 01 · 需求与方案

> 本文档先于代码定稿（先文档后代码）：所有 AI 生成指令以本方案为唯一规格来源，代码按规格实现、不自由发挥。

## 1. 一句话定位

为华为门店顾问提供**证据可溯源**的顾客接待、营销内容与价格核验工作台——每条结论说得出"为什么"，不编造。

## 2. 目标用户与场景

- **用户**：华为门店顾问 / 店长（PC 板块）。
- **主场景**：顾客进店咨询（接待话术）、对比竞品（卖点与依据）、询价（价格核验与人工确认）、成交后（跟进计划）。
- **次场景**：营销内容撰写、知识问答。

## 3. 要解决的问题

顾问凭记忆接待容易说错参数、报错价、编造兼容性；资料分散在多个板块，无法在 30 秒内给出带出处的答案。

## 4. 功能优先级（P0 不做就失分；P2 明确放弃）

| 级别 | 功能 | 取舍理由 |
|---|---|---|
| P0 | 顾客接待（门店零售/学生学习）、价格核验、营销草稿、知识问答、成交跟进 | 直接对应赛道业务闭环 |
| P1 | 五段完整串联（洞察→推荐→价格→营销→合规）、合规待办 | 体现可解释与合规意识，标准库内可完成 |
| P2 | 真实门店数据接入、动态促销/库存核验、多门店账号体系、复杂可视化 | 4 小时内无法保证数据真实，宁可诚实标注不做 |

## 5. 评委 30 秒演示路径设计

线上链接 → 「顾客接待」选「门店零售」→ 示例按钮 → 「生成接待方案与价格核验」→ 结果区三块：**方案 / 价格快照与核验日期 / 依据出处**。详见 README「评委请先看这里」。

## 6. 评分导向对照

能跑（纯标准库零依赖，评委环境必有东西看）→ 可解释（每条结论带出处 + 合规待办）→ 完成度诚实（Mock 明确标注 + 已知局限 4 条）→ 界面（三段式布局，够用即可）。
