# 01 · 需求与方案

> 本文档先于代码定稿（先文档后代码）：所有 AI 生成指令以本方案为唯一规格来源，代码按规格实现、不自由发挥。

## 1. 一句话定位

为华为门店顾问提供**证据可溯源**的顾客接待、营销内容与价格核验工作台——每条结论说得出"为什么"，不编造。

## 2. 目标用户与场景

- **用户**：华为门店顾问 / 店长（PC 板块）。
- **主场景**：顾客进店咨询（接待话术）、对比竞品（卖点与依据）、询价（价格核验与人工确认）、成交后（跟进计划）。
- **次场景**：营销内容撰写、知识问答。

## 3. 要解决的问题

顾问凭记忆接待容易说错参数、报错价、编造兼容性；资料分散在多个板块，无法在 30 秒内给出带出处的答案。

## 4. 功能优先级（P0 不做就失分；P2 明确放弃）

| 级别 | 功能 | 取舍理由 |
|---|---|---|
| P0 | 顾客接待（门店零售/学生学习）、价格核验、营销草稿、知识问答、成交跟进 | 直接对应赛道业务闭环 |
| P1 | 核心环节串联（洞察→推荐→价格→营销→演示脚本→合规）、合规待办 | 体现可解释与合规意识，标准库内可完成 |
| P2 | 真实门店数据接入、动态促销/库存核验、多门店账号体系、复杂可视化 | 4 小时内无法保证数据真实，宁可诚实标注不做 |

## 5. 七步业务输出字段与实现状态

七步是面向顾问的业务框架，不代表各步都具备真实门店数据或自动化执行能力。当前七步均有对应代码；第 5 步生成的是规则驱动、带产品事实出处的可编辑话术草稿。

| 步骤 | 输出字段 | 当前状态与边界 |
|---|---|---|
| 1. 客户洞察卡 | 客户身份、使用场景、核心需求、最大顾虑、购买触发点、沟通策略、依据 | 已实现；缺失项标记待追问，不推断顾客事实。 |
| 2. 推荐方案 | 推荐产品、推荐理由、关键产品事实、适配程度、来源 | 已实现；默认本地 Mock 精选检索，未知硬条件不算满足。 |
| 3. 价格与报价状态 | 具体配置、公开价格、价格口径、基准日期、来源、待人工核验项 | 已实现公开价格快照；动态价格、库存和权益须人工核验。 |
| 4. 营销内容 | 平台、内容策略、标题、正文、行动引导、推荐图片与来源 | 已实现渠道草稿；事实、图片授权与发布须人工复核。 |
| 5. 3 分钟演示脚本 | 开场、需求确认、产品演示、异议处理、收口 | 已实现规则驱动的 180 秒结构化草稿；产品事实附知识库路径与行号，兼容、价格和体验仍须核验。 |
| 6. 成交跟进 | 今天、第 1 天、第 3 天、第 7 天 | 已实现匿名四节点计划；浏览器端存储，不自动发送。 |
| 7. 依据与合规 | 已引用来源、检测到的风险、待人工确认项 | 已实现规则扫描；可能误报或漏报，仍需人工审核。 |
