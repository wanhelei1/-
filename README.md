# 门店增长工作台 · 华为PC门店销售智能助手

> 纯 Python 标准库实现。面向浙客松·AI+X 破界黑客松（华为产业落地赛道），围绕华为PC本地知识库提供门店顾客接待工作台，并以「客户洞察 → 推荐方案 → 价格核验 → 营销内容 → 演示脚本 → 成交跟进 → 依据合规」七步作为业务框架：输出保留来源，未知项明确标注待追问，不编造。

## 亮点

- **七步销售流程框架**：客户洞察卡 / 推荐方案 / 价格与报价状态 / 营销内容 / 3分钟演示脚本 / 成交跟进 / 依据与合规；6 步已有对应功能，演示脚本自动生成列为 P1 计划。
- **零依赖可跑**：纯 Python 标准库 HTTP 服务 + 随包分发的本地知识库，无 API Key、无第三方包、无网络依赖，评审环境永远有东西看。
- **证据优先**：结论附文件/章节来源与基准日期；价格只展示带核验日期的官方公开快照，不能安全展示的金额直接转人工核验。
- **诚实的边界**：知识问答为明确标注的本地 Mock 精选检索；机密的 P4 价格政策由打包脚本自动排除；合规检查保留人工确认项，不冒充可直接发布。
- **16 项自动化测试**：一条命令验收，2026-10-18 实测 16/16 通过。

## 环境要求

- Python **3.10+**（标准库实现，无需 `pip install` 任何包）
- 磁盘约 35MB（知识库随包分发）

## 本地运行

```bash
py -3 app.py        # Windows；macOS/Linux: python3 app.py
```

浏览器打开 <http://127.0.0.1:7860>。托管环境加参数 `--host 0.0.0.0 --port 7860`。

Docker 一键运行：

```bash
docker build -t sgw . && docker run -p 7860:7860 sgw
```

验收：

```bash
py -3 -m unittest discover -s tests -v
```

## 七步销售流程与输出结构

以下七步是面向门店顾问的业务框架；当前六步已有对应功能，第 5 步自动生成演示脚本尚未实现：

### 一、客户洞察卡 ✅
客户身份 · 使用场景 · 核心需求 · 最大顾虑 · 购买触发点 · 沟通策略 · 依据
> 只记录顾客明确表达的信息，缺失项标记「待追问」，不把推测写成客户事实；沟通建议围绕优先顾虑生成，兼容性等高风险问题转为核验或实测任务；顾客原话与知识库方法资料分开展示。

### 二、推荐方案 ✅
推荐产品 · 推荐理由 · 关键产品事实 · 适配程度 · 来源
> 硬条件需要可追溯的正向证据；有反证可排除；未知或冲突不自动算通过；候选产品、冲突与待核验项一并展示。

### 三、价格与报价状态 ✅
具体配置 · 公开价格 · 价格口径 · 基准日期 · 来源 · 待人工核验项
> 只展示带核验日期的官方公开价格快照；库存、促销、地区差价、授权折扣等一律转人工核验，不把历史记录当作现价，不用受限价格政策推算成交价。

### 四、营销内容 ✅
平台 · 内容策略 · 标题 · 正文 · 行动引导 · 推荐图片与来源
> 覆盖小红书 / 朋友圈 / 抖音 / 视频号 / 微信公众号 / 知乎 / 新闻稿 / 直播 / 门店长图等渠道草稿；事实锚点、版本边界、图片来源与发布前人工审核显式标注；缺事实或缺图片时提示不足，不编造。

### 五、3 分钟演示脚本 ⏳ 规划中
开场 · 需求确认 · 产品演示 · 异议处理 · 收口
> 演示方法论与话术片段已随知识库可检索（P5 培训库情景演练、P6 直播讲解模板）；按客户洞察与推荐结果自动生成个性化脚本已列入 P1 计划，当前版本不自动生成。

### 六、成交跟进 ✅
今天 · 第 1 天 · 第 3 天 · 第 7 天
> 四节点匿名线索跟进计划（线索代号标识，不要求姓名电话）；节点状态：待联系/已联系/已解决/已跳过；话术为待顾问核对的模板，不自动发送，尊重顾客停止联系意愿；浏览器端计划仅存当前设备 localStorage。

### 七、依据与合规 ✅
已引用来源 · 检测到的风险 · 待人工确认项
> 汇总各阶段事实与图片来源，检查绝对化措辞、价格促销、无依据比较、虚构体验、贬低竞品、虚假承诺及图片型号不一致等风险；通过检查 ≠ 合法合规或可直接发布，保留人工审核。

## 使用流程

1. 首页「顾客接待」选择场景（门店零售 / 学生学习），输入客户任务，可补充角色、优先顾虑、软件版本、外设型号和拟核对产品。
2. 点击「生成接待方案与价格核验」查看轻量接待结果；或点击「运行完整洞察、推荐与合规流程」一次串联洞察、推荐、价格、营销与合规链路。
3. 在「营销内容」选择型号、渠道、人群，单独生成营销草稿及事实依据。
4. 在「价格核验」查看来源、日期、价格状态和必须人工确认的条件。
5. 在「知识问答」按问题检索本地知识片段与出处。
6. 在「成交跟进」生成四节点计划并维护状态（数据仅存当前浏览器）。

## 技术架构

```text
index.html 工作台（移动端适配）
   │ HTTP（默认 127.0.0.1:7860 / 托管 0.0.0.0:7860）
app.py（标准库 ThreadingHTTPServer：路由 / 校验 / 静态资源）
   │
store_growth_workflow.py（跨模块流程装配，模块间不互相复制代码）
   ├─ ① customer_insight_agent/kb_agent.py                    客户洞察
   ├─ ② 3号(1)/recommendation_engine.py
   │     3号(1)/retrieval_adapter.py + mock_retriever.py      推荐与检索适配
   ├─ ③ pricing_module.py                                     价格快照与核验
   ├─ ④ marketing_content_module.py                           营销草稿
   ├─ ⑥ follow_up_module.py                                   成交跟进
   └─ ⑦ BLOCK-07/block07_compliance.py                        依据与合规
   │
knowledge-base/华为PC全板块深度知识库_v7/（本地事实源，公开子集）
```

主要接口：`GET /health` · `GET /api/bootstrap` · `POST /api/insight` · `POST /api/workflow` · `POST /api/consult` · `POST /api/knowledge-query` · `POST /api/quote` · `POST /api/marketing` · `POST /api/followups/plan|task|status`。

## 数据治理：机密资料不进仓库

知识库含 8 个公开板块（00-建库规范 / P1 产品参数 / P2 卖点话术 / P3 竞品资料 / P5 培训赋能 / P6 营销素材 / P7 常见问题 / P8 客户场景）。**P4 价格政策（机密）、待审核资料、历史归档与来源研究底稿一律不进入本仓库**：`prepare_public_deploy.py` 自动排除受限目录，并生成逐文件校验清单 `bundle-manifest.json`。

## 已知局限与下一步

1. 知识问答为明确标注的本地 Mock 精选片段检索（确定性关键词排序），不是全库生产检索，也未接入外部 LLM——下一步扩展全库索引与相关性调优。
2. 价格核验只展示带核验日期的公开快照，不含动态促销、库存、补贴；软件/外设兼容性不从参数推断，须在客户目标环境实测。
3. 3 分钟演示脚本自动生成尚未实现（P1）；营销事实与来源的逐条映射仍需人工复核。
4. 未使用真实门店成交/转化样本，不声明销售提升、ROI 或效果指标；知识库教材中的教学示例不作为真实客户案例或产品背书。
